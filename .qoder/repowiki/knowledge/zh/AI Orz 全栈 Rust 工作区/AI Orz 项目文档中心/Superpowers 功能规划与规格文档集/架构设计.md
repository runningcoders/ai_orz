本模块为纯文档型 leaf 模块，按职责分为两个并列子目录：
- `plans/`：按 `YYYY-MM-DD-<主题>.md` 命名的一次性实施计划，每个文件描述单一特性（如 chat-mvp、a2a-server、canvas-rendering-infrastructure、mobile-adaptation），包含目标、架构分层约定（Handler → Domain → DAL → DAO）、前后端文件变更表、分 Step 的任务清单及 git commit 模板，作为 agentic worker 执行任务的可操作输入。
- `specs/`：按特性划分的子目录（如 `mobile-adaptation`、`enhance-entity-search`、`2026-07-19-a2a-server`），每个 spec 统一包含 `spec.md`（Why/What Changes/Impact/Constraints/Requirements with Given-When-Then 场景）、`tasks.md`（可拆分任务）、`checklist.md`（验收检查项），形成“需求→任务→验收”的闭环。
文档依赖方向单向指向代码仓库（引用 `src/handlers`、`src/service/{domain,dal,dao}`、`frontend/src`、`common/src/api` 等路径），不反向被代码引用；遵循项目四层架构约定，在 plan 中显式约束新增 API 必须走 Handler→Domain→DAL→DAO 分层，并通过 `ai-orz-macros` 的 `#[generate_http_handler]` + `#[derive(Params)]` 生成 HTTP handler 与 LLM 工具参数。
