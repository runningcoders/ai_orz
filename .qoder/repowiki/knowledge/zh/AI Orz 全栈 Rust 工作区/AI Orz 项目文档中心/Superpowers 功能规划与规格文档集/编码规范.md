- plans 文件采用 `YYYY-MM-DD-<主题>.md` 命名，每个文件聚焦单一特性，并在开头声明 Goal、Architecture、Tech Stack 三段元信息。
- plan 内使用表格列出后端/前端新增或修改的文件及其职责，便于 diff review 与自动化追踪。
- 任务拆分为带 `- [ ]` checkbox 的 Step，每个 Step 指定 Files、精确行号范围、代码片段、验证命令与 commit message 模板。
- specs 子目录统一包含 `spec.md`、`tasks.md`、`checklist.md` 三件套，spec 中使用 Why/What Changes/Impact/Constraints/Requirements (Given-When-Then) 结构组织需求。
- 所有 plan/spec 在涉及后端改动时显式遵循 Handler → Domain → DAL → DAO 分层约定，新增 HTTP API 需通过 `common/src/api` 定义 DTO 并使用 `ai-orz-macros::Params` 派生。
- 前端相关 spec 明确约束 Dioxus 0.7 + Tailwind/DaisyUI 技术边界，禁止引入新依赖，仅通过现有 web-sys/wasm-bindgen 能力实现响应式逻辑。
