模块按职责划分为三层：
- `tests/common/`：共享测试基础设施。`app.rs` 中的 `TestApp` 通过 `ai_orz::router::create_router` 构建内存路由，封装 GET/POST/PUT/DELETE/JWT/SSE 请求并返回 `(StatusCode, serde_json::Value)`；`env.rs` 的 `init_full_test_env` 使用 `tokio::sync::OnceCell` 确保全局单例（storage/jwt/tool_registry/service/producer/consumer）仅初始化一次，并通过临时目录 + InMemory 向量存储隔离数据；`assertions.rs` 提供 `assert_api_ok` / `assert_api_error` 统一断言业务 envelope；`factories/` 提供 `agent_factory`、`project_factory`、`user_factory`（含 `bootstrap_and_login`、`login_and_get_jwt`）生成业务实体。
- `tests/integration/`：每个文件对应一个功能域（a2a_flow、agent_management、core_crud、cron_project_followup、memory、message_delivery、tool_call、vector_degradation 等），均通过 `#[sqlx::test]` 注入 `SqlitePool`，调用 `init_full_test_env` 后构造 `TestApp` 发起真实 HTTP 请求。
- 顶层 `http_handler_macro_test.rs` 与若干 `.md` 文档描述被测路由契约。
依赖方向单向：integration tests → common → 被测 crate `ai_orz`（router/config/storage/jwt/service/producer/consumer），common 不反向依赖 integration 用例。
