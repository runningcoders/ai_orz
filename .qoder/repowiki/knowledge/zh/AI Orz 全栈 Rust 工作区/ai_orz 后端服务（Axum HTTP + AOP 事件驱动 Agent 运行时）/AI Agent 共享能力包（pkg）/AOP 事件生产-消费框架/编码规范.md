- 消费者通过实现 `Consumer` trait 声明 `interested_events`、`consume_mode`、`on_event` 等方法，并以 `Arc<dyn Consumer>` 形式注册到全局 Registry。
- 事件类型需实现 `Event` trait，提供 `kind`、`id` 以及可选的 `order_key`、`priority`、`created_at` 元字段，用于顺序保证与监控。
- 异步消费模式通过 `ConsumeMode::Async` 切换，由 Registry 自动为每个消费者分配独立 `InMemoryEventQueue` 并 spawn 指定并发数的 worker 循环拉取。
- 所有 I/O 与锁操作均通过 `map_err(|e| err!(Internal, ...))` 包装 RwLock 获取失败，并在关键路径使用 `sys_error!`/`sys_warn!`/`sys_info!` 记录日志。
- Registry 在事件序列化前提取元字段并统一注入到 JSON 顶层（event_id/kind/order_key/priority/created_at），确保队列与监控读取一致。
- 可扩展组件（Producer、Scheduler、EventQueue、AopMetricsHook）均以 trait + Arc 动态分发方式实现，新增实现只需放在对应目录下并按约定接口实现即可。
