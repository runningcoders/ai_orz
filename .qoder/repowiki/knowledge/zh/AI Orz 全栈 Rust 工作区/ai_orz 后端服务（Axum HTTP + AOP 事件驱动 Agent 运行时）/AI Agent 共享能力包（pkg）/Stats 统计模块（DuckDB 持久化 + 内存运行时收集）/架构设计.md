模块采用「trait + 类型擦除」的双层架构：
- 核心接口在 `traits.rs` 中定义 `StatEvent`（事件元数据：timestamp/tags/metrics）和 `StatTable<E>`（表名、建表、单条/批量插入、SQL 列引用），所有具体事件表均实现这两个 trait。
- `collector.rs` 中的 `Stats` 是顶层协调器，内部用 `Mutex<HashMap<TypeId, ...>>` 维护已注册的事件→表映射，并通过 `ErasedBuffer`（`Box<dyn Any>`）做按事件类型的缓冲；达到 `batch_size` 时调用 `flush_type_id` 以固定锁序（tables → conn）避免死锁。
- `erased.rs` 提供 `ErasedStatTable` 与 `ErasedWrapper<T>` 将泛型 `StatTable<E>` 类型擦除为 `dyn ErasedStatTable`，使 `Stats` 能以统一方式管理多种事件表。
- 内置事件表按职责拆分到独立文件：`default.rs`（通用 JSON tags/metrics 表）、`model_call.rs`、`tool_call.rs`、`agent_awake.rs`、`project_event.rs`、`task_event.rs`，其中专用表通过 `is_dedicated_table() = true` 启用独立字段而非 JSON 列。
- `runtime/mod.rs` 是互补的内存版子模块，提供泛型 `RuntimeStatsCollector<K>`，基于 `tokio::sync::RwLock` + 滑动窗口（60 分钟）时间桶，用于 AOP/SSE/Channel 等无需持久化的运行时指标。
- 对外暴露 `record_event!` 宏自动推断表并补全 timestamp，以及全局 `OnceLock<Arc<Stats>>` 单例供无 `RequestContext` 的 AOP 消费者访问。
- 依赖方向：各事件表 → traits → collector → erased；runtime 子模块完全独立，不依赖 DuckDB。
