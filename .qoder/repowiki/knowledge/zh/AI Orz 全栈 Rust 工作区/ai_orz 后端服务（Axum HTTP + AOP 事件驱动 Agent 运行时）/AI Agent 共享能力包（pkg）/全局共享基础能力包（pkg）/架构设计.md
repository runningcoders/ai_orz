本模块作为 `src/pkg` 聚合层，通过 `mod.rs` 统一声明子模块并在 `init_all` 中集中初始化：先调用 `logging::init` 配置 tracing，再初始化 `storage`、`jwt`、`tool_registry`、`tool_tracing` 等全局单例，最后输出注册信息。
- 请求上下文 (`request_context.rs`)：以不可变 `RequestContext` + `RequestContextBuilder` 模式贯穿 HTTP 请求生命周期，从 `HeaderMap` 解析用户/组织/角色/调用方类型等信息，并通过 `EnrichContext` trait 与 `enrich_ctx!` 宏实现树形扩散式字段增强；同时封装 `Storage` 门面暴露 `db_pool`、`vector_store`、`stats` 等下游能力。
- Agent 运行时状态 (`agent_runtime_state.rs`)：基于 `DashMap<String, AgentRuntimeInfo>` 的全局单例（`OnceLock<Arc<...>>`），维护 Idle/Busy/Resting 三态，并提供原子 `try_set_busy` 修复 TOCTOU 竞态，状态变更通过 `tokio::spawn` fire-and-forget 发布到 AOP 事件总线。
- JWT (`jwt.rs`)：使用 `jsonwebtoken` 的 HS256 算法，通过 `OnceLock<JwtConfig>` 持有全局签名密钥与默认过期时间，对外暴露 `encode_jwt` / `decode_jwt` 便捷函数。
- 日志 (`logging.rs`)：基于 `tracing_subscriber`，支持控制台与按日滚动文件双路输出，可选 JSON 格式，并带 `retention_days` 自动清理旧日志；通过 `LogFields` trait 配合 `ai_orz_macros::LogFields` 自动注入 span 字段。
- 每日 JSONL (`daily_jsonl.rs`)：通用按 `{YYYYMMDD}.jsonl` 分片追加写入器，被内存 trace 存储与 tool call 日志复用，提供 `append` / `read_line` / `read_line_json` 接口。
依赖方向：本模块向上被业务 handler/service 引用，向下依赖 `common`（配置、枚举、常量）、`crate::pkg::aop/storage/stats` 等同级子模块，自身不反向依赖业务模型。
