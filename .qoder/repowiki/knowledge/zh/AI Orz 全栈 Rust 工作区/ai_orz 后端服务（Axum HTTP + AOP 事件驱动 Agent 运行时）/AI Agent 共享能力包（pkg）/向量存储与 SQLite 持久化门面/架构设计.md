模块以 `mod.rs` 中的 `Storage` 结构体作为统一入口，内部通过 `Arc<StorageInner>` 持有 `SqlitePool`、可插拔的 `Arc<dyn VectorStore>` 和 `Stats`，由 `Storage::new()` 根据 `DatabaseConfig.vector_store_type` 在运行时选择具体后端（InMemory/Hnsw/LanceDb/SqliteVss），并自动执行 sqlx migrations。

- 抽象层：`vector.rs` 定义 `VectorStore` trait（init_collection/upsert/search/get/delete/clear_collection/flush 等），所有后端实现该 trait，业务 DAO 仅依赖此 trait。
- 后端实现：
  - `mem_vector.rs`：纯 Rust 内存 + bincode 懒持久化，线性余弦搜索，适合小数据量。
  - `hnsw.rs`：基于 `instant-distance` 的 HNSW 索引，每个 collection 独立 `.bincode` 文件，后台 60s 定时 flush + Drop 兜底落盘，支持按 model_provider_id 重建索引。
  - `lance.rs`：基于 LanceDB 嵌入式向量数据库，使用 Arrow FixedSizeListArray 存储向量，内置 HNSW 索引。
  - `fts5.rs`：SQLite FTS5 全文检索工具（如 `escape_fts5_keyword`）。
- 依赖方向：各后端 → `crate::models::vector` 中的统一数据结构（VectorIndexParams/VectorRow/VectorSearchHit）→ 上层 DAO；`Storage` 对外暴露 `sqlite_pool()`、`vector()`、`stats()` 访问器，并提供全局单例 `get()/init()` 用于无上下文场景。
