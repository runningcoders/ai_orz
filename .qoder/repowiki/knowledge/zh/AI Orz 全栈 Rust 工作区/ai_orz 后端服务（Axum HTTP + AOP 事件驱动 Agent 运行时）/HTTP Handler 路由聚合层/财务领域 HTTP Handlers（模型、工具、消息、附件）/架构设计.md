模块以 `mod.rs` 作为顶层聚合，导出 attachment、mcp_server、mcp_tool、message、message_channel、model_provider、tool 七个子领域；每个子领域遵循统一结构：一个 `mod.rs` 声明各方法文件并通过 `pub use` 重导出 `*_handler` 函数，业务逻辑通过 `crate::service::domain::*` 调用领域服务（如 `domain().model_provider_manage()`、`runtime::domain().tool_execution()`），请求上下文由 `RequestContext` 注入。

- 每个 handler 使用 `ai_orz_macros::generate_http_handler` 宏自动实现 HTTP 路由适配，并用 `register_handler_tool(id, name, description, params, [neural], [tags])` 同时注册为 Agent 可调用的工具，使同一函数既可作为 REST 端点又可被 AI Agent 调用。
- 响应类型集中在子域的 `response.rs` 中，测试文件通过 `#[cfg(test)]` 条件编译隔离。
- 依赖方向单向向下：handlers → service/domain → 基础设施，不直接访问数据库或网络。
