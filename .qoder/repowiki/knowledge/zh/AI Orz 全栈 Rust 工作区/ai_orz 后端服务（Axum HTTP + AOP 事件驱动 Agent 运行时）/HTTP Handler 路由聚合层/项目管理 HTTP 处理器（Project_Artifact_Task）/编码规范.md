- 每个 HTTP 方法独立为一个文件，文件名采用动词+名词形式（如 `create_project.rs`、`update_task_status.rs`），并在子域 `mod.rs` 中集中 `pub use` 暴露 `*_handler` 函数。
- Handler 函数统一签名 `(ctx: RequestContext, params: XxxRequest) -> Result<XxxResponse>`，通过 `#[generate_http_handler]` 与 `#[register_handler_tool(...)]` 宏声明路由与工具元数据。
- 业务调用一律经 `crate::service::domain::project::domain()` 获取领域管理器（`project_manage` / `artifact_manage` / `task_manage`），handler 不直接访问持久层。
- 响应构造集中在子域内 `response.rs` 的 `to_detail` / `to_list_item` 等转换函数中，将领域模型映射到 `common::api` 的 DTO。
- 错误处理统一使用 `common::error::{bail_err, err}` 配合 `Result` 返回，缺失资源场景通过 `NotFound` 或 `InvalidRequest` 语义化报错。
- 需要权限/上下文扩展的 handler 使用 `enrich_ctx!` 宏基于领域对象（如 task）增强 `RequestContext` 后再调用领域服务。
