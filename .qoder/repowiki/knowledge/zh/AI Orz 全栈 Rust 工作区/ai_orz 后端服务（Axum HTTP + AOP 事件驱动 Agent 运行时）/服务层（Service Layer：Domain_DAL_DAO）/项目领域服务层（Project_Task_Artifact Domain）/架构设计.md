模块以 `mod.rs` 为入口，定义统一的 `ProjectDomain` trait 及 `ProjectManage`、`TaskManage`、`ArtifactManage` 三个子能力 trait，并由单一结构体 `ProjectDomainImpl` 同时实现这三个 trait，通过依赖注入的 `ProjectDal`、`TaskDal`、`ArtifactDal` 三个 DAL 接口完成数据访问，严格遵循“Domain 层只组合 DAL、不调用 DAO”的分层约定。

- 单例与初始化：通过 `OnceLock<Arc<dyn ProjectDomain>>` 暴露全局 `domain()`，并提供 `init()` 绑定真实 DAL；测试场景通过 `new(...)` 构造独立实例保证隔离。
- 按业务对象分文件：`service.rs` 实现 Project 管理（含状态机 `transition_status` 与 FTS5+向量混合搜索），`task.rs` 实现 Task 管理（含依赖图构建、进度更新），`artifact.rs` 实现 Artifact 管理（Attachment / GeneratedContent 两类产物、内容读写、权限校验），`task_graph.rs` 提供基于 `dependencies` 字段构建 DAG 并渲染为 Mermaid 字符串的工具。
- 跨实体聚合：`get_project`/`get_task` 通过 `FetchOptions` 按需注入 task_graph、artifacts、progress_summary 等附加信息，复用 `artifact_to_detail` 转换函数统一 DTO 映射。
- 上下文与审计：所有写操作通过 `enrich_ctx!` 宏将实体信息注入 `RequestContext`，并使用 `record_event!` 记录 `ProjectEvent`/`TaskEvent` 等审计事件。
- 依赖方向：本模块仅向上暴露 trait 与 `ListArtifactsParams` 等公共类型，向下依赖 `service::dal::*` 与 `models::*`，不反向引用上层 handler。
