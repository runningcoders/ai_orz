根模块是 ai_orz workspace 的 bin/target，通过 `src/main.rs` 调用 `ai_orz::run()` 启动：先初始化配置与所有 pkg 基础设施（日志、存储、JWT、工具注册表），再初始化 service 层并幂等加载基础数据，随后注册 producer/consumer 到 AOP 事件总线，最后挂载 axum Router 监听 TCP。HTTP 路由集中在 `src/router.rs`，按 `/api/v1/public`、`/api/v1/protected`、`/.well-known/agent.json`、`/a2a` JSON-RPC、`/health` 划分；受保护路由统一叠加 `jwt_auth_middleware` → `request_context_middleware` → `require_role_middleware` 中间件链。业务代码严格遵循四层架构：`handlers`（适配层，按 finance/hr/project/system/organization/user/a2a 分目录）、`producer`（外部 WS/轮询事件产出）、`consumer`（内部事件消费）、`service/domain`（业务编排）、`service/dal`（PO↔Entity 转换）、`service/dao`（本地 DB CRUD + 外部 API 出站）、`pkg`（无业务感知的 AOP、storage、stats、tool_registry、logging 等基础设施）、`models`（PO + 业务实体 + 内部事件）。`common` 与 `ai-orz-macros` 作为独立 workspace 成员被后端和 frontend 共同依赖，提供 DTO、枚举、错误类型及 `#[generate_http_handler]` / `#[derive(Params)]` 等 IDL 宏。
