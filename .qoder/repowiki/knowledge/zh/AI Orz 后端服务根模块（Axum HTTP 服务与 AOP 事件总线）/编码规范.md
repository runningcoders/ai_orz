- HTTP 路由集中定义在 `router.rs`，按 public/protected 子路由函数拆分，每个业务域（hr/finance/project/system/organization/user/a2a）一个 nest 块，handler 通过 `handlers::xxx::yyy::handler_fn` 路径引用。
- 受保护路由统一使用三层中间件顺序：外层 `jwt_auth_middleware` 校验 JWT，内层 `request_context_middleware` 从请求头构造 RequestContext，再按需叠加 `require_role_middleware` 做角色校验。
- 日志通过根模块导出的 `log_info!` / `log_warn!` / `log_error!` / `log_debug!` 宏调用，支持无上下文字符串字面量模式与带 `&ctx` 的 span 注入模式，字段由 `#[derive(LogFields)]` 自动生成。
- 服务层严格遵循 DAO 不调 DAO、DAL 不调 DAL、Domain 不调 Domain 的单向依赖边界，各层职责通过独立的 `service/{domain,dal,dao}` 子目录隔离。
- DTO、枚举、错误类型统一放在 `common/src/{api,enums,error}` 下并通过 feature flag（sqlx/axum-integration/tokio-integration 等）条件编译，使 common 可被后端与前端 Dioxus 同时依赖。
- AOP 事件驱动：业务逻辑通过 producer 产出事件、consumer 订阅处理，启动阶段先注册 producer/consumer 再启动 AOP 调度器，确保事件总线就绪后再执行业务初始化。
