本模块为纯 SQL 迁移目录，采用 `YYYYMMDDHHMMSS_描述.sql` 命名约定保证执行顺序，由外部迁移工具（如 sqlx-migrate、golang-migrate 或自定义 runner）按文件名排序依次执行。
- 首份 `20260420000000_initial.sql` 是合并后的最终初始 schema，包含 organizations、users、agents、model_providers、tasks、projects、short_term_memory_index、long_term_knowledge_node、knowledge_reference、messages、artifacts 等核心表，所有表均使用 `STRICT` 模式并统一携带 `created_by/modified_by/created_at/updated_at` 审计字段。
- 后续迁移以增量方式演进：新增列（如 messages.reply_to_id、artifact.project_id）、修正类型（provider_type 从 TEXT→INTEGER）、扩展功能（attachments、mcp_servers、cron_triggers、execution_plan_result）。
- 全文检索通过 FTS5 虚拟表实现：`memory_fts5.sql` 为 short_term_memory_index 与 long_term_knowledge_node 建立 trigram 分词的 FTS5 索引；`entity_fts5.sql` 为 skills/tools/messages/tasks/projects/agents 六张主表分别创建 FTS5 虚拟表，并通过 AFTER INSERT/UPDATE/DELETE 触发器自动同步，删除/更新路径统一使用 `DELETE FROM fts WHERE rowid = old.rowid` 而非 FTS5 的 delete 特殊命令以避免值不匹配错误。
- 每个迁移文件自包含且幂等（大量使用 IF NOT EXISTS），支持独立回滚困难，依赖外部版本控制机制跟踪已执行迁移。
