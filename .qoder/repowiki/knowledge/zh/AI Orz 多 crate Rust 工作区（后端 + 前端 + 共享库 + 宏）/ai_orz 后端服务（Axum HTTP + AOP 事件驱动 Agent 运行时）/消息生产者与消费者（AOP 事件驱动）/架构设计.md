模块以 `src/consumer` 和 `src/producer` 两个子目录划分职责，统一通过 `pkg::aop` 的 `Consumer`/`Producer` trait 接入 AOP 事件中心。

- 生产者侧：`producer/mod.rs` 的 `init()` 在启动时注册 `CronTriggerProducer`（周期扫描到期定时任务并发布 `cron.trigger` 事件）和 `A2aPollingProducer`（轮询远程 Agent 任务并同步消息/状态），同时启动 `message_channel` 内部通道生产者；每个 Producer 通过 `RwLock<Option<Arc<Registry>>>` 持有 Registry 引用，由框架在 `register()` 阶段注入。
- 消费者侧：`consumer/mod.rs` 的 `init()` 集中注册所有业务 Consumer，包括 `MessageConsumer`（订阅 `message.created`，按 `to_role` 分发到 Agent/User/System 分支）、`CronTriggerConsumer`（消费 `cron.trigger`，按 payload.action 路由到 agent_rest/project_followup）、`TaskEventConsumer`（消费 `task.status_changed`，仅对 Completed 触发 Owner Agent 通知），以及 tool_exec_log/stats、think_round_stats、agent_loop 等统计/日志类消费者。
- 依赖方向单向向下：消费者/生产者只依赖 `service::domain`、`service::dal`、`models::events`、`pkg::RequestContext`，不反向引用上层 handler；具体业务编排委托给 domain 层（如 `RuntimeDomain.awaken`、`MessageDomain.delivery`、`HrDomain`、`ProjectDomain`），实现事件流转与业务逻辑解耦。
- 重试与确认：`MessageConsumer` 实现 `ack/nack` 将消息状态回写为 Processed/Pending，并通过 `AgentRuntimeStateManager` 的 busy/idle 语义避免并发唤醒同一 Agent 的竞态。
