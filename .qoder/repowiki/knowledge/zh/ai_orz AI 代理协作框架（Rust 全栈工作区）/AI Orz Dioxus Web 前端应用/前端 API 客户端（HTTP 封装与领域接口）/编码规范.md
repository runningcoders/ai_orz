- 每个业务域文件按资源维度用注释分段组织（如「项目管理」「任务管理」「产物管理」），每个 CRUD 操作对应一个独立 async 函数。
- REST 路径统一以 `/api/v1/...` 前缀硬编码在函数内，通过 `format!` 拼接资源 ID 或查询参数。
- 可选查询参数统一通过 `super::build_query_string(&[("key", field.map(|v| v.to_string()))])` 构造，None 字段自动被过滤。
- 分页列表使用 `super::build_pagination_url(base, &req.pagination)` 将 `PaginationParams` 序列化为 query string 后调用 `api_get`。
- 无返回数据的写操作统一调用 `api_put_empty`/`api_post_empty`，并将状态字段包装为 `{ "status": ... }` 的 JSON 对象传入。
- 所有异步函数统一返回 `Result<T, ApiError>`，由上层根据 `ApiError.error_code` 区分业务错误（如 409 切换 Embedding Provider）。
