- 每个内置工具以「工厂结构体 + CoreTool 核心结构体」成对实现：工厂实现 `BuiltinToolFactory`（`create_po` 构造 ToolPo 并调用 `po.fill_defaults_for_builtin()`，`create` 返回 `Box<dyn CoreTool>`），核心结构体实现 `CoreTool` 并在 `call` 中解析 `serde_json::Value` 参数。
- 工具配置通过 `ToolPo.config` 中的 JSON 反序列化为专用 struct（如 `FsToolConfig`、`ShellExecConfig`），默认值在 config struct 的 `Default` 或 getter 方法中提供。
- 所有对外部资源的访问必须经过 `tool_security` 提供的校验：HTTP 走 `validate_target_url`/`read_limited_response_body`/`sanitize_response_headers`，文件系统走 `fs::resolve_and_validate_path`，禁止直接裸调系统 API。
- 需要用户确认的危险操作（如越权路径读取、非白名单工作目录）统一返回包含 `require_confirmation: true` 的 JSON 结果，而非直接抛错。
- 工具描述中使用加粗的 `**Permission rule**` / `**Security**` 段落向 LLM 显式声明权限与安全约束，作为 prompt 的一部分随 ToolPo.description 下发。
- 测试文件与实现文件同名分离（`fs_tests.rs`、`shell_tests.rs`、`http_tests.rs`、`mcp_tests.rs`），并通过 `#[cfg(test)] mod ...` 在 `mod.rs` 中条件引入。
