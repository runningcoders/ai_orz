模块按功能子目录组织：`mod.rs` 仅声明 `profile` 子模块；`profile/` 下分别实现 GET/PUT `/api/v1/user/me` 两个 HTTP 处理器（`get_current_user.rs`、`update_current_user.rs`），并通过 `profile/mod.rs` 的 `pub use` 暴露 handler 函数。每个处理器使用 `ai_orz_macros` 的 `#[generate_http_handler]` 宏生成路由绑定，并用 `#[register_handler_tool(...)]` 注册为工具元信息（id/name/description/params）。业务逻辑完全委托给 `crate::service::domain::organization` 领域的 `user_manage()` 抽象层，处理器自身只负责从 `RequestContext` 提取 `user_id`、参数校验、错误转换（`bad_request`/`not_found`）以及将领域模型映射为 `common::api` 中的响应 DTO。
