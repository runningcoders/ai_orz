- 每个业务子域（Project/Task/Artifact）各自一个 `.rs` 文件实现对应的 Manage trait，trait 定义集中在 `mod.rs` 中。
- 所有写操作在调用 DAL 前通过 `enrich_ctx!` 将当前实体注入 RequestContext，再使用 `record_event!` 记录包含 from/to status、operator、root_user_id 等字段的审计事件。
- 可选关联数据的加载采用 FetchOptions 模式（如 `with_task_graph`、`with_artifacts`、`with_progress_summary`），由 Domain 层按需二次调用其他 DAL 进行聚合。
- 状态变更统一通过 `transition_status` 方法集中校验合法转移表（match current→target），禁止直接修改状态字段。
- 对外查询区分 `list`（语法糖）与 `query`（核心通用查询），复杂过滤场景要求调用方直接使用 `query`。
- DAL 依赖通过构造函数注入 `Arc<dyn XxxDal + Send + Sync>`，并在模块顶部用 `OnceLock` 暴露全局单例，测试时通过 `new(...)` 替换实现。
