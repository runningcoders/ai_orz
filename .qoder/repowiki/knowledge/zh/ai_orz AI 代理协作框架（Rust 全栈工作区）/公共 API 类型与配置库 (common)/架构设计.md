本模块以 `lib.rs` 暴露 `api`、`config`、`constants`、`enums`、`error`、`models` 六个子模块，作为跨进程（后端服务 + 前端）共享的类型契约。
- `api/`：按领域（agent、artifact、attachment、auth、message、project、skill、task、tool、user 等）拆分 DTO 文件，每个 DTO 使用 `serde` 序列化并通过 `schemars::JsonSchema` 生成 JSON Schema；统一通过 `ApiResponse<T>`、`EmptyResponse`、`PaginationParams`、`PagedResult<T>` 封装请求/响应格式，并在 `mod.rs` 中集中 `pub use` 重导出。
- `enums/`：每个领域一个枚举文件（如 `agent.rs`、`project.rs`），在 `mod.rs` 中汇总 re-export，供前后端共用状态机与分类值。
- `config.rs`：定义 `AppConfig` 聚合体（server/database/stats/frontend/logging/jwt/consumer/lark/a2a_server），所有字段通过 `#[serde(default)]` 提供默认值，并提供大量路径构造方法（`db_path`、`artifacts_dir`、`agent_data_dir`、`skills_root_dir` 等）统一基于 `BASE_DATA_PATH`（可通过 `AI_ORZ_BASE_PATH` 环境变量覆盖）派生磁盘路径。
- `error/`：统一的强类型错误体系，包含 `ErrorCode`、`ErrorType`、`ErrorField`、`Error` 以及 `bail_err`/`ensure_err`/`err` 宏，并可选实现 `axum::response::IntoResponse`（受 `axum-integration` feature 控制）。
- 依赖方向：`api` 依赖 `enums`、`error`、`models`；`config` 依赖 `enums`；整个 crate 通过 `Cargo.toml` 的 `[features]`（`sqlx`、`axum-integration`、`jwt-integration`、`tokio-integration` 等）按需引入重型依赖，使核心类型保持无 I/O 的纯数据层。
