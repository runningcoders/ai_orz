- API 请求/响应结构体统一使用 `#[derive(Debug, Clone, Serialize, Deserialize)]`，并通过 `schemars::JsonSchema` 派生以生成 OpenAPI 兼容的 JSON Schema。
- DTO 按领域拆分为独立文件（如 `agent.rs`、`project.rs`），并在 `api/mod.rs` 中通过 `pub mod` 声明与 `pub use *::*` 集中重导出，测试文件以 `<domain>_test.rs` 命名并通过 `#[cfg(test)]` 引入。
- 配置结构体全部使用 `#[serde(default)]` 标注可省略字段，并为每个配置块实现 `Default` trait，由独立的 `default_xxx()` 函数提供默认值。
- 路径访问统一通过 `AppConfig` 上的方法（如 `db_path`、`artifacts_dir`、`agent_data_dir`）派生，避免在业务代码中拼接字符串路径。
- 错误处理采用 `common::error::{Error, ErrorCode, ErrorType}` 统一模型，并通过 `bail_err!`、`ensure_err!`、`err!` 宏抛出，对外暴露 `common::error::Result<T>` 别名。
- 重型第三方依赖（axum/sqlx/tokio/jsonwebtoken 等）通过 Cargo features 条件引入，仅在对应 integration feature 开启时才参与编译。
