模块按职责划分为五个子目录，构成 Dioxus 0.7 应用的共享基础设施：
- `api/`：基于 reqwest + web_sys 的 HTTP 客户端，集中实现 `api_get/api_post/api_put/api_delete/api_post_multipart` 等通用方法，统一封装 `ApiResponse<T>` 反序列化、401 自动跳转登录、`ApiError` 错误模型，并按业务域拆分为 auth/background_task/finance/hr/log_stats/message/organization/project/seed/system 子模块；通过 `build_pagination_url` / `build_query_string` 统一分页与查询参数构造。
- `components/`：纯 Dioxus 组件库，包含图表（charts/）、聊天（chat/）、画布场景（canvas_scene/chart_scene/force_layout/graph_canvas/workspace_graph/relation_graph）、通用 UI（button/modal/toast/confirm_dialog/markdown/code_editor/searchable_select）及业务组件（create_http_tool/process_detail/stats/task_progress/aop_gauge/gauge/hud_palette/kanban_canvas/layered_layout/particles/state），各子模块通过 `mod.rs` 再导出公共类型。
- `hooks/`：以 `use_` 前缀暴露 Dioxus Hook，如 `use_workspace_data`（聚合 projects + agents 列表加载）、`use_resource`、`use_require_auth`（未登录重定向并回填 role）、`use_theme`/`use_provide_theme`（基于 Context + localStorage 的主题控制器）。
- `layouts/`：`AppLayout` 作为根布局组合 Navbar 与 Content，并在顶层执行 `use_require_auth` 权限守卫；`navbar` 负责导航菜单渲染。
- `store/`：基于 Dioxus `Signal` 的全局状态，`auth.rs` 维护登录态、角色、用户名、组织 ID 并通过 localStorage 持久化；`toast.rs` 提供全局消息通知。
- `utils/`：纯函数工具集（time/file/message/status）与 `local_storage()` 封装，被 store 和 hooks 复用。
依赖方向严格单向：components/hooks/layouts → store/utils → api → common crate；api 不反向依赖任何前端模块。
