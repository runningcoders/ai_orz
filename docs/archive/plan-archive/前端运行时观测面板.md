## 一、目标

| 问题 | 方式 |
|------|------|
| 后端 3 个运行时接口（runtime-status/cancel-thinking/runtime-list）已交付，前端无对接 | API Client 新增 3 个函数，复用 common::api::runtime DTO |
| Agent 详情页无运行时实时面板 | 详情页新增第 7 Tab「⚡ 运行时」，渲染 RuntimePanel 组件 |
| 用户无法主动取消思考（浪费 token+时间） | RuntimePanel Busy 态显示取消按钮，ConfirmDialog 二次确认 |
| 工作台缺少全局运行中 Agent 视角 | Workspace 顶部统计条下方新增运行中 Agent 卡片，5 秒轮询，支持状态过滤 |
| 轮询频率过高浪费请求，过低不实时 | 智能降频：Busy 3 秒轮询，Idle/Resting 30 秒降频 |

收敛一句话：前端 3 模块（API Client + RuntimePanel 组件 + Workspace 卡片）对接后端 3 运行时接口，完成思考运行时可视化闭环 + 主动取消。

## 二、架构思路

```
frontend/
├── api/hr.rs
│   ├─ get_runtime_status(req)  → GET /agents/{id}/runtime-status
│   ├─ cancel_thinking(req)     → POST /agents/{id}/cancel-thinking
│   └─ list_runtime_agents(req) → GET /agents/runtime-list?state=&task_id=&project_id=
│
├── components/
│   └── runtime_panel.rs
│       ├─ Props: agent_id: String
│       ├─ use_future 轮询（Busy 3s / Idle 30s）
│       ├─ 状态展示：state badge + 上下文（message/task/project）
│       ├─ ThinkRuntimeCard：场景/轮次进度条/token 4 格/trace_id
│       └─ 取消按钮：ConfirmDialog 二次确认 → cancel_thinking
│
├── pages/hr/agent_detail.rs
│   └─ Tab 6 (index=6)「⚡ 运行时」→ RuntimePanel { agent_id }
│
└── pages/workspace.rs
    ├─ use_future 5 秒轮询 list_runtime_agents
    ├─ 过滤条：全部 / 思考中 / 休息中
    └─ 运行中卡片：state badge + agent_id + scene/round/token + task_id
        └─ onclick → WorkspaceView::AgentDetail 跳转详情页

复用资产：common::api::runtime::*（DTO 单一事实源）、ConfirmDialog、agent_runtime_badge_class 样式
```

## 四、分发点速查表

| 功能场景 | 组件/函数 | API 调用 | 轮询策略 |
|----------|----------|----------|----------|
| 详情页运行时面板 | RuntimePanel { agent_id } | get_runtime_status | Busy 3s / Idle 30s |
