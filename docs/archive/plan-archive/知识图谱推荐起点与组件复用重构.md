## 一、重构目标（为什么做）

知识图谱功能存在两个体验缺口：(a) 用户进入图谱页面面对空白画布，没有"从哪里开始遍历"的引导；(b) 想看单个 Agent 的知识图谱只能在全局页切换 Agent，Agent 详情页缺少独立的知识图谱视图。

| 问题维度 | 解决方式 |
|---------|---------|
| (a) 知识图谱页面无"起步入口" → 用户面对空画布不知点哪里 | 后端新增 `recommend_seed_nodes` 接口：按节点关联度数（入+出）倒序 Top N 推荐核心节点；前端渲染推荐卡片，点击直接触发 seed_node_ids 遍历 |
| (b) 仅全局知识图谱路由入口，Agent 详情页看不到专属图谱 | 前端拆分 `knowledge_graph.rs`：路由入口 `HrKnowledgeGraph`（AppLayout+Agent选择器）+ 可复用子组件 `KnowledgeGraph { agent_id: Option<String> }`；Agent 详情页新增第 5 个 Tab 嵌入 KnowledgeGraph（agent_id 固定 Some） |
| (c) 推荐需要跨 Agent 全局 & 单 Agent 两种模式 | RecommendSeedNodesParams.agent_id: Option<String>，None 时包含 published 共享节点；DAL 层 limit 保护 500 上限 |
| (d) 度数统计如果纯 SQL 实现复杂依赖 SQLite 窗口函数 | DAL 应用层统计：先 query_knowledge_nodes 拉节点 → list_relations_batch 查所有关系 → HashMap 汇总每个节点的入/出边 → 倒序 truncate(limit) |
| (e) 组件拆分后推荐起点区、搜索、图谱渲染三处内部状态耦合 | 全部收敛到 `KnowledgeGraph` 子组件内部 use_signal；对外只暴露 `agent_id: Option<String>` 一个 prop，agent_id 变化时 use_effect 自动重加载推荐 |

**收敛后效果**：知识图谱组件变为"可嵌入 widget"；任意页面只需一行 `KnowledgeGraph { agent_id: Some(x) }` 即可渲染完整图谱（含推荐起点），无需重复写画布逻辑。

## 二、架构思路（怎么做的）

推荐链路（后端） + 组件复用（前端）双链路：

```
后端（度数统计应用层计算）
前端 HTTP → recommend_seed_nodes handler
  │  RecommendSeedNodesParams { agent_id: Option, limit: Option }
  │  limit 默认 5，最大 50（min(5,50) 保护）
  ▼
RuntimeMemory trait（分层合规入口）→ 委托 DAL
  │
  ▼
MemoryDal::recommend_seed_nodes
  ① query_knowledge_nodes：按 MemoryQuery（agent_id / status=Active / exclude=Forgotten / limit=500 上限保护）
  ② list_relations_batch(node_ids)：一次拉所有节点的关系
  ③ HashMap 遍历 relations 聚合 (incoming, outgoing)：出边 source 计数 +1 / 入边 target 计数 +1
  ④ 组装 SeedNodeRecommendation { node, degree, incoming, outgoing }
  ⑤ sort_by degree 倒序 → truncate(limit)
  ▼
Handler：domain 结构 → API DTO（node.id/node_name/summary/tags JSON 解析）
  │
前端组件（拆分）
HrKnowledgeGraph（路由入口）
  │  AppLayout 外壳 + Agent 选择器 SearchableSelect
  │  选中 agent 格式 "name (id)" → rfind('(') 提取 id
  ▼
KnowledgeGraph 子组件（Props: agent_id: Option<String>）
  ├─ use_effect(agent_id)：当 agent_id 变化 → 调 recommend_seed_nodes 加载推荐
  ├─ 推荐起点卡片网格：每个卡片展示 node_name/summary/node_type/degree 徽章
  │   → 点击 → 复用内部 handle_node_click(node_id)，直接 seed 遍历（跳过搜索步骤）
  ├─ 搜索框区（原有）
  └─ 图谱画布渲染（原有）
    Agent 详情页 Tab5 → KnowledgeGraph { agent_id: Some(id.clone()) }
    → agent_id 固定 → use_effect 只执行一次 → 推荐只加载该 Agent 的核心节点
```

**关键边界（行为红线，回归必保）**：
1. **推荐节点数上限保护**：DAL 层 query_knowledge_nodes 固定 limit=500，避免节点过多时 list_relations_batch 拖慢响应；handler 层再 min(50) 防参数滥用
2. **全局推荐语义（agent_id=None）**：必须包含 include_shared=true（published 共享节点纳入推荐池），否则全局推荐只有未隔离的未分类节点，空结果率高
3. **KnowledgeGraph 子组件单一对外 Prop**：仅 `agent_id: Option<String>`；推荐/搜索/选中节点等全部是内部 use_signal，禁止外部驱动内部状态（避免 props 爆炸）
4. **推荐卡片点击直接 seed 遍历**：必须走内部 handle_node_click（保证 seed_node_ids 信号被设置 → 触发后续加载节点 & 边），禁止单独写一份分支逻辑（易漏掉画布刷新）
5. **Agent 选择器 "name (id)" 格式约定**：rfind('(') 后 slice 需确认 len-1 去掉尾 ')'；与 agent_detail.rs 已有相同模式保持一致

## 七、后续扩展路径（推荐功能增强 4 步模板）

> **核心不变量**：KnowledgeGraph 子组件单 Prop 模式 / recommend_seed_nodes 接口形态不动。

1. **增加推荐维度（如基于时间衰减的热度）**

   - 如需权重可配置：在 RecommendSeedNodesParams 增加 ranking_mode 枚举字段（Degree / Recency / Hybrid）
2. **推荐卡片点击后自动展开 1 跳邻居**
   - 子组件 [knowledge_graph.rs](../../frontend/src/pages/hr/knowledge_graph.rs) 推荐卡片点击处，当前仅 handle_node_click；可增加一步：调用 load_relations(node_id) 预展开 1 跳邻居（已有内部 load_relations 函数，手动触发）
3. **新增 Project 详情页嵌入知识图谱**
   - 参照 Agent 详情页 Tab5 模式：在 project_detail.rs 的 tab 区新增 tabX，渲染 `KnowledgeGraph { agent_id: None }`（如需 project 维度：需后端 MemoryQuery 扩 project_id 过滤 + DAL 适配）
4. **推荐起点增加"冷门惊喜"（低度新奇性）模式**
   - 前端推荐区增加下拉："热门核心 (度高)" / "冷门发现 (度低)"；后端 ranking_mode 扩展 LowDegree 分支，将排序逻辑改为正序取低度节点（适合知识探索场景）
