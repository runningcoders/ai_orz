## 一、重构目标（为什么做）

组织首次初始化后技能库为空，内置工具只在内存 registry 注册但 DB 无记录，default.json 的技能元数据不携带文件内容，大技能文件内嵌 JSON 也不便维护。

| 问题维度 | 解决方式 |
|---------|---------|
| (a) default.json 技能无文件内容 → apply 后 skill.md 不会创建 | SkillFileDef 支持三来源（content / ref_path / url），apply 时按优先级解析并写入 |
| (b) 大技能文件内嵌 JSON 维护不便 | 引入 include_dir! 将 seed/skills/ 目录编译期嵌入，default.json 用 ref_path 引用 |
| (c) 新组织初始化无预置技能（技能库空） | initialize_system 增加 apply_preset_skills 步骤，从 default.json 读取导入 |
| (d) 内置工具只注册到内存 registry，DB tools 表空 | initialize_system 增加 sync_builtin_tools 步骤（domain 层补方法） |
| (e) apply_snapshot 与 initialize_system 技能导入逻辑重复 | 抽出 apply_preset_skills 独立函数，两个入口统一调用 |

**收敛后效果**：预置技能仅在 default.json + seed/skills/ 目录维护，两个导入入口共用同一函数；首次初始化后新组织"开箱即用"有 3 个 neural 基础技能 + builtin 工具写入 DB。

## 二、架构思路（怎么做的）

四层收敛，数据来源单一（default.json 唯一真相源）：

```
default.json 总控 meta（编译期 include_str!）
  │  技能定义（元数据 + SkillFileDef，用 ref_path 引用编译期内嵌）
  ▼
seed/skills/ 子目录（编译期 include_dir! 嵌入）
  │  platform_guide/skill.md、memory_guide/skill.md、collaboration_guide/skill.md
  ▼
apply_preset_skills(ctx, skills, author_id_override)
  │  共享逻辑：解析 SkillFileDef 三来源 → 元数据 upsert → 文件写入
  │  author_id_override：初始化传 Some(owner) / 模板恢复传 None
  ▼
两个入口统一调用：
  ├─ initialize_system（首次初始化）：sync_builtin_tools + apply_preset_skills
  └─ apply_snapshot_to_db（模板恢复）：apply_preset_skills
```

**关键边界（行为红线，回归必保）**：
1. SkillFileDef 内容优先级：`content` > `ref_path` > `url`；三者全空返回错误
2. 旧快照向后兼容：SkillDef.files 字段 `#[serde(default)]`，无 files 字段按空 vec 处理
3. author_id 替换语义：仅当 `author_id_override.is_some()` 且原 author 为 `TEMPLATE_ADMIN` 时才替换，不影响第三方导入技能
4. include_dir 路径锚定 `src/service/domain/system/seed/`，ref_path 必须是该目录下的相对路径（如 `skills/platform_guide/skill.md`）
5. URL 抓取场景（预留）：必须 HTTPS；预置技能仅用 ref_path，不依赖运行时网络

### 4.2 SkillFileDef 三来源解析

| 来源 | 场景 | 优先级 |
|------|------|--------|
| `content: Some("...")` | 小内容直接内嵌 JSON / 导出快照时 | 最高（1） |
| `ref_path: Some("skills/x/skill.md")` | 预置技能（编译期内嵌，无运行时依赖） | 中（2） |
| `url: Some("https://...")` | 运行时动态抓取远程技能（预留，需 HTTPS） | 最低（3） |

> 代码入口：[mod.rs :: resolve_skill_file_content()](../../src/handlers/system/seed/mod.rs)

## 七、后续扩展路径（新增预置技能 4 步模板）

> **核心不变量**：导入逻辑 / default.json 结构 / SkillFileDef 解析机制不动。

1. **创建技能内容文件**：[seed/skills/](../../src/service/domain/system/seed/skills/)
   - 新建子目录 `skills/{技能简称}/`（如 `skills/tool_guide/`）
   - 写入主文件 `skill.md`；如需附件放同目录（参考 platform_guide 结构）
2. **在 default.json 声明元数据**：[default.json](../../src/service/domain/system/seed/default.json)
   - 复制现有 TEMPLATE_PLATFORM_GUIDE 条目改字段
   - ID 命名：`TEMPLATE_{大写英文简称}_GUIDE`
   - files 字段：`[{ "path": "skill.md", "ref_path": "skills/{简称}/skill.md" }]`
3. **（可选）增加 URL 来源动态技能**：
   - SkillFileDef.url 填 HTTPS URL；预置技能不建议用此方式（网络依赖），仅适合第三方远程技能市场场景
   - 需先验证 URL 可访问性 + 返回内容大小限制（避免阻塞导入）
4. **（可选）预置技能自动绑定到所有新 Agent**：
   - 当前设计仅写入共享库（Published），Agent 需用户主动安装
   - 如需自动绑定：在 initialize_system 中 apply_preset_skills 后循环调用 `install_skill_to_agent`
   - 参考：`SkillManage::install_skill_to_agent` 方法签名
