> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「Agent 回复用户消息」在飞书渠道走引用回复端点（`POST /open-apis/im/v1/messages/:message_id/reply`），话题消息以话题形式回复，非飞书渠道与无父消息场景静默降级为普通发送。

**Architecture:** 三层协作，渠道无关的解析与渠道相关的传输决策分离：
- **Domain**（`src/service/domain/message/delivery.rs`）：出站消息继承父消息 `thread_id` 并落库（复用已有 root_id 父消息查询，零额外查询）；`deliver_message` 按 `reply_to_id` 反查父消息**一次**，产出渠道无关的 `ReplyTarget { external_key, thread_id }` 透传。
- **DAL**（`src/service/dal/message_channel.rs`）：`MessageChannelDalImpl` 是唯一的出站编排器；其 Lark 分支把渠道无关的 `ReplyTarget` 解析为飞书原生参数（剥离 `lark:` 前缀取 `om_xxx`、按 `thread_id` 决定 `reply_in_thread`），其余渠道忽略。
- **DAO**（`src/service/dao/lark/http.rs`）：新增 `reply_text_message`，`push` 按是否携带回复参数在「回复端点」与「发送端点」之间二选一。

**Tech Stack:** Rust + Axum + sqlx 0.8 + SQLite；reqwest 出站；`#[sqlx::test]` 测试；Makefile 门禁（`make clippy` / `make test-be`）。

---

## 背景与不变量

- **创建与推送是两段异步**：`send_to_user`/`send_to_agent` 只 `save_message`；随后 `MessageConsumer` 重新从 DB fetch 消息再走 `Domain::deliver_message`。父消息的上下文无法在内存中跨阶段传递，故 `deliver_message` 现场按父键反查一次（主键点查，成本极低）。
- **外部键口径**：出站推送成功后 DAL 回写 `messages.external_key = "lark:{om_xxx}"`（见 `src/service/dal/message_channel.rs#L486-L502`）。回复目标即「父消息的 external_key」。
- **话题语义**：入站话题消息的 `thread_id`（`omt_` 前缀）已在阶段一贯通落库（`messages.thread_id`）。飞书官方说明：回复一条已是话题形式的消息时默认按话题回复；显式传 `reply_in_thread: true` 语义等价且更明确。

## 非目标（本计划不做）

- 微信 / Slack / Email / Webhook / A2A 渠道不实现引用回复（无对应语义，保持现状）。
- 仅支持文本消息的引用回复；媒体/卡片回复不在范围内。
- 不改动 `messages.external_key` 的既有写入口径。

```rust
/// 出站引用回复目标（渠道无关）
///
/// 由 Domain 层按出站消息的 `reply_to_id` 反查父消息得出，透传给渠道 DAL。
/// DAL 各渠道分支按自身语义解释：飞书剥离 `lark:` 前缀得到 `om_xxx` 并据此走
/// 回复端点；其它渠道忽略。
#[derive(Debug, Clone)]
pub struct ReplyTarget {
    /// 父消息在外部渠道的键（形如 `lark:om_xxx`）
    pub external_key: String,
    /// 父消息所属话题 ID（`omt_` 前缀）；`None` 表示非话题消息
    pub thread_id: Option<String>,
}

/// 把渠道无关的回复目标解析为飞书原生回复参数（纯函数，便于单测）
///
/// - 校验 `external_key` 渠道前缀为 `lark:` 并剥离出飞书 `om_xxx` message_id；
/// - `thread_id` 存在 → 以话题形式回复（`reply_in_thread = true`）。
///
/// 返回 `None` 时调用方降级为普通发送（无目标 / 前缀不符 / 键为空）。
fn resolve_lark_reply(target: Option<&ReplyTarget>) -> Option<LarkReply> {
    let target = target?;
    let message_id = target.external_key.strip_prefix("lark:")?;
    if message_id.is_empty() {
        return None;
    }
    Some(LarkReply {
        message_id: message_id.to_string(),
        in_thread: target.thread_id.is_some(),
    })
}
```

```rust
    /// 以「引用回复」形式发送文本消息到指定飞书消息
    ///
    /// 端点：`POST /open-apis/im/v1/messages/:message_id/reply`。
    /// `reply_in_thread = true` 时以话题形式回复（父消息属于话题时使用）。
    /// 返回值语义与 [`Self::send_text_message`] 一致（无 message_id 时返回 `None`）。
    pub async fn reply_text_message(
        &self,
        token: &str,
        reply_to_message_id: &str,
        text: &str,
        reply_in_thread: bool,
    ) -> Result<Option<String>> {
        let content = serde_json::json!({ "text": text }).to_string();

        #[derive(Serialize)]
        struct ReplyMessageReq {
            content: String,
            msg_type: &'static str,
            reply_in_thread: bool,
        }

        #[derive(Default, Deserialize)]
        struct ReplyMessageData {
            #[serde(default)]
            message_id: String,
        }

        let url = format!(
            "{}{}",
            API_BASE,
            PATH_REPLY_MESSAGE.replace("{message_id}", reply_to_message_id)
        );
        let resp = self
            .http
            .post(&url)
            .bearer_auth(token)
            .json(&ReplyMessageReq {
                content,
                msg_type: "text",
                reply_in_thread,
            })
            .send()
            .await
            .map_err(|e| from_reqwest("reply_message", e))?
            .json::<LarkResponse<ReplyMessageData>>()
            .await
            .map_err(|e| from_reqwest("reply_message", e))?;

        let data = resp.check("reply_message")?;
        if data.message_id.is_empty() {
            log_warn!(
                "lark reply_message succeeded without message_id: reply_to={}",
                reply_to_message_id
            );
            return Ok(None);
        }
        Ok(Some(data.message_id))
```
