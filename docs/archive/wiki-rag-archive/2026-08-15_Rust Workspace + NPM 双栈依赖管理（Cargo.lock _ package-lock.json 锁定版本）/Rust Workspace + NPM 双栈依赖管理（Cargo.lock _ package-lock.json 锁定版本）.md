## 1. 使用的系统与工具

- **后端/前端 Rust 代码**：使用 Cargo workspace 统一管理四个成员——根 `ai_orz`、`frontend`、`common`、`ai-orz-macros`，通过根 `Cargo.toml` 的 `[workspace] members` 声明，resolver 设为 `2`。
- **前端 Node.js 资源**：使用 npm（`package.json` + `package-lock.json`），仅包含 Tailwind CSS v4 CLI、DaisyUI v5 等构建期依赖，无运行时 JS 包。
- **工具链锁定**：`rust-toolchain.toml` 固定 channel 为 `stable`，并预装 `rustfmt`、`clippy` 组件以及 `wasm32-unknown-unknown` target。
- **CI 缓存与离线编译**：`.github/workflows/rust.yml` 设置 `SQLX_OFFLINE=true`，并通过 sccache (`mozilla-actions/sccache-action`) 缓存跨 job 的编译产物；同时缓存 `~/.cache/ort`（ONNX Runtime 预编译二进制）和 `~/.cache/sccache`，key 基于 `Cargo.lock` hash。

## 2. 关键文件

- `Cargo.toml`（根 workspace）：声明成员、workspace resolver、各 crate 的依赖与 features。
- `common/Cargo.toml`：共享 crate，通过 optional dependencies + feature flags（`sqlx`、`axum-integration`、`jwt-integration`、`base64-integration`、`reqwest-integration`、`toml-integration`、`bincode-integration`、`tokio-integration`）按需裁剪依赖树。
- `ai-orz-macros/Cargo.toml`：proc-macro crate，仅依赖 `proc-macro2`、`quote`、`syn`、`schemars`、`glob`、`serde_json`。
- `frontend/Cargo.toml`：Dioxus 0.7 WASM 应用，依赖 `dioxus`、`web-sys`、`wasm-bindgen` 等，并通过 `path = "../common"` 引用共享 crate。
- `frontend/package.json` + `frontend/package-lock.json`：npm 依赖声明与锁定。
- `Cargo.lock`：整个 workspace 的单一锁文件，所有子 crate 共享同一份解析结果。
- `rust-toolchain.toml`：固定 toolchain 与组件。
- `.github/workflows/rust.yml`：CI 中安装 protoc（供 lancedb 的 build script）、启用 sccache、运行 clippy/test/coverage。

## 3. 架构与约定

- **Workspace 内依赖**：`common` 与 `ai-orz-macros` 通过 `path = "..."` 以本地路径引用，不发布到 crates.io，由 workspace 统一解析版本。
- **Feature-flag 裁剪依赖**：`common` crate 将重依赖（sqlx、axum、jsonwebtoken、reqwest、toml、tokio、base64）全部标记为 `optional = true`，由调用方通过 feature flag 显式开启，避免引入不必要的编译开销。
- **版本范围策略**：外部 crate 普遍采用语义化版本区间（如 `axum = { version = "0.8" }`、`sqlx = "0.8.6"`、`fastembed = "5.13"`），具体版本由 `Cargo.lock` 锁定；前端 npm 依赖使用 `^` 前缀（如 `tailwindcss: ^4.1.0`），由 `package-lock.json` 锁定。
- **特性开关控制第三方行为**：例如 `fastembed` 禁用 default-features 中的 `image-models` 以避免 image → exr → pulp 的 x86 const eval bug；`rmcp` 关闭 default-features 仅启用 `client` 与 `transport-child-process`。
- **数据库迁移与离线模式**：`migrations/` 目录存放 SQLx 迁移脚本，CI 中通过 `SQLX_OFFLINE=true` 配合 `.sqlx/` 快照进行离线校验。

## 4. 约定与约束

- **workspace 成员边界**：只有根 `Cargo.toml` 声明的四个成员参与构建；`common` 与 `ai-orz-macros` 是独立 crate，不反向依赖后端 service 代码，保证可被 frontend 复用。
- **toolchain 固定**：所有构建（本地与 CI）必须使用 `rust-toolchain.toml` 指定的 `stable` channel，且必须包含 `rustfmt`、`clippy` 组件及 `wasm32-unknown-unknown` target。
- **CI 门禁依赖**：Clippy 与测试阶段要求系统级 `protoc` 与 `libprotobuf-dev`（用于 lancedb/lance-encoding 的 build script），缺失则构建失败。
- **依赖更新流程**：新增或升级外部 crate 需同步提交 `Cargo.lock` 与 `package-lock.json`；CI 通过 `cargo fmt --all -- --check` 与 `cargo clippy --all-targets -- -D warnings` 强制格式与 lint 一致性。
- **覆盖率门禁**：coverage job 使用 `cargo-llvm-cov`，push main 时 fail-under-lines 阈值 45%，PR 时为 38%，低于阈值即失败。
- **无私有注册表**：仓库未配置 `cargo config` 或 `.npmrc` 指向私有源，所有依赖来自 crates.io 与 npmjs.org。
