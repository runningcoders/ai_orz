# 统一定时调度器 P3 落地方案

> P0/P1/P2 打通了数据、租约、派发与 Agent 自主创建；P3 把现有 `/system/triggers` 页面按 **When / Who / What / How** 四组模型升级，**不新建日程独立页、不引日历组件**（A-设计 §10 判据）。

## 1. 边界与决策

| 项 | 决策 | 依据 |
|---|---|---|
| 页面归属 | 沿用 `frontend/src/pages/system/triggers.rs` 与 `/system/triggers` 路由 | A-设计 §10「原位改造、组件复用」 |
| 形态区分 | 同页列表，用 `trigger_type` + `behavior` 双标签区分；加形态/行为两个筛选下拉（前端本地过滤） | A-设计 §10「同页分形态」 |
| 系统项 readonly | 新增的 Who / What / How 字段在编辑弹窗里只读展示，**不放开编辑入口**；原有 name/时间/payload 编辑能力保留 | A-设计 §10「系统项保留 readonly 语义，不因改造放开编辑」 |
| 组件复用 | 表格、分页外的筛选下拉、Modal、Cron 预设、状态标签全部沿用；未引入任何新组件 | A-设计 §10 |
| 写路径 | 不改 DTO、不改后端 handler：创建/更新仍只提交基础字段；身份与行为模板由后端/P2 工具固化 | P2 已定「Who 组从 ctx 固化，前端不可传」 |

## 2. 落地内容

### 2.1 列表按四组重排

表头从 7 列改为 8 列：`名称 / What` · `形态 / How` · `When` · `Who` · `状态` · `下次执行` · `上次执行` · `操作`。

- **What**：名称下方展示 `description`（截断 + title 悬浮），无说明时回落顶层 `action`；
- **How**：触发类型 badge 与行为模板 badge 双标签，行为模板用可读文案（同步维护 / 异步通知 / Agent 唤醒），异步两族用 `badge-info` 轻区分；
- **When**：原调度信息（cron / 间隔 / 指定时间）+ 生效窗口（`start_at`~`end_at`）第二行；
- **Who**：`创建者/ID → 目标类型/ID`，系统触发器两者皆空时显示「系统」。

新增纯函数（文件内，可单测口径）：`behavior_text` / `behavior_badge_class` / `is_system_shape` / `creator_type_text` / `target_type_text` / `who_text` / `window_text`。

### 2.2 筛选

两个本地筛选 signal：`ShapeFilter`（全部/系统/日程，按 `behavior == SyncMaintenance` 判定）、`BehaviorFilter`（全部/同步/通知/唤醒）。`filtered_list` 由 `triggers_list` 派生，列表统计条数与空态文案随之变化（有数据但无匹配时提示「当前筛选条件下无匹配项」）。

### 2.3 编辑弹窗四组只读概览

点「编辑」时 `get_cron_trigger` 详情存入 `detail_snapshot`，弹窗顶部渲染只读概览（When / Who / What / How + 说明 + 窗口）。这些字段**不出现在可编辑表单区**——系统项因此天然 readonly，日程项身份字段也不会被误改。

### 2.4 修 P2 遗留的日程编辑 bug

P2 给编辑回填加了 `TriggerType::Schedule => "schedule"`，但表单 select 没有对应 option、提交 match 又把未知值兜底成 `Cron`——编辑日程保存会把形态改掉。本阶段一并修：

- 触发类型 select 增加 `日程（三选一）` 选项；
- 提交逻辑 `"schedule" => TriggerType::Schedule`，时间严格按 **cron > interval > run_at** 三选一（与后端 `create_cron_trigger` 一致）；
- 回填时按实际存储的字段分别回填 `form_cron` / `form_interval` / `form_run_at_local`；
- 新增 `parse_local_datetime_ms` / `format_local_datetime`（datetime-local ↔ 毫秒，本地时区）支撑一次性日程的指定时间。

## 3. 验证

- `make clippy-fe`：全绿（前端 wasm clippy）。
- 未改后端代码、未改 DTO，后端测试不受影响。
- 文档门禁：`make wiki-meta` / `make wiki-index` / `make wiki-check` 全绿。

## 4. 手动创建的形态边界

前端 `+ 创建触发器` 选「日程（三选一）」时，走的是既有 `create_cron_trigger`：只写时间规则与基础字段，`behavior` 取默认 `SyncMaintenance`、Who 组为空（`validate_trigger` 对该模板放行）。**这是一条带日程形态标签的系统调度规则，不是 Agent 自主日程**——不会被 `AsyncAgentWakeup` 唤醒链路派发。真正的日程由 Agent 工具 `schedule_agent_task`（P2）创建，身份与行为模板由后端从 ctx 固化。表单里已加此提示，避免误用。

## 5. 明确不做

- 不新增日程独立路由、不引入日历/月视图组件（A-设计 §11）。
- 前端不创建/编辑 Who 组身份字段，也不选择 behavior（创建主体是 Agent 工具 `schedule_agent_task`，见 P2）。
- 不实现「取消日程」的独立语义：复用现有暂停/删除按钮（P3 判据「用户可查看/取消日程」由此满足）。
