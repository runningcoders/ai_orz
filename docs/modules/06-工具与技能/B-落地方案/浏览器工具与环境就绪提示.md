## 一、目标

| 问题 | 解决方式 |
|------|---------|
| `http_fetch` 抓不到 JS 渲染页 | 新增 Builtin 内置工具 `browser`，包装 agent-browser CLI（Manual，tag: `browser`） |
| 页面交互（点击/填表）无能力 | 透传原子子命令（open/snapshot/click/fill 等），daemon 常驻页面状态跨调用保持 |
| 绑定了工具但宿主机未装 CLI，绑定时无感知 | **tool_readiness 统一体系**：工具清单 `runtime_ready` 预检 + 前端绑定页警示 badge + 调用时结构化引导兜底 |
| lark_cli/gh_cli 缺失时报错泛化 | spawn 报错统一走 tool_readiness 引导（存量工具一并修复） |
| tavily_search 的 key 探测内联在工具内 | 迁入 tool_readiness，清单级可见 |

**收敛后效果**：Agent 具备「打开渲染页 → 快照定位 → 交互 → 截图取证」闭环；「选择了工具但环境缺失」在选工具、绑定、执行三个接触点都有清晰提示。

## 二、架构思路

```
browser.call(ctx, params)
    → tool_readiness::command_available(po.cli_command())   # D28：命令在 ToolPo.config，非 ai_orz.toml
        未找到 → { error_code: "cli_not_installed",
                   install: "brew install agent-browser 或 cargo install agent-browser",
                   hint: "或在浏览器工具配置页的 command 字段配绝对路径" }
    → 子命令黑名单校验（config.disabled_commands；默认空 = 不屏蔽、全开放）
    → tokio::Command spawn（不经 shell，argv 直拼）
        固定参数: --session ai_orz_agent_{agent_id}（会话隔离；非法字符折叠 `_`，纯符号 owner 加稳定哈希）
    → 超时 + stdout/stderr 合并 + 截断（超预算全量落盘回传 log_path）
    → screenshot 子命令: screenshot_path_arg 跳过带值选项定位 PATH（--screen 0 / --threshold 0.01 不当路径）
                        → 输出落 ArtifactManage 产物存储，返回引用

就绪预检（读路径，带用户上下文）：
list/query/search tools handler → to_list_item
    → tool_readiness::probe(tool_id, ctx.uid)（TTL 缓存，只读）
        CLI 型: 二进制可寻址（ToolPo.config 绝对路径优先 → PATH）
        key 型: 共享 config key 非空 OR 该用户凭证库含对应 kind（如 TavilyKey）
    → ToolListItem.runtime_ready: ready | not_ready{reason,hint} | unknown
前端 agent_detail「工具与技能」页 → 未就绪 badge
```

**关键边界**：Manual 人工确认；黑名单屏蔽脚本执行类子命令（默认不屏蔽）；headless 固定；截图落存储不内嵌 base64；探测只读 + TTL 缓存 + 异常返回 unknown。

## 七、后续扩展路径

1. **common（已落地）**：`BrowserConfig` 加统一 `env: Option<HashMap<String,String>>` 字段承接 agent-browser 启动变量；`BROWSER_ENV_CATALOG` 为常用中文兜底与引导文案，**不再是写入白名单**；写入走规则式校验（前缀 + 两级黑名单 + 字符串值 + 组合约束），前后端共用 `validate_browser_env`，spawn 侧再兜底一次。两级黑名单：`BROWSER_ENV_BLOCKED` 显式清单（session / namespace / config / plugins / flows-dir / dashboard / stream-port / no-xvfb 等）+ `BROWSER_ENV_DENY_TOKENS` 危险片段兜底（未登记的新变量命中外连 / 代码执行 / 凭据 / 会话 / 监听面片段即拒）；`validate_browser_env_combinations` 禁止 `ALLOWED_DOMAINS` 与 `STATE`/`RESTORE` 共存。已覆盖：自定义浏览器路径、启动参数、UA、配色、隐藏滚动条、代理 / 绕过、登录态（state/restore）、域名白名单、引擎等；CLI 新变量无需改代码即可配置。`runtime_ready` 枚举按需扩展新 reason 类型。
2. **后端动态探测（已落地）**：`pkg/tool_registry/browser_env_probe.rs` 在详情页加载时解析 agent-browser 自带 skills 文档的变量块（`KEY="示例" # 说明`），并扫本机已知浏览器路径、推导无凭据代理作为推荐值；`common::api::BrowserEnvProbeDTO` 承载结果。**仅 `get_tool` 挂 `attach_browser_env_probe`**（`update_tool` 不挂——前端保存后会重新拉详情，重复探测会让改 command 的保存多等一次子进程且结果随即被覆盖）；2~3s 超时 + 60s TTL **单条**缓存（与 command 无关），失败留 `None`。探测不参与就绪判定，CLI 变量表只有一张，来源标注区分「CLI 提供 / 内置精选」。
3. **前端（已落地）**：工具详情页 browser 配置表单改为引导式——探测来源标注（CLI 版本 / 静态兜底）+ 顶部「本机探测到的可用选项」一键填入 + 快捷预设（HTTP 代理 / CI 无沙箱，不再写死 macOS Edge 路径）+ 环境变量动态行（下拉来自动态 DTO 或 common 兜底、选中即显示含义与可填值、枚举项给下拉、推荐值按钮、CLI 来源标记、高级项标 warning）+ `allow_local_network` 下拉（默认允许 / 明确拒绝 / 允许本内网，见第 10 条纠偏）+ 安全边界说明。spawn 侧环境变量排序注入（`ExecOptions.envs`，语义为叠加而非替换）。`runtime_ready` 若需反映具体 env 问题再扩展 reason。
4. **open URL 入口检查（已落地，默认值见第 10 条纠偏）**：`pkg::http::validate_browser_open_url` 在 `browser.rs` 的 `open` 分支、spawn 之前做字面检查——scheme 限 http/https；云元数据端点无条件拒；localhost / 字面内网地址按管理员级 `BrowserConfig.allow_local_network` 放行（默认已改为允许，仅显式 `false` 收紧）。不做 DNS 解析（防虚假安全感）；拒绝返回结构化错误 + 引导文案。此检查只挡入口，完整边界仍靠浏览器级 allowed-domains 与部署层 egress（见 A-设计红线 17）。
5. **工具描述提示词引导（已落地，后经第 9 条修订）**：`create_po` 的 `description` 从平铺命令表改为带起步引导的 snapshot-and-ref 心智模型——何时用（HTTP fetch 看不到 JS 内容 / 需交互）→ 从 `open <url>` 起步 → `snapshot` 拿 `@eN` ref → 基于 ref 操作 → 页面变化后重新 snapshot（ref 失效）；并写明 `snapshot`/`read` 优先于 `screenshot`（截图只作视觉取证）、元素缺失先 `wait` 再 snapshot、session 跨调用保持无需重复 open。`browser_tests.rs::factory_po_metadata` 断言关键短语防文案回归。
6. **domain 分发**：无需 Domain 层改动（pkg 注册表闭环；截图存储经既有 DAL 入口）
7. **新工具文件**：未来其他外部 CLI（如 ffmpeg_cli）复用 tool_readiness 注册探测器即可获得三层提示
8. **注册**：builtin.rs 入表；tag `browser` 与 `search` 组「网络访问」工具包供 Agent 一键绑定
9. **整串 command + 动态 skill 转译（已落地）**：解决「官方 skill 是给裸 CLI 写的、照搬会过时」的阻抗不匹配——
   - **schema**：`BrowserParams` 从 `{command, args[]}` 收敛为单个整串 `command`（如 `fill @e3 "hello world"`），与 gh_cli/lark_cli/skillhub_cli 入参形态统一，Agent 读官方 skill 后去掉 `agent-browser` 前缀即可填入。`tokenize_command` 做 shell 风格分词（引号包裹 + 反斜杠转义；朴素 split_whitespace 会切碎 `fill` 的空格文本，这是与 gh_cli 的关键差异）；白名单改为校验首 token；截图路径 / `close --all` / `open` URL 检查均基于分词后参数。
   - **skills 只读子命令**：白名单新增 `skills`，`validate_skills_args` 只允许 `list [--json]` / `get <name> [--ref <path>]... [--json]`；拒 `--all`/`--full`（实测 `--full` 约 150KB）——拒 `path`（回显本机路径）；`--ref` 与技能名走路径白名单（仅 `[a-zA-Z0-9._/-]`、禁 `..`/绝对/UNC），防读本机任意文件。Agent 由此可动态读 CLI 自带的最新官方指南，`--ref` 按需加载单篇 reference，CLI 升级即自动跟版本。
   - **转译引导并入工具描述（曾短暂独立成 skill，后撤销）**：一度 seed 新增 `BROWSER_AUTOMATION` 桥接 skill，但转译内容收缩后与工具 description 高度重复、维护双份且还得占一个预置技能位（category 还得迁就白名单），故撤销 skill、把引导直接写进 `browser` 工具 description（常驻进提示词，模型调用工具时必然看到）。描述给出：整串 `command` + 去 `agent-browser` 前缀 + `skills get core` / `--ref` 读官方指南 + 默认开放可黑名单 + 核心循环（open→snapshot→ref→re-snapshot）+ session 持久 + 截图产物 + 优先用本工具而非裸 shell。CLI 易变的命令用法一律外包给自带文档，不复制，故不随升级落后。
   - 设计取舍（用户拍板）：曾考虑「保持结构化 + skill 教拆词」与「加 raw 兼容字段」，选整串方案求全家工具形态一致 + 转译极简；拒绝「完整开放 skills」（`--all` 撑爆上下文）。

10. **定位纠偏：配置管理而非功能封禁（已落地，取代第 9 条中的封禁设计）**：用户明确 browser 工具的定位是**把人该配的东西做成配置页**（命令路径 / 超时 / 启动环境变量 / 可选约束），而不是替用户决定「哪些 CLI 功能不许用」。核心论据：CLI 天然具备这些能力，硬禁只会挡住老实走工具的人——想绕的人走 shell_exec 一样能跑裸 `agent-browser`，白名单形同虚设。据此整体反转此前的硬编码封禁，改为配置驱动、默认开放：
    - **子命令白名单 → 黑名单配置项**：`BrowserConfig.disabled_commands: Option<Vec<String>>`，`None`/空（默认）= 不屏蔽，开放 CLI 全部命令（含 eval/batch/tab/cookies/network）；管理员只把明确有风险的命令列进来屏蔽，不必枚举其余命令，CLI 升级新增命令也默认可用——比白名单更契合「默认开放 + 配置管理」的定位。删掉硬编码 `ALLOWED_COMMANDS` 拦截。
    - **skills / close --all / screenshot 路径硬限制移除**：`validate_skills_args` / `validate_skills_ref` 删除，skills 参数（含 --all/--full/path）一律透传；`close --all` 放开；screenshot 允许 Agent 指定路径（给了就用、未给才用临时路径，成功仍归档产物并返回 local_path，Agent 指定路径不删）。`--full` 撑上下文的问题从「禁止」降为「skill 里建议优先 --ref」的引导。
    - **env 禁用清单 → 风险提示**：`validate_browser_env` 只保留 `AGENT_BROWSER_` 前缀 + 字符串类型这一个硬约束（防 PATH/LD_PRELOAD 劫持子进程，是字段语义边界而非功能封禁）；`BROWSER_ENV_BLOCKED`/`BROWSER_ENV_DENY_TOKENS`/组合约束从拦截改为 `browser_env_blocked_reason` 的风险提示，配置页照常可填、标 ⚠️ 由管理员取舍。探测 DTO 的 `configurable` 恒 true（字段保留兼容），前端移除只读禁用逻辑。
    - **allow_local_network 默认 true**：`unwrap_or(true)`，测本机 dev server 开箱可用；仅显式 `false` 收紧。云元数据仍无条件拒（真实 SSRF 风险，与效率无关）。
    - **Manual 语义澄清**：`ControlMode::Manual` 在 Agent 运行时走 `dispatch_manual_tool → request_tool_call` 同步转发、立即返回，**不是**每次弹人工审批（shell_env.rs:29 的旧注释误导）。工具描述已去掉「pauses for human approval」话术。
    - **静默截断 → 可恢复截断**（同批修正）：原 `combine_output` 超 256KB 直接扔掉尾部、只回 `truncated: true`，Agent 无从取回全文（且字节切片会切坏 UTF-8 多字节字符）。改为按字符边界收缩，全量写 `tools/browser/logs/{YYYYMMDD}/{call_id}.log`，回传 `truncated` + `full_output_bytes` + `log_path` + 取回提示（Agent 用 `fs_read` 自助读全文，对齐 `tool_output_boundary_design` 红线 1 与 shell_exec 协议）；落盘失败不否定命令结果，但如实回传「未留存」。工具描述补「truncated 时读 log_path」引导。
    - **`file://` 本地 HTML：完全对齐 fs_read/fs_write（同日再纠偏）**：撤销上一版"默认拒绝 + 自建目录白名单"方案——那套 `validate_browser_open_url_with_file`/`validate_local_file_url` 已删除。现改为复用 fs 的 `resolve_and_validate_path`（同一函数、同一 `FsAccessMode::Read`）：数据根 + `allowed_file_dirs`（对齐 fs 的 `additional_allowed_paths`）内可直接 `open file:///abs/path.html`；作用域外返回 `require_confirmation` 让 Agent 请求用户授权（非硬拒），敏感文件/符号链接按读档规则拒。`BrowserConfig.allow_file_url` 默认 `None/true` 放行，仅管理员显式设 `false` 才完全禁用。scheme 分派在 browser 工具层：file 走 fs 校验、http(s) 走字面检查。前端开关文案改为"默认：允许（与文件工具一致）"，工具描述补授权引导。详见 A-设计红线 19。
    - **保留的真实边界**：非 http(s)/云元数据 URL（`file://` 例外见上）、`AGENT_BROWSER_` 前缀、输出截断（现为可恢复截断）、超时、session 隔离、产物归档——这些是字段语义/资源管理/SSRF 纵深，不是对 CLI 功能的封禁。
    - 验证：browser 单测、集成测试、common 校验测试、env 探测测试、前端测试、`clippy -D warnings`、`inline-test-lint`、`wiki-check` 全通过。
