## 一、目标与范围

| 项 | 内容 |
|----|------|
| 目标 | 工作台从「监控看板」变为「可到场的现场」：进来能看到谁需要我，选中工位能推进到可操作的对话层 |
| 本期交付 | P0 结构拆分 → P1 后端投影 + 前端数据入口 → P2 席位场替换图谱 → P3 景深层可操作 |

## 三、后端方案

### 3.1 契约

新增 `common/src/api/scene.rs`，遵循「前后端复用契约放 common」：

```
GetSceneProjectionRequest
└─ seat_limit: Option<u32>        缺省 8，上限 8

SceneProjectionResponse
├─ generated_at: i64
├─ seq: u64                        进程内单调，重启归零
├─ entities: Vec<SceneEntity>      按 attention 优先级排序
├─ attention_total: u32
└─ stats: SceneStats

SceneEntity
├─ id: String
├─ kind: SceneEntityKind           Agent | Task | Project
├─ display_name: String
├─ dims: PresenceDims
├─ labels: Vec<StateLabel>
├─ attention: SceneAttention
└─ last_activity_at: i64

PresenceDims
├─ interruptible: bool
├─ category: SceneCategory         Working | Idle | Waiting | Stalled | Offline
├─ blocked_on: Option<BlockReason> UserReply | Approval | ExternalResult | Unknown
└─ since: i64

StateLabel
├─ key: String                     think_round / tool_call / waiting_reply …
├─ text: String                    展示文案
└─ at: i64

SceneStats
├─ agent_total / working / idle / waiting / stalled: u32
└─ queue_backlog: u64
```

`SceneProjection` 是 `SceneEvent` 的 fold 结果：v1 由 HTTP 返回当前值，v2 由 SSE 推送同一结构的增量，前端消费方不变。

> 现有可复用契约：[workspace_metrics.rs](src/handlers/system/workspace_metrics.rs)、[system.rs](common/src/api/system.rs#L584-L624)

### 3.2 分层与归属

| 层 | 归属 | 职责 | 不做什么 |
|----|------|------|----------|
| 契约 | `common/src/api/scene.rs` | DTO、枚举、字段文档 | 不放推导规则，不依赖 domain |
| handler | `src/handlers/system/scene_projection.rs` | 鉴权与 ctx、按维度取数、降级、DTO 组装 | 不写推导规则，不直接访问 DAO |
| domain | `src/service/domain/system/scene_projection.rs` | 纯推导：category / attention / 排序 / 截断 | 不做 IO，不认识 HTTP，不持有 DAL |
| dal / dao | 复用 message 等既有通道 | Waiting 判定所需的窗口查询 | 不为 scene 新建表、DAO 或仓储 |
| models | 不新增 | 投影是读模型，不落库 | 不建 PO，不加迁移 |

依赖方向：

```
common::api::scene  ◀── handler ──▶ system::scene_projection（纯函数）
                          │
                          └──只读──▶ runtime / message / hr / task 各域
```

domain 只依赖 common 与内部输入结构；handler 是唯一的取数与编排者，与 [workspace_metrics.rs](src/handlers/system/workspace_metrics.rs#L42-L90) 的既有模式一致。

### 3.3 领域设计：读模型，不是聚合根

`SceneProjection` 没有写路径、没有表、没有生命周期、没有业务身份——它是 CQRS 的查询侧，不是新领域实体。由此推出三条：

1. **不建仓储**。不为 scene 新增 DAO/DAL、迁移或 PO；数据一律从各域既有通道只读获得。
2. **规则只写一次**。`category_of` / `attention_of` / `rank` 三个判定函数同时服务 v1 的全量 `derive(input)` 与 v2 的增量 `apply(event)`，避免两套口径。
3. **关注集不落存储**。「关注谁」= 排序后截断的产物，不是一张表；pin 属于前端偏好。

内部输入结构定义在 domain，不进 common：

```
SceneInput
├─ now: i64
├─ seat_limit: u32
├─ facts: Vec<PresenceFacts>
└─ stats_input: StatsInput

PresenceFacts
├─ agent_id / display_name
├─ runtime_state: AgentRuntimeState
├─ state_started_at: i64
├─ current_message_id: Option<String>
├─ last_agent_message_at: Option<i64>
├─ last_user_message_at: Option<i64>
└─ is_task_message: bool
```

输出直接使用 `common::api::scene` 的 DTO，不另建同形领域模型（与 `query_think_traces` 直接返回 common 类型的既有做法一致）。

### 3.4 端点与取数编排

新增 `GET /api/v1/system/scene/projection`，handler 放 `src/handlers/system/scene_projection.rs`，编排方式沿用 [workspace_metrics.rs](src/handlers/system/workspace_metrics.rs#L42-L90) 的「本 handler 只做编排，各域提供查询」模式。

| 维度 | 数据源 | 现状 |
|------|--------|------|
| category / since | `runtime_domain().list_runtime_agents` 的内存态 | 已有 |
| labels（轮次、当前消息） | `AgentRuntimeInfo.state_started_at` / `current_message_id` / `think_runtime` | 已有 |
| Waiting | `MessageQuery` 一次窗口查询（近 24h、`to_role=User`），按 `(project_id, task_id)` 归并取最新，再看其后是否有 `from_role=User` | 需新增查询编排 |
| Stalled | Working 且 `now - state_started_at > 30min` | 计算 |
| 待审批 | 任务域 | P1 不做；NeedsYou 先只由 Waiting 产生，审批维度随任务域接口进入 P2 |
| 统计 | runtime 计数 + AOP 队列积压 | 已有 |

#### 作用域与降级

- **作用域必须复用各域既有收窄逻辑**：runtime 列表、消息窗口查询都要按 `ctx` 的用户/组织过滤，禁止在 scene 侧另写一套过滤——跨租户泄露是这个端点最容易出的错。
- 单维度失败按空值/0 呈现并记 error 日志，整体仍返回 200（与 metrics 端点同策略）。
- 每次请求最多 2 条 SQL（消息窗口查询 + 可选的关注集补全），runtime 遍历为内存操作。
- 目标 p95 < 150ms；`seat_limit` 只截断返回条数，不改变排序前的统计口径。
- `seq` 用进程内 `AtomicU64`；前端以 `generated_at` 判断新鲜度，不以 `seq` 判断。

## 四、前端方案

### 4.1 目录拆分

```
frontend/src/pages/workspace/
├─ mod.rs            页面壳：路由入口、Overview/Focusing 状态机
├─ source.rs         SceneSource、PollingDiffSource、SceneEvent
├─ presentation.rs   PresentationState（动画态、亮度相位、过渡进度）
├─ scene/
│   ├─ mod.rs        SceneCanvas：相机、拾取、LOD
│   └─ seats.rs      席位坐标常量表 + SeatMap（localStorage 持久化）
├─ hud/
│   └─ mod.rs        AttentionQueue / GlobalStats / SelectionCard
└─ focus/
    └─ mod.rs        对话景深层
```

原有 `pages/workspace.rs` 已删除，内容迁入 [workspace/mod.rs](frontend/src/pages/workspace/mod.rs)。路由声明不变（[pages/mod.rs](frontend/src/pages/mod.rs) 的 `pub mod workspace;` 自动指向新目录）。

### 4.2 数据入口

```
SceneSource
├─ snapshot() -> SceneProjectionResponse
└─ watch()    -> Stream<SceneEvent>

SceneEvent（v1 由轮询 diff 合成，语义与 v2 一致）
├─ EntityUpserted    { entity }
├─ CategoryChanged   { id, from, to, at }
├─ AttentionChanged  { id, from, to, reason, at }
└─ Activity          { id, at }
```

`PollingDiffSource` 以 5s 轮询 projection、30s 刷新统计，比较前后快照产出事件。组件层只订阅 `SceneEvent`，不感知轮询。

### 4.3 表现状态机

`PresentationState` 为每个实体维护：当前颜色、目标亮度、亮度相位、过渡进度。规则：

- `Activity` 只推进相位，不改布局；
- `CategoryChanged` 触发颜色过渡（~240ms）；
- `AttentionChanged` 触发边框/光晕；
- 无事件时相位衰减到静止帧——「不做装忙」在实现层就成立；
- 时间戳只读事件里的 `at`，不自行生成。

### 4.4 席位与镜头

- `SeatMap`：`agent_id → 0..7`，持久化在 localStorage；新实体取空闲席位，无空位时按「最久未互动」淡出，pin 的不移除；**已落座的实体永不换位**。
- LOD：`zoom < 0.8` 只画光点 + 状态色环；`0.8 ~ 1.4` 加名称；`> 1.4` 加 labels。
- 镜头：选中后计算目标 center/zoom，约 300ms 缓动，同时 `FocusLayer` 淡入；`Esc` 反向。全程不换路由。

### 4.5 景深层

`focus/mod.rs` 复用 [components/chat](frontend/src/components/chat) 的渲染组件与现有消息 API，v1 支持：查看会话、整段发送一条消息、一次确认动作。流式输入输出不在本期。

| 阶段 | 内容 | 产出 | 验收 | 主要风险 |

## 七、风险与约束

1. **共享组件隔离**：`graph_canvas.rs` 同时服务 HR 知识图谱，场景改造一律新建组件，禁止就地改布局与数据绑定。
2. **Waiting 误报**：把通知类消息算成「等你」会让注意力队列失效。口径收窄到任务类消息与被 @ 的消息，宁漏不刷屏。
3. **Stalled 误判**：长工具调用会被误判为卡住，阈值取 30 分钟且只降级为 Info。
4. **席位与排序冲突**：后端按 attention 排序只影响「尚未落座」的候选，已落座实体的席位不受排序变化影响。
5. **拆分期回归**：P0 不改行为，允许旧逻辑原样搬迁；行为变化全部推迟到 P2。
6. **数据陈旧**：轮询间隔内界面可能显示旧值，必须用 `generated_at` 显式提示「数据停在 X 分钟前」，不允许静默展示。
7. **越权读取**：投影跨多个域取数，任何一处漏掉 `ctx` 收窄都会造成跨租户泄露。取数只走各域已收窄的接口，scene 侧不另写过滤。

## 八、实施偏差（P0–P3 落地后回填）

| 计划 | 实际 | 原因 |
|------|------|------|
| `SceneSource.watch()` 产出 `SceneEvent`，表现层订阅事件 | `SceneSource` 只返回快照；`scene/canvas.rs` 的 `VisualBook` 比较前后快照推导颜色/高亮过渡 | 席位场只需要「现在长什么样」，快照差异足以驱动 240ms 过渡；事件流等 v2 SSE 再引入 |
| `focus/mod.rs` 作为对话景深层 | 复用既有 `dock.rs` 底部横幅（项目会话 / Agent 私聊 / 任务锚定已在其内） | 避免重复一套消息渲染与输入组件，且满足「对话不跳路由」 |
| 席位场复用通用 `CanvasScene` | 新建专用 `scene/canvas.rs` | 共享组件内部固定初始缩放与自带拖拽/缩放按钮，无法满足固定机位、LOD 与镜头缓动，同时不能改共享组件 |
| 席位聚焦改写路由（`?view=agent:<id>`） | 页面内 `focus_seat` 状态 + `effective_view`；Esc / 点空白退出 | 达到「30 秒内完成一次处理且全程不跳路由」；深链 `?view=agent:<id>` 仍兼容 |
| 图谱数据按视图预取 | 删除 `graph_*` 预取，仅 TaskDetail 拉一次任务归属 | 场景层只需要投影；任务归属仅用于解析对话上下文与默认 @ |

其它落地约束：

- 后端投影取数走两级缓存：DAO 实体缓存（`hr.agent_dao.entities`，按 id、60s）+ 业务名单缓存（`hr.agent_directory.ids`，`all_active`、30s），写路径主动失效、TTL 兜底；名单或实体取数失败时降级为空表（渲染回落 id）。等待窗口查询上限仍为 500 条（`collect_waiting`）。
- 画布尺寸随 `window.resize` 重新测量；离线/断流由 `scene_stale` 在顶栏显式提示。
