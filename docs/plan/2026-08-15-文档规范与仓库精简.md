## 一、目标（为什么做）

**核心问题**：docs 目录 11.8 万行文档中 >60% 是「实现快照型冗余」——执行期蓝图的 Task/Step checkbox、完整函数体代码块、`cargo/git` 命令参数快照。这些内容：
- 与实际代码严重漂移（完成 1 周后就过时），误导新读者
- 维护成本极高（改一行代码 → 要同时改 3 份文档快照）
- 噪音淹没真正有价值的架构决策

| 问题维度 | 解决方式 |
|---------|---------|
| 规范真空 | 在 [AGENTS.md §2.1](../../AGENTS.md#L92-L358) 增加 270 行强制执行章节，确立四象限处理流程 + 代码引用铁律 + 三套章节模板 |
| 代码 vs 文档信息边界不清 | 强制区分：「契约表达型」代码块（接口形状）可保留但必须附源码路径；「实现快照型」代码块（函数体/测试/命令）一律删除改用路径引导 |
| 执行期蓝图长期残留噪音 | 建立 docs/superpowers/ → plan/ 或 archive/ 的 7 天内强制精简归档流程 |
| 文档头缺失、定位不清、不知道何时该打开 | 所有手动维护文档补标准四件套文件头（🎯定位 / 状态含日期 / 查阅场景 / 关联文档） |

**收敛后效果**：活跃文档（排除 archive/ 封存区）从 ~11.6 万行 → **3.6 万行（-68.8%）**，所有手动维护文档 100% 合规，零漂移风险。

### 关键边界 / 行为红线（AGENTS §2.1 强制执行，回归必保）

1. **代码引用铁律**：契约型代码块必须附源码路径；快照型代码块必须删除换路径。任何实现快照（函数体/测试/命令/Task-Step checkbox 正文）**禁止出现在** `design/` `plan/` `README` `ARCHITECTURE` 文档中（§2.1.2）
2. **ARCHITECTURE.md 零代码块**：权威总纲不允许任何代码块（包括契约型），纯概念和关系；ASCII 架构图除外（§2.1.3 + Task 8 落地）
3. **完成后强制精简归档**：`docs/superpowers/plans/*.md` 功能完成 7 天内必须二选一处理（精简迁 plan/ 或删或移 archive），禁止长期留存（§2.1.3）
4. **文件头四件套强制**：所有手动维护文档第一屏必须含「🎯定位 + 状态(含日期) + 查阅场景 + 关联文档」，缺任何一项视为不合规（§2.1.1）
5. **文档与代码双源禁止**：同一个信息（字段定义、接口签名、流程步骤）不允许在文档和代码中各写一份；文档只写「为什么 + 边界 + 索引 + 路径」，字段细节永远点链接跳代码读真源

## 四、后续处置流程速查表（新增/完成功能时必走）

### 4.1 新增文档时的定位选择（避免放错目录）

| 你写的内容属于 | 放哪个目录 | 用哪个模板 | 第一屏必须有 |
|--------------|-----------|-----------|-------------|
| 为什么这样设计（设计动机、决策表、边界、扩展模式） | `docs/design/<中文功能名>_design.md` | 模板 A（5 章） | 🎯定位 + 状态「定稿或vX.Y」+ 查阅场景 + 关联文档 |
| 某功能的规划、架构思路 + 落地完成后的结果快照（验收数据） | `docs/plan/<中文功能名>.md` | 模板 B（7 章） | 🎯定位「规划与落地结果快照」+ 状态「完成（日期）/进行中」+ 查阅场景 + 关联文档 |
| writing-plans skill 产生的**执行期蓝图**（Task/Step checkbox + 代码块/命令细节） | `docs/superpowers/plans/YYYY-MM-DD-<功能英文名>.md` | writing-plans 标准头（含 REQUIRED SUB-SKILL） | 该标记只允许出现在本目录下的进行中文件中 |
| 三件套 Spec（开发期间的 spec/checklist/tasks 蓝图） | `docs/superpowers/specs/<功能名>/{spec,checklist,tasks}.md` | brainstorming/spec 三件套标准 | 同上，仅开发期间允许 |
| 被新方案取代的历史方案快照、纯执行期无参考价值的蓝图 | `docs/archive/*.md` 或 `docs/archive/superpowers-archive/` | 模板 C（归档说明头 + 原文不动） | 📦归档标记（取代原因 + 保留理由 + 生效方案引用） |

## 七、后续扩展路径（新增文档 / 新增功能完成后 4 步模板）

> **核心不变量**：文档定位永远先选目录（design/plan/superpowers/archive 四象限），然后套对应模板；代码细节永远点链接读真源；superpowers 下的文档永远是临时的，功能完成 7 天内必须处理。

1. **第一步：定位选目录 + 选模板**（功能开发启动前写文档时）
   - 如果是设计讨论稿（决策记录）→ 选 `docs/design/<中文功能名>_design.md` + 模板 A
   - 如果是功能规划 + 落地结果快照 → 选 `docs/plan/<中文功能名>.md` + 模板 B
   - 如果只是给子代理做执行蓝图（含代码/命令细节）→ 选 `docs/superpowers/plans/YYYY-MM-DD-功能英文名.md` + writing-plans skill 输出；**注意该文件一定会在完成后被精简/删除**
   - 参考：[AGENTS.md §2.1.3 四象限角色/允许内容边界表](../../AGENTS.md#L218-L258)

2. **第二步：文档写作过程中严格遵守代码引用铁律**
   - 想贴 trait/struct/enum 字段列表（无实现体）→ 贴契约型代码块 + 紧后一行附 `> 当前实现：[file.rs::Xxx](file:///绝对路径#Lx-Ly)`
   - 想贴完整函数/测试/命令/循环 → **不贴**，改成一句话路径引导：`> 实现见 [file.rs::function_name](file:///绝对路径#Lx-Ly)`
   - 想画 ASCII 分层图/目录树 → 直接贴，无需加路径（纯图示自解释）
   - 参考：[AGENTS.md §2.1.2 代码引用铁律判定表](../../AGENTS.md#L132-L184)

   - 禁止「完成后把 superpowers 下的执行蓝图当长期文档保留」
