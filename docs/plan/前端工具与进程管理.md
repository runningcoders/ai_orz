# HTTP 工具表单 + 进程管理页面 + ChatSidePanel 工具调用 Tab

## 已定决策

- HTTP 方法白名单维持 GET/POST（表单下拉仅两项，PUT/PATCH/DELETE 另行安排）
- 进程列表双露为 `shell_list` LLM 工具（与 shell_status/shell_kill 凑齐三件套，复用 Agent scope 过滤）
- 工具调用 Tab 两种对话模式都加（项目对话按 project_id 查，默认对话按前台 agent_id 查）
- 进程详情采用「共享组件 + Modal 弹窗」形态，不建独立路由页——列表页与聊天侧栏弹窗共用同一组件

## 后端：进程列表接口（shell_list 双露）

- `common/src/api/system.rs`：新增 `ListProcessesRequest`（空参，scope 由 ctx 决定）与 `ListProcessesResponse { processes: Vec<ProcessInfo> }`；`ProcessInfo { pid, call_id, tool_id, agent_id, command, working_dir, background, started_at, alive, exit_code, log_path }`（alive 由返回前 `refresh` 探活得出）
- `src/handlers/system/process/shell_list.rs`：新增，`#[register_handler_tool(id = "shell_list", tags = "shell")]` + `#[generate_http_handler]`，内部调 `system::domain().process_manager().list_processes(ctx)` 并逐条 refresh 转 `ProcessInfo`；`mod.rs` 注册模块
- `src/router.rs`：system nest 新增 `GET /processes` → `shell_list_handler`（排在 `/processes/{pid}` 前避免路由遮蔽）
- 测试：shell_list handler 单测（用户 ctx 全量 / agent ctx 仅见自己，仿 tool_call_entry_test.rs 的 init 模式）

## 前端一：HTTP 工具创建表单

- `frontend/src/pages/finance/tools.rs`（288 行，现无创建入口）：页头加「+ 创建 HTTP 工具」按钮，弹出 `components::modal::Modal` 表单
- 表单字段对齐 `CreateToolRequest` + `HttpToolConfig`（src/pkg/tool_registry/http.rs:43）：
  - 基础：name（必填）、description、tags（逗号分隔）
  - 配置：method 下拉（GET/POST）、url 模板（必填）、headers/query/body 三个可选 JSON 文本域（提交前 `serde_json` 解析校验）、timeout_ms、response_max_bytes、allowed_status_codes、response_json_pointer、allowed_domains/blocked_domains（逗号分隔）、allow_local_network 复选框
  - parameters_schema 可选 JSON 文本域
- 提交调现有 `create_tool`（frontend/src/api/finance.rs:134，已封装未使用），protocol 固定 `Http`；成功后 toast + 刷新列表，校验失败行内提示
- 前端纯函数测试：JSON 文本域解析校验、表单必填校验（拆为可测的 validate 函数）

## 前端二：进程管理页面

- `frontend/src/api/system.rs`：新增 `list_processes()`（GET /api/v1/system/processes）、`get_process_status(pid, tail_lines)`（GET /processes/{pid}，复用 `ShellStatusResponse`）、`kill_process(pid)`（POST /processes/{pid}/kill）

## 假设与边界

- 进程详情不做独立路由页（Modal 即详情，两处复用）
- HTTP 工具表单不含编辑已有工具（创建为主，编辑另行安排）
- 工具调用 Tab 数据依赖 JSONL 扫描查询，limit 30 控制开销；进程列表为内存态，服务重启后为空属预期
- 前端不新增路由级代码分割，按现有 pages 目录组织
