## 一、适配目标（为什么做）

当前前端（Dioxus 0.7 WASM）针对桌面端宽屏设计，375px ~ 768px 移动端宽度下存在 8 类可用性阻塞：

| 问题维度 | 现状痛点 | 解决方式 |
|---------|---------|---------|
| (a) Navbar 溢出 | 5+ 一级菜 + 4 下拉 + 用户菜单，375px 下横向挤压不可点 | 移动端切换汉堡菜单 + 抽屉式垂直导航（use_breakpoint Hook 驱动） |
| (b) Chat 双栏挤压 | sidebar 固定 320px + main 并列，移动端无法共存 | 移动端 sidebar 改为滑入/滑出覆盖层，单栏切换 + 返回按钮 |
| (c) 数据表格横滚 | 17 处 `.table` 小屏大量横滚，关键列不可见 | `<640px` thead 隐藏，每行转卡片（`td::before` 显示 `data-label`） |
| (d) 看板固定列宽 | kanban-column 固定 300px，水平滑动体验差 | 移动端纵向堆叠，kanban-column 100% 宽 |
| (e) Modal/Toast 越界 | `.modal-content` 固定 500px 宽；Toast 右上角窄框 | `<640px` Modal 全屏化（100vw/100vh/圆角0）；Toast 横向占满（左右 12px） |
| (f) 网格降列 | overview-stats 4 列、detail-grid auto-fit 220px，375px 下挤压不可读 | ≤768px 降列（2 列 / 1 列多级断点） |
| (g) 触摸交互缺陷 | 按钮点击区域 <32px；hover 才显示的操作（message-actions）不可达；iOS 输入框 <16px 自动放大 | 按钮最小 40/44px；hover 降级为始终可见；输入框 font-size ≥ 16px |
| (h) 全局触摸优化 | 点击蓝色高亮（tap highlight）、触摸手势冲突 | `-webkit-tap-highlight-color: transparent` 全局；touch-action 适当设置 |

**收敛后效果**：所有页面在 375px 及以上宽度可用；768px 以上桌面端视觉与交互完全不变（双端兼容红线，CSS @media 严格分离，零回归）。

## 二、架构思路（怎么做）

CSS 优先（@media 断点变量统一），仅必要时用 `use_breakpoint` Hook 切换组件结构；P0 → P1 → P2 → P3 优先级推进：

```
P0 核心阻塞（移动端可用前提）
├─ CSS 基础设施：:root 断点变量 + 全局移动端规则（触摸/字号/padding）
├─ use_breakpoint Hook：window.matchMedia("(max-width:768px)") 监听
├─ Navbar：is_mobile() 切换 ── 汉堡按钮 + 抽屉 + 遮罩 + 路由跳转后自动关
└─ Chat：is_mobile() 切换 ── sidebar 覆盖层滑入滑出 + 返回按钮 + 单栏切换

P1 管理页可用性
├─ 17 处表格：CSS 卡片化 + <td data-label="字段名"> 属性补充
├─ Modal：CSS 全屏化（<640px）+ Toast 位置适配（横向占满）
└─ 网格：overview-stats/detail-grid/stats-grid 等断点降列

P2 完善体验
├─ 看板纵向堆叠、筛选行/卡片头部纵向布局、page-header 允许换行
└─ 触摸细节（按钮最小高度、输入框 16px、hover 降级、iOS 防放大）

P3 质量保障
├─ 桌面端三档回归：768px（分界点）/ 1024px / 1440px，21 个页面逐页
├─ 移动端三档验证：375px iPhone SE / 390px iPhone 14 / 768px iPad
└─ 真机 iOS Safari + Android Chrome 核心交互（Chat SSE/文件上传/表单）
```

**统一断点（:root CSS 变量，所有 @media 不硬编码）**：
- `--breakpoint-sm: 640px`（表格卡片化 / Modal 全屏化分界）
- `--breakpoint-md: 768px`（移动/桌面主分界）
- `--breakpoint-lg: 1024px`（次要）

**关键边界（双端兼容红线，违反即回滚）**：
1. 桌面端（≥768px）所有现有功能与视觉完全一致，不允许回归
2. 桌面端任意交互（点击/表单/Modal/SSE/上传）失效 = P0 阻塞
3. 移动端核心交互（Navbar 抽屉 / Chat 单栏 / 表格卡片）不可用 = P0 阻塞
4. `cargo check` 出现 warning 或错误 = 阻塞
5. 现有测试用例失败 = 阻塞

## 四、分发速查表（新增页面移动端适配 4 步模板）

新增一个含表格的页面（如「HR 考核管理」）时，移动端适配 4 步零遗漏：

### 4.1 表格卡片化（必做，若有 .table）

| 步骤 | 操作 | 参考文件 |
|-----|------|---------|
| 1 | 每个 `<td>` 补 `data-label: "字段名"`（与 `<th>` 文本一致） | [finance/message_channels.rs](../../frontend/src/pages/finance/message_channels.rs)（mobile-adaptation 落地后参考） |
| 2 | 如表格含操作列按钮，整行排布；移动端按钮宽度自适应（不要固定 px） | [hr/agents.rs](../../frontend/src/pages/hr/agents.rs) |

### 4.2 响应式网格（必做，若有多列 .grid）

| 步骤 | 操作 | 断点参考 |
|-----|------|---------|
| 1 | 检查是否使用了 --breakpoint 变量的已有 @media 类（overview-stats/detail-grid/stats-grid 等已定义）；是则直接套用 | index.html Mobile Adaptation 区块 §网格响应式 |
| 2 | 新增自定义网格 → 统一走 @media (max-width: 768px) 降为 1~2 列；≤480px 再降 | 同 §P1 Task 7 |

### 4.3 Navbar / Chat 无需改造（全局生效）

只要页面沿用 `AppLayout` 包裹 + 内置 `MessageChat` 组件，移动端自动切汉堡菜单与 Chat 单栏。

### 4.4 最终双端回归（必做）

- 桌面端 1024px：视觉与适配前完全一致 → 通过
- 移动端 375px：无横向滚动溢出、表格转卡片、按钮可点、表单可填 → 通过

## 七、后续扩展路径（移动端深化 4 步模板）

**核心不变量**：断点统一（--breakpoint-sm/md/lg）；CSS @media 优先，仅组件结构切换用 use_breakpoint；桌面端零回归红线。

1. **PWA 离线包与安装**：`frontend/index.html` 追加 manifest.json + service worker；Cargo.toml 加 pwa 相关依赖；桌面端安装提示走现有逻辑
2. **移动端点钞手势**（左滑删除消息等）：新增 `use_touch_gesture` Hook（基于 touchstart/touchend）；与现有 click 事件共存，桌面端不挂载
3. **性能优化（WASM 包体）**：移动 WASM 首屏慢问题独立处理；dioxus 组件 lazy 加载 + wasm-opt 体积裁剪
4. **新增原生能力（相机/相册/定位）**：web-sys MediaDevices / Geolocation API 封装新 Hook；use_breakpoint 内仅移动端启用权限申请 UI
