## 一、目标（为什么做）

原 awaken 和 sleep_and_settle 流程无统一业务上下文注入机制，沉睡沉淀 Prompt 模板散落在 settle_memory.rs，且沉淀模式下 Agent 仍可能触发消息类工具造成循环唤醒，存在以下问题：

| 问题维度 | 解决方式 |
|---------|---------|
| (a) awaken 和 sleep_and_settle 方法签名不统一，扩参需多处改动 | 新增 `ThinkingOptions` 统一选项结构体（scene + project + task + user_profile），两方法都接收此参数，Builder 模式构造 |
| (b) 消息携带 project_id/task_id 时 Prompt 无业务上下文，Agent 对场景感知弱 | Project/Task 实体新增 `to_prompt_summary()` 方法；awaken 流程 MessageConsumer 查询实体并注入 ThinkingOptions；PromptBuilder 新增 project_context/task_context 方法 |
| (c) 沉睡沉淀 Prompt 约束模板散落在 settle_memory.rs 的 format!，与 build() 不对称 | PromptBuilder 新增 `build_sleep_prompt(pending_memories_summary)` 方法，沉淀约束章节内聚在 builder 内，与 build() 对称复用挂载链路 |
| (d) 沉淀模式下 Agent 仍可加载和调用消息类工具，可能触发异步唤醒自己 | 双层工具过滤机制：① wake_agent_brain 中 Auto 工具按场景过滤（Settle 只保留 neural/memory tag）② sleep_and_settle 中 Manual 工具和 skill 也按同规则过滤 |
| (e) sleep_and_settle 传入 settle_prompt 完整字符串含约束模板（内外职责耦合） | settle_prompt 参数改为 pending_memories_summary（仅短期记忆编号摘要），完整 Prompt 由 builder.build_sleep_prompt() 内聚生成 |

**收敛后效果**：awaken 与 sleep_and_settle 通过统一 ThinkingOptions 传递上下文，消息关联的项目/任务实体自动注入 Prompt；sleep_and_settle 双层过滤保证沉淀模式只接触记忆类工具，约束模板从 handler 层内聚到 builder 层，Prompt 拼装公共逻辑（上下文区块 + 工具技能区块）通过私有方法提取供 build() 和 build_sleep_prompt() 对称复用。

## 二、架构思路（怎么做的）

统一选项 + 场景分发 + Prompt 拼装内聚 + 双层工具过滤：

```
思考场景枚举和统一选项（Domain 入口）
  ThinkingScene 枚举：Awaken（响应外部消息）/ Settle（沉淀记忆）
    └─ is_tool_allowed(tags)：Settle 场景只允许 tags 含 "neural" 或 "memory"
  ThinkingOptions 结构体（Builder 模式）：
    ├─ scene: ThinkingScene（决定工具过滤行为）
    ├─ project: Option<Project>（消息关联的项目实体）
    ├─ task: Option<Task>（消息关联的任务实体）
    └─ user_profile: Option<UserPo>（预留扩展）
    便捷构造：ThinkingOptions::new() 默认 Awaken
             ThinkingOptions::for_scene(Settle)
             .with_project(project) / .with_task(task)
  │
  ├─► Domain 签名改造
  │   wake_agent_brain(ctx, agent, scene: ThinkingScene)
  │   awaken(ctx, agent, message, options: &ThinkingOptions)
  │   sleep_and_settle(ctx, agent, pending_memories_summary, options: &ThinkingOptions)
  │
  ▼
入口层上下文注入（Adapter 层）
  MessageConsumer::handle_agent_message：
    wake_agent_brain(scene = Awaken)
    → 查询 message.project_id → project_domain.get → 注入 options.project
    → 查询 message.task_id → project_domain.task().get_task → 注入 options.task
    → awaken(options)
  settle_memory handler：
    wake_agent_brain(scene = Settle)
    → build_pending_memories_summary()（只返回编号摘要，不含约束模板）
    → sleep_and_settle(summary, options = for_scene(Settle))
  │
  ▼
PromptBuilder 扩展（PO 模型 + DAL 实现）
  trait PromptBuilder 新增 3 个方法：
    fn project_context(&mut self, project: &Project)
    fn task_context(&mut self, task: &Task)
    fn build_sleep_prompt(&self, pending_memories_summary: &str) -> String
      （默认实现回退 build()，仅 DefaultPromptBuilder 真正实现沉淀语义）
  Project/Task 模型新增行为：
    Project::to_prompt_summary() → 【项目上下文】区块字符串
    Task::to_prompt_summary() → 【任务上下文】区块字符串
  DefaultPromptBuilder（DAL 层）改造：
    结构体新增 project_context / task_context 字段
    提取两个私有公共方法供 build() / build_sleep_prompt() 复用：
      ① build_tools_and_skills_sections() → 神经工具/技能 + 常用工具/必加载技能 四个区块
      ② build_common_context_sections() → 用户画像 + 项目上下文 + 任务上下文（有值即拼装）
    build_sleep_prompt() 实现：
      保留 system_prompt + 工具技能区块 + 通用上下文（含画像/项目/任务）+ 历史对话 + trace_id
      跳过 tool_failures（沉淀不调外部工具）和 current_message（沉淀无用户消息）
      内聚沉淀约束章节（不发消息、只用记忆工具、内循环语义）
      + 待沉淀短期记忆摘要（编号列表）
      + 6 步任务步骤（归纳→查图谱→创建/更新节点→建关系→评估共享→标记完成）
      + 5 条认知要点（图谱是活的、记抽象不记细节、迭代不覆盖、published 跨 Agent 桥接）
  │
  ▼
双层工具过滤机制（Settle 场景）
  ① Auto 工具过滤（wake_agent_brain 中 Rig 注册时）：
     match scene {
       Awaken => 全部 Auto 工具注册到 Rig
       Settle => 只保留 tags 含 "neural" 或 "memory" 的 Auto 工具
     }
  ② Manual 工具 + skill 过滤（sleep_and_settle 中 Prompt 展示时）：
     skill_pos 只保留 tags 含 neural/memory 的
     all_tools（Manual）也只保留 tags 含 neural/memory 的
  → 两层都过滤，确保沉淀模式下 Agent 无论 function calling 还是手动调用，都只能接触记忆类工具
```

**关键边界（行为红线，回归必保）**：
1. **ThinkingScene::is_tool_allowed 判定规则**：仅 tags 含 "neural" 或 "memory" 字符串时 Settle 场景可用（记忆认知技能 tags = ["neural", "memory"]）；Awaken 场景全部可用
2. **enrich_ctx 链路不变**：caller_type 扩展已约定入口设置，本改造不涉及 enrich_ctx，project/task 上下文仅在 options 中通过 Consumer 查询后显式注入
3. **沉淀 Prompt 内容保留项**：user_profile（认知是具身的，Agent 需知道自己是谁）+ project_context / task_context（场景化沉淀：在什么项目/任务下总结的经验，沉淀出的知识自带场景标签），仅跳过 tool_failures 和 current_message
4. **沉淀约束红线（build_sleep_prompt 中明确写入）**：①不要发送消息②不要调用消息类工具③只使用记忆类工具④这是内循环（与自己的记忆对话，不是与外部世界交互）；严禁触发消息流程导致异步唤醒自己
5. **sleep_and_settle 参数语义**：pending_memories_summary 参数仅为短期记忆编号摘要字符串（编号列表格式），完整约束模板由 builder 内聚，handler 层不再 format! 完整 Prompt
