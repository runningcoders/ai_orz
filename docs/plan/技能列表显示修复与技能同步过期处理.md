## 二、架构思路

严格单向分层，变更沿「common DTO 单一事实源 → DAO Query Struct → DAO SQLite WHERE → DAL 业务语义 → Handler 透传 → 前端 UI」顺序传递，无反向依赖：

```
common::api::skill            SkillQueryRequest / SearchSkillsRequest 加 author_type
        ↓ (DTO → Query 映射，Handlers 只做字段透传，不含业务)
service::dao::skill::SkillQuery  加 author_type 字段；has_parent 改用 = '' / != ''
        ↓ (DAO 层只做 SQL 过滤，不含策略决策)
service::dao::skill::sqlite     WHERE 段：author_type AND parent_skill_id 空串比较
        ↓
service::dal::skill             list_for_agent 加 exclude_status=Expired；
                                install_to_agent 找到任意副本(含Expired)→原地字节级文件
                                diff 覆盖+状态重置+元数据更新；否则新建
        ↓
service::domain::hr::skill      引入 ensure_skill_access 统一守卫：
                                Admin Bypass → 作者本人 → Agent 创建者 → Forbidden
                                替换 list/get_content/update_content 内联检查
                                并补 update_skill / delete_skill 入口守卫
        ↓ (前端严格单向，只读取 common DTO)
frontend::pages::hr::skills     filter_author_type signal 接入；创建者列渲染
```

T3 原地更新的决策矩阵：
- 查到 (author_id=agent, parent_skill_id=source) 任意状态副本 → 原地
  - 状态变更（含 Expired→Draft）标记 is_status_change
  - 元数据变更（name/description/tags/category/version）标记 is_meta_change
  - 每个源文件字节 vs 副本文件字节比对，不匹配即 write_file_bytes 覆盖并置 any_file_changed
  - 三者任一为真 → UPDATE skill PO + 文件记录同步
- 查不到副本 → 新建（原 `create_skill_for_agent_from` 分支）

T6 权限矩阵（4 象限）：
| 角色 \ 技能归属 | User(本人) | Agent(我创建) | Agent(他人创建) | Admin/SuperAdmin |
|---|---|---|---|---|
| Member(我) | ✅ | ✅ | ❌ Forbidden | - |
| SuperAdmin/Admin | ✅ | ✅ | ✅ (Bypass) | ✅ |

## 六、执行结果摘要

6/6 任务全部落地并通过对应测试矩阵。Skill DAL 17/17、Skill Domain 10/10 单测 100% 通过；双端 Clippy `-D warnings` 零告警。附带顺手修复：

- `update_skill` / `delete_skill` Domain 入口原本没有资源级访问控制，普通 Member 可通过 HTTP 接口篡改/删除他人或 Agent 名下任意技能，现已通过 `ensure_skill_access` 守卫闭环。
- `ensure_skill_access` 内嵌套 if 经 Clippy `collapsible_if` 报错，改用 Rust 1.80+ let-chain（`&& let Some(agent) = ... && agent.po.created_by == uid`）保持可读性且零警告。

## 七、后续扩展路径

1. **权限模型升级**：当前 ensure_skill_access 用硬编码的 Admin bypass + 作者 + Agent 创建者三层，下一步可抽为统一 `ResourceGuard<Skill>` Trait，与 Project/Task/Agent 等其它资源共用同一判定引擎（参考已有并查集 UserRole）。
2. **install_to_agent 字节级比对**：目前用内存 `==` 对比 whole-file bytes，技能文件上限 2MB 可接受；如未来出现大文件附件，可升级为 BLAKE3/xxhash 预计算 hash 并持久化到 skill_file 表，减少 IO。
3. **T4 author_type 前端联动详情回跳**：skills 页点击创建者 Agent 行，可直接路由到 `/hr/agents/:id` 详情，当前末 6 位 ID 仅展示未接路由。
4. **Docs 补齐**：本次变更范围横跨 common/DAO/DAL/Domain/Handler/Frontend 六层但无对应 design 文档，建议在 `docs/design/skill_query_and_install_policy.md` 落地 5 章节决策快照（含 has_parent 空串 bug 根因、install 幂等决策表、权限矩阵）。
5. **计划归档**：按 AGENTS.md 归档规则，本文档在确认补写 design 后可整体移动到 `docs/archive/plan-archive/` 并加 Template C 归档头，同时通知 wiki-maintainer 重定向所有引用。
