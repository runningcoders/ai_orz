## 一、目标

1. 统一 3 种内容源（文本 / HTTPS URL / 附件散文件）进单一子结构 SkillContentInput{content,url,files}，并带 6 纯方法前后端双接口复用。
2. 直接删旧字段（CreateSkillRequest.content+initial_files、UpdateSkillRequest.content+files），不做 Compat DTO / From 转换 / flatten 兼容层——测试阶段零兼容债。
3. Create/Update 内容源处理 100% 共享：Domain 私有 apply_content_sources 4 原子流水线（DirectText / RemoteZip / Attachments / FrontmatterMerge）。
4. Phase 1 前端同步改造，不延后：新建 SkillForm 共用组件 = SkillMetaEditor + SkillContentInputEditor 3 Tab；列表页 Create Modal 与详情页 Update Modal 全替换；净减约 180 行旧表单代码；改 skill.md 不再走独立 update_skill_file_content 接口。
5. URL 抓取与 Seed 共用实现：抽出 pkg/fetch_remote_content.rs SSOT。

---

## 二、架构思路

**4 层对称：**
- **common DTO 层**：SkillContentInput + 6 方法；Create/Update 双请求体删旧字段换 content_input。
- **Adapter Handler 层**：create/update 两 handler 对称；classify 预检 + HTTPS/unique_target 校验 + 复用现有 update_skill 附件读取流程（finance_domain().get_attachment include_content=true → bytes）+ URL pkg fetch → 组装 CreateSkillParams / UpdateSkillParams → domain。
- **Domain 层**：SkillManage.create_skill 签名换 CreateSkillParams；11 处老调用点走兼容（file_writes = Skill.files[i].content）；私有 apply_content_sources 4 原子（Phase 1 原子 1/3 完整，原子 2/4 空骨架留 P1-4 填）。
- **前端 UI 层**：SkillForm 共用组件（mode=Create/Update{skill_id} + initial_value + on_submit Callback）；内嵌 SkillMetaEditor + SkillContentInputEditor（Tab0 文本 / Tab1 URL / Tab2 附件装配 Table 复用 chat.rs upload_attachment）。

技术栈：Rust (Axum + sqlx 0.8 + SQLite STRICT) · Dioxus 0.7 (WASM) · Tailwind v4 + DaisyUI v5 · Reqwest。
