## 一、目标（为什么做）

用户画像在唤醒链路中仅包含基础信息（显示名/邮箱/角色），缺失用户的沟通风格、工作习惯、内容偏好等个性化维度；偏好来源应区分「用户本人声明」与「Agent 对话观察推断」，两者权重与写入权限严格隔离。

| 问题维度 | 解决方式 |
|---------|---------|
| 偏好无结构化存储位，散落在技能隐式引导中 | `users` 表新增 `preferences TEXT` 字段（Markdown/纯文本，用户自述权威源）；知识图谱侧沉淀推断节点 |
| Agent 工具可能越权写入 `users.preferences`（update_current_user 已注册为 Agent 工具） | handler 内安全守卫：`ctx.agent_id` 为 Some（Agent 上下文）时忽略 preferences 字段，仅允许真人 HTTP 会话修改 |
| 偏好节点检索无统一 tag，跨 Agent 共享不明确 | 统一打 `user_preference` + `published` tag，node_name 固定格式 `用户偏好-{display_name}（{user_id}）`，user_id 放名称不进 tag |
| 唤醒 Prompt 无画像注入点（ThinkingOptions.user_profile 预留字段无人赋值） | consumer/message 构建 ThinkingOptions 时，按 from_id 查 UserPo 并 `with_user_profile()` 注入；PromptBuilder 自动拼装【用户画像】区块 |
| 偏好内容渲染格式不统一（编辑态/展示态/节点详情三套） | 展示态一律复用 `MarkdownRenderer`，编辑态用 textarea（Markdown 书写） |

**收敛后效果**：偏好声明 > 推断的优先级明确；Agent 无法篡改用户自述；唤醒 Prompt 自动携带画像 = 基础信息 + 自述偏好；图谱侧偏好通过技能引导 Agent 主动 `query_memory(tags=["user_preference"])` 检索，服务端暂不注入避免引入截断策略复杂度。

## 二、架构思路（怎么做的）

双源双路径，写入权限严格隔离，注入链路服务端自动拼装：

```
【用户自述源】权重=高（声明>推断）
  用户 HTTP 修改 profile
    → handler/user/profile/update_current_user
      → 守卫：ctx.agent_id=Some → 忽略 preferences
      → 守卫通过 → UserDal.update → DB users.preferences

【图谱推断源】权重=低（可演进可修正）
  Agent 对话观察到偏好
    → TEMPLATE_MEMORY_COGNITION 技能引导：短期记忆先记→沉淀建知识节点
      → node: tags=[user_preference, published] + node_type=fact
      → node_name: 用户偏好-{display_name}（{user_id}）
      → node_description: Markdown（内容+观察依据）
    → TEMPLATE_COMMUNICATION 技能：回复风格优先遵循已有偏好

【唤醒注入】(Agent 无感知)
  consumer/message 构建 ThinkingOptions
    → from_id=User 时查 UserPo → with_user_profile(user)
      → PromptBuilder 拼【用户画像】= 基础信息 + preferences 非空行
```

**关键边界（行为红线，回归必保）**：
1. **声明 > 推断**：`users.preferences` 仅用户本人通过 HTTP 会话可写；Agent 调用 `update_current_user` 时 preferences 字段必须被静默忽略，绝不写入 DB
2. `user_preference` 图谱节点必须带 `published` tag（跨 Agent 共享语义）；同一用户优先 `update_memory` 更新既有节点，不重复建新节点
3. 唤醒链路注入仅取 `users.preferences`（自述源）；图谱侧偏好暂靠 Agent 工具主动检索，服务端不自动拼入避免引入检索开销与截断策略
4. `preferences` 为空时 Prompt 【用户画像】区块不渲染偏好行，保持 Prompt 干净（空字符串不占 token）
5. `UpdateUserRequest`（管理员接口）不加 preferences 字段，维持管理员权限与用户自述的边界分离

## 七、后续扩展路径（4 步模板）

> **核心不变量**：Agent 不写 `users.preferences`（红线 #1）、声明>推断权重（红线 #2）、安全守卫入口固定。

1. **服务端图谱偏好自动注入**：如后续唤醒链路要自动拼入图谱侧节点，在 [consumer/message.rs](src/consumer/message.rs#L326-L328) 追加 `query_memory(tags=["user_preference"])` 调用，结果经截断策略后拼入 user_profile（注意 token 成本）
2. **偏好采纳晋升按钮**：记忆搜索页按 `tags=["user_preference"]` 检索结果追加「采纳为自述偏好」按钮，调用 update_current_user（前置守卫自动放行，仅人类用户可点）——入口参考 [frontend/src/pages/hr/memory_search.rs](frontend/src/pages/hr/memory_search.rs)
3. **偏好字段结构化**：单字段 Markdown → JSON schema 时，改 UserPo + DAO SQL + common DTO + 前端表单校验（§四 4.2）
4. **多组织偏好维度**：如需组织级偏好（不挂用户），新增 knowledge node 命名规范 + tag `org_preference`，消费端按 org_id 过滤 node_name 前缀检索
