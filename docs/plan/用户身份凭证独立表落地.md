> 🎯 **定位**：② 落地快照 — 用户身份凭证从 users.identity_credentials JSON 列迁移到独立表 user_credentials 的实现路径与验收基准

## 一、目标

| 问题 | 解决方式 |
|------|---------|
| JSON 列读-改-写整列覆盖存在并发丢更新（lost update） | 独立表 `user_credentials` 行级 CRUD，天然消解 |
| 三类型默认槽位（default_credential_id 等）致 JSON 结构膨胀 | 单 `is_default` 标记，作用域由 `visibility` 派生（private=个人默认 / public=组织默认），双部分唯一索引兜底 |
| kind/visibility 语义弱（i32 数字不可读） | TEXT 字符串枚举（`lark_app`/`private` 等），代码侧 Rust 枚举 + sqlx::Type 派生（新代码优化规范首例尝试） |
| 凭证行与用户行耦合（UserDao 持有凭证解析职责） | 新增 `UserCredentialDao`，消费侧（lark/message_channel DAL）直接依赖凭证 DAO，不再经 UserDao |
| 个人默认缺位时解析链语义不明确 | `find_default` 作用域优先链：个人默认 > 个人其他 > 组织默认 > 组织其他 public |

**收敛后效果**：凭证成为一等公民实体（独立表 + 独立 DAO + 行级生命周期），为后续 tags 打标、组织共享凭据、Agent 专属绑定预留干净扩展面。

## 二、架构思路

```
users 表（删除 identity_credentials JSON 列）
    ↕ 行级读写（取代 JSON 整列覆盖）
user_credentials 表（一凭证一行：kind TEXT 枚举 / visibility / is_default / detail JSON 加密）
    ↑ UserCredentialDao（新）            ↑ UserCredentialQuery（分页 + 过滤复用 push_query_filters）
    │                                        │
UserDal（凭证行级方法原位替换）        消费侧直接依赖：
    │                                    - lark DAL（resolve_credentials_for_user）
    │                                    - message_channel DAL（渠道凭证解析）
    ▼
IdentityCredentialManage Domain（行级 CRUD + set_default 权限门控：
    private 默认仅 owner 本人 / public 默认需 Admin+）
    ▲
finance handlers（lark/github/tavily 三组 CRUD，统一空检查模式）
```

**关键边界**：
- 凭据表零外部使用方引用（Agent/工具/渠道绑定归使用方实体，如 channel config 的 lark_credential_id）
- secret 类字段加密仍发生在 Domain 编排层（detail 密封边界不变），DAO 不感知字段结构
- QueryBuilder 运行时查询用纯列名（`as "col: Type"` 标注语法仅 query! 宏有效）
- 明文直通兼容保留（decrypt 对未加密值原样返回）

## 四、分发点速查表

| 改动点 | 入口 | 要点 |
|--------|------|------|
| 表迁移 | migrations/20260819000000_user_credentials.sql | STRICT 表 + 双部分唯一索引（private: user_id+kind / public: org_id+kind）+ json_each 存量搬迁幂等 |
| 字符串枚举 | common/src/models/identity_credentials.rs | `#[serde(rename_all = "snake_case")]` + `sqlx(rename_all = "snake_case")`；common 无 sqlx feature 时 cfg_attr 跳过派生（WASM 兼容） |
| 默认解析链 | dao/user_credential/sqlite.rs `find_default` | 候选 = 本人活跃 + 同 org public 活跃；排序 user_id 匹配 DESC → is_default DESC → created_at ASC |
| set_default 事务 | dao/user_credential/sqlite.rs `set_default` | 先取目标 → 同事务清同作用域旧默认（作用域列组合由 visibility 派生）→ 立新默认 |
| 权限门控 | domain/finance/identity_credential.rs `set_default_credential` | private 仅 owner（ctx.uid == user_id）；public 需 UserRole::has_permission(Admin)；None 语义 = 取消个人默认（幂等） |
| 所有权校验 | domain/finance/identity_credential.rs `load_owned_credential` | 非本人凭证按 NotFound 处理（不泄露存在性） |
| 消费侧解耦 | dal/lark.rs | new_with_credential_dao 注入；UserCredentialPo 行级查询 + HashMap 缓存（同凭证多渠道引用免重复查库） |
| QueryBuilder 列集 | dao/user_credential/sqlite.rs `CREDENTIAL_COLUMNS` | 纯列名（运行时 FromRow 解码）；query! 宏路径保留 `as "col: Type"` 标注 |

## 五、验收清单

- [x] 迁移幂等：存量 JSON 搬迁为行记录（INSERT OR IGNORE + json_type 守卫），旧列删除无回滚窗口
- [x] 软删联动：soft_delete 同步清 is_default（默认槽位自动空出，测试覆盖）
- [x] set_default 权限门控：private 仅本人 / public 需 Admin+ / 类型不匹配报错 / None 幂等取消
- [x] 解析链优先级：个人默认 > 个人其他 > 组织默认 > 组织其他 public（find_default 排序键覆盖）
- [x] 并发丢更新消解：行级 update 取代整列覆盖（表设计层面消解）
- [x] secret 恒不回显：集成测试守护断言（channel response 全链路不出现 app_secret 明文）
- [x] 明文直通兼容：解密路径对未加密值原样返回（seed 与迁移数据均依赖）
- [x] WASM 兼容：common 凭证类型 sqlx 派生经 cfg_attr 门控，前端 wasm32 clippy 零告警
- [x] clippy -D warnings 双端零告警；lib 974 + 集成测试全绿

## 七、后续扩展路径

1. **common**：`identity_credentials.rs` 加新 CredentialKind 变体（TEXT 枚举直接追加）；`CredentialDetail` 对应变体 + normalized/validate/encrypt_sensitive 行为
2. **domain 分发**：`identity_credential.rs` match kind 分发联动（对齐 LarkApp 渠道引用检查 / GithubToken 登录态清理模式）
3. **handler 目录**：`handlers/finance/<kind>_integration/` 对齐三组既有结构（create/update/delete/set_default/get_status 五文件 + 空检查模式）
4. **进阶能力**：tags 打标分类（is_default 迁移为 tag 语义的预留演进）、组织共享凭据（visibility=public 读写路径）、Agent 专属绑定（使用方实体存 agent_id，凭据表保持零外部引用）
