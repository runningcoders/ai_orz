# 系统初始化模型配置策略调整

> 🎯 **定位**：初始化系统时模型配置策略调整的落地快照——对话模型改可选、向量模型创建不阻塞+启用时切换、补配闭环（自动重建触发）
> 状态：v1.0（2026-08-17）
> 触发场景：初始化系统、补配模型、更换 Embedding Provider 时查阅
>
> 关联文档：
> - [上层权威文档](AGENTS.md) — 分层架构、枚举类型安全、查询分页规范
> - [LAYERED_ARCHITECTURE_PRACTICE.md](docs/LAYERED_ARCHITECTURE_PRACTICE.md) — 分层纪律与边界

---

## 一、目标

| 问题 | 解决方式 | 架构收益 |
|------|---------|---------|
| 初始化时对话模型必填，Agent 创建前无法跳过 | `chat_model` 改 `Option`，条件化创建 provider | 用户可分阶段配置，降低初始化门槛 |
| 向量模型跳过后果不明确，后补时无自动重建 | 向量模型保持可选但强化后果提示；首次补配自动注册重建任务 | 语义搜索从"不可用"到"自动恢复"，无需手动重建 |
| 已有 Embedding Provider 时无法创建备用 | 允许创建但降级为 `Disabled` 状态，启用时走切换确认 | 支持预先配置备用模型，切换时机由用户掌握 |
| 初始化后无 UI 入口新建 Embedding Provider | 创建 Modal 增加 capability 选择（Agent/Embedding） | 补配闭环前端入口补齐 |

## 二、架构思路

```
三段式改动：
① 后端协议与初始化流程
   common::api::organization → chat_model 改 Option + serde(default)
   initialize_system handler → 条件化创建 + 动态步骤数 + 边界校验
   ↓
② 后端补配闭环
   domain::finance::model_provider → create 时 Embedding 降级为 Disabled
   handlers → 创建/更新 Embedding 时按生效状态条件注册 RebuildVectorsTask
   ↓
③ 前端三处
   reception.rs → 2 步表单（基础信息 → 模型配置）+ 跳过后果提示
   agents.rs → 创建 Agent 时按 capability 过滤 + 空态引导
   model_providers.rs → 创建 Modal capability 选择 + 禁用/删除语义分离
```

**关键边界**：
- `Disabled = 2` 是真实禁用状态（条目保留可再启用），与软删除 `Deleted = 0` 语义分离
- 只有「首个创建」或「编辑使用中的 Embedding 配置变化」才触发向量重建
- `ModelProviderStatus` 新增 `Disabled` 变体，枚举 i32 存储，无需 migration

## 六、执行结果摘要

### 后端

- **common DTO**：`chat_model` 改为 `Option`，`chat_provider_id` 改为 `Option<String>`，`ModelProviderStatus` 新增 `Disabled = 2` 变体。
- **初始化 Handler**：动态计算步骤数，chat/embedding 条件化创建，入口补充模型字段边界校验（直调 API 绕过前端时返回 400）。
- **Domain 层**：`create_model_provider` 实现 Embedding 创建降级逻辑；`update_model_provider` 守卫启用时走 409 switch_required。
- **Handler 层**：创建/更新 Embedding 时按生效状态条件注册 `RebuildVectorsTask`，响应 DTO 加 `status` + `rebuild_task_id`。

### 前端

- **初始化向导**：重构为 2 步表单，带步骤指示器和跳过后果提示。
- **Agent 创建页**：Provider 下拉仅展示 Agent 能力，空态引导用户去模型管理。
- **模型管理页**：创建 Modal 加 capability 选择（Agent/Embedding），禁用（status=2）与删除语义分离，创建成功 toast 按状态区分提示。

### 测试

- 新增 7 个集成测试用例：最小初始化 1 个 + Embedding 生命周期 6 个。
- 既有 `bootstrap_system`（chat 必填）保持不变，15+ 处引用零影响。

### 与计划的偏离

无偏离。

## 七、后续扩展路径

1. **common 模型**：若后续需要更多模型状态（如 `Pending`、`Error`），在 `ModelProviderStatus` 追加变体，检查 `from_i32` 穷举匹配。
2. **domain 分发**：若后续需要「定时检查 Disabled Embedding 的健康状态」，在 `finance::init_base_data()` 或 Cron Trigger 中实现。
3. **handler 目录**：若后续需要「批量切换 Embedding Provider」，新增 `batch_switch_embedding.rs` handler，复用现有 `switch_embedding` 逻辑。
4. **前端**：若后续需要「向量重建进度可视化」，在仪表盘或模型详情页集成 `RebuildProgressResponse` 轮询展示。
