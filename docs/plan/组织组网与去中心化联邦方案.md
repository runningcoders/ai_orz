# 组织组网与去中心化联邦方案（评审稿）

> 状态：评审中 · 未走 wiki 查重流程
> 范围：多设备部署下组织间点对点建联、目录同步、去中心化组网
> 前置讨论：2026-09-04 架构咨询（两层网关 / 影子记录 / 集团极薄化 / 配对引导）

---

## 一、目标与范围

**目标**：任何两个 ai_orz 节点上的组织可以点对点建联；建联后双方互持目录，可发起跨组织通信；网络无主节点，靠重复配对自然生长。

**本期实现（Phase 1）**：
- 数据模型：`scope` 三态扩展、`group_name` 展示字段、`organization_links` 连接表
- 组网配对协议：配对码签发 / 验证 / 建联（双向凭证交换）
- 目录同步：建联时双向拉取对端组织目录，写入影子记录

**本期不做（YAGNI，Phase 2+ 预留）**：跨组织业务调用鉴权（联邦 JWT）、能力白名单、计费结算、定期目录对账。

## 二、核心决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|------|------|
| D1 | 集团 = `group_name` 纯展示标签，**不参与任何逻辑判断** | 消解分布式一致性问题：可重名、可不同步、无权威源；名字错了只影响显示 |
| D2 | `scope` 三态：`Local / Linked / Remote` | "能否通信"只看 Linked，判断规则极简；Remote = 目录同步所得影子（未建联） |
| D3 | 去中心化，无锚点/主节点 | 组织对等建联；目录靠配对时 gossip 传播，最终一致可接受（D1 保证了不一致无害） |
| D4 | 连接参数独立 `organization_links` 表，不进 organizations | organizations 是被 join 最频繁的表，凭证混入会放大泄漏面（安全，非洁癖） |
| D5 | 配对码模式，复用邀请码机制 | 不收对方管理员账密（安全红线）；`validate_invite_code` / `register_by_invite` 是现成范式 |
| D6 | 双向独立凭证 | A 调 B 与 B 调 A 用不同 token；出站存明文（调用用）、入站存哈希（校验用） |
| D7 | 接口落位 organization 维度，**不新建顶层模块**；统一前缀 `/api/v1/organization/links/*`，按挂载点拆鉴权 | 组网本质是组织间关系操作，与 service 层落点（DAO/DAL/Domain 均在 organization 域）对齐；机器端点调用方是对端节点（无本地用户 JWT），不能进 `protected_routes` 的 JWT 链，但可同前缀挂 root 层（axum 0.8 同前缀双挂载已探针实测：nest 内与 root 直挂路由互不冲突，7 端点全可达） |

## 三、数据模型变更

### 3.1 枚举扩展（`common/src/enums/organization.rs`）

```rust
pub enum OrganizationScope {
    /// Local (当前设备运行的组织)
    #[default]
    Local = 0,
    /// Remote (目录同步所得影子，未直接建联)
    Remote = 1,
    /// Linked (与本组织直接建联，可通信)
    Linked = 2,
}
```

- 存量数据默认 `0`（Local），不受影响；`1` 的语义细化为"影子、未建联"
- 同步更新：`From<i32>` / `to_i32` 转换、doc 注释、`enums` 模块测试
- **不变量**：`scope == Linked` ⇔ `organization_links` 存在对应记录（links 是事实源，scope 是投影）

### 3.2 迁移 SQL（两个文件）

```sql
-- migrations/20260904000001_add_group_name_to_org.sql
-- 组织集团名（纯展示标签，不参与逻辑判断；建联时若本端为空且对端非空则抄录）
ALTER TABLE organizations ADD COLUMN group_name TEXT NULL;
```

```sql
-- migrations/20260904000002_create_organization_links.sql
CREATE TABLE IF NOT EXISTS organization_links (
    id TEXT NOT NULL PRIMARY KEY,
    local_org_id TEXT NOT NULL,             -- 本端组织 id
    peer_org_id TEXT NOT NULL,              -- 对端组织 id（organizations 中 scope=Linked 的记录）
    endpoint TEXT NOT NULL,                 -- 对端 API 基址（联邦通信地址）
    access_token TEXT NOT NULL,             -- 出站凭证：本端调用对端时携带（32 字节随机，hex）
    peer_token_hash TEXT NOT NULL,          -- 入站校验：对端调用本端时携带凭证的 SHA-256 哈希
    status INTEGER NOT NULL DEFAULT 1,      -- 1=Active 0=Revoked
    created_by TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    FOREIGN KEY (local_org_id) REFERENCES organizations(id),
    FOREIGN KEY (peer_org_id) REFERENCES organizations(id)
) STRICT;

-- 一对组织之间只有一条连接（重复建联走 upsert/续联）
CREATE UNIQUE INDEX uq_organization_links_pair
    ON organization_links(local_org_id, peer_org_id);
CREATE INDEX idx_organization_links_peer ON organization_links(peer_org_id);
```

> 注：`base_url` 维持"前端展示链接"语义不变；联邦通信地址一律以 `organization_links.endpoint` 为准。

## 四、组网配对协议

### 4.1 流程（五步）

1. **对端签发配对码**：对端管理员调 `POST /api/v1/organization/links/pairing/issue` → 返回 24 字符配对码（字符集同邀请码：去 0/O/1/I），**10 分钟有效、单用途**（用后即焚）
2. **本地发起建联**：用户在本地输入 `配对码 + 对端地址` → `POST /api/v1/organization/links`
3. **双向验证、交换凭证**：本地凭配对码调对端 `POST /api/v1/organization/links/pairing/verify`；双方各自生成 32 字节随机 token，交叉交付（A 的 access_token = B 校验用的 peer_token_hash 来源）
4. **写入连接 + 影子**：双方各自落 `organization_links` 一条 + `organizations` 一条 `scope=Linked` 影子
5. **目录同步**：双向拉取对端目录（见第五节），推送本地目录；`group_name` 空端抄录非空端

### 4.2 API 设计（挂 organization 维度，统一前缀，按挂载点拆鉴权）

**用户侧端点**——调用方是本地用户/管理员，走 JWT，挂进 `protected_routes` 的 organization nest（`/api/v1/organization/links/*`）：

| 端点 | 方法 | 鉴权 | 说明 |
|------|------|------|------|
| `/organization/links/pairing/issue` | POST | 本端管理员 JWT | 生成配对码（短时效、单用途） |
| `/organization/links` | POST | 本地用户 JWT | 发起建联（body：配对码 + 对端地址），服务端出站完成验证与凭证交换 |
| `/organization/links` | GET | 本地用户 JWT | 已建联列表（前端"关联组织"页数据源） |
| `/organization/links/{peer_org_id}` | DELETE | 本端管理员 JWT | 断联（见 4.3） |

**机器侧端点**——调用方是对端节点（无本地用户 JWT），**同一前缀**在 root 层直接全路径挂载（a2a callback 先例，`router.rs:128-134`），配对码/契约凭证鉴权中间件独立实现：

| 端点 | 方法 | 鉴权 | 说明 |
|------|------|------|------|
| `/organization/links/pairing/verify` | POST | 配对码本身 | 验证配对码，交换建联信息与凭证 |
| `/organization/links/directory` | GET | 契约凭证 | 返回本节点组织目录（见 5.1 白名单字段） |
| `/organization/links/directory/sync` | POST | 契约凭证 | 接收对端推送的目录 |

- 同前缀双挂载（JWT nest 内用户侧 + root 直挂机器侧）已用探针测试实测：axum 0.8 路由表下两种挂载互不冲突，7 个端点全部可达
- 阅读约定：**挂载点即鉴权边界**——`protected_routes` nest 内 = 用户侧（JWT），root 层直挂 = 机器侧（配对码/凭证）
- Handler 遵循双宏标注规范：`generate_http_handler`；**组网端点不注册 `register_handler_tool`**（非 Agent 工具，防 Agent 误触组网）
- 配对码/凭证校验失败返回统一 `err!(Unauthorized, ...)`，不区分"码无效/已过期"（防枚举探测）

### 4.3 断联

`DELETE /api/v1/organization/links/{peer_org_id}`（本端管理员）：置 `status=Revoked`，**不删除**对端影子记录（降级 `scope=Remote`），保留历史审计线索。对端通过下次调用失败感知（401 → 惰性降级）。

## 五、目录同步机制

### 5.1 同步内容（白名单字段，红线：仅目录元信息）

```
id, name, description, base_url, group_name, status, updated_at
```

**绝不包含**：用户、Agent、任务、项目、消息、记忆、凭证等任何业务数据。

### 5.2 传播与幂等

- 每次建联时：从对端 `GET /api/v1/organization/links/directory` 拉全量目录 → 本地 upsert（已存在的按 `updated_at` 新者胜）
- 写入规则：本地已有（含 Linked）→ 更新元信息不动 scope；本地没有 → 写入 `scope=Remote` 影子
- 推送侧：建联完成后 `POST /api/v1/organization/links/directory/sync` 主动推一次本地目录给对端
- **无递归爆炸**：每个节点只与直接 Linked 对端同步，天然 O(直连数)；按 id upsert 幂等，环（A→B→C→A）无害
- 变更传播：Phase 1 不做主动推送（改名靠下次建联/手动触发同步），留 `/directory/sync` 端点作 Phase 2 对账入口

## 六、安全设计

1. **红线一（凭证交换）**：只收配对码，不收对端管理员账密——用户在任何界面都不应输入对方密码
2. **红线二（数据边界）**：目录同步只出白名单字段；出站响应统一过 `redact!`（EXPORT policy，复用现有脱敏引擎，见 `common/src/redaction/`）
3. **配对码**：24 字符、10 分钟 TTL、单用途、签发记审计（`log_info!` 带 log_id）；防枚举（统一错误响应 + 签发/验证限流）
4. **凭证**：双向独立 token；`peer_token_hash` 只存哈希；吊销 = 断联置 Revoked；泄漏应急 = 重置 token（续联端点复用）
5. **审计**：建联/断联/目录同步/凭证重置全部落审计日志，`RequestContext` 贯穿 `trace_id`
6. **入口隔离**：机器侧端点与用户侧同前缀（`/api/v1/organization/links/*`）但在 root 层直接挂载（a2a callback 先例），不进 JWT 鉴权链（配对码/凭证鉴权中间件独立实现，不碰 `jwt_auth.rs`）；同前缀双挂载已实测可行

## 九、测试与验收标准

1. **端到端**：两个测试 server（不同端口）模拟两节点，从签发配对码到目录互通全链路
2. **幂等**：同一对组织重复建联 → upsert 不重复；目录重复同步 → 无重复影子
3. **安全**：过期配对码拒绝、已用配对码拒绝（单用途）、错误凭证 401、目录响应经 `redact!` 后无越权字段
4. **兼容**：存量组织（scope=Local）读写不受迁移影响；存量 Remote 记录语义兼容
