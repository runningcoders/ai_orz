## 一、目标

| 问题 | 解决方式 |
|------|---------|
| Agent 无法获取实时网络信息 | 新增 Builtin 内置工具 `tavily_search`（Auto 模式，tag: `search`） |
| API key 归属混乱（个人 key 被迫塞共享配置） | **授权双轨制首例**：`CredentialKind::TavilyKey` 个人凭证（用户凭证库，加密）+ `[tavily].api_key` 共享兜底；解析顺序用户凭证优先 → 共享 config |
| 授权缺失时工具静默失败 | 调用时返回 `api_key_missing` 结构化引导（双路径：绑个人凭证 / 配共享 key），本阶段先内联实现 |
| 搜索结果直接拼接不可控 | 返回结构化 JSON（title/url/snippet 列表 + 截断标记），LLM 自行取舍 |

**收敛后效果**：Agent 绑定 tag `search` 即具备网络检索能力；TavilyKey 成为后续所有「个人授权型工具」接入用户身份体系的标准样板。清单级 `runtime_ready` 预检由阶段二 tool_readiness 统一接入。

## 二、架构思路

```
tavily_search.call(ctx, params)
    → 授权解析（双轨）：
        ① TavilyCredentialResolver（pkg trait，DAL 实现注入）
           → ctx.uid 用户凭证库 TavilyKey（优先，解密后明文）
        ② config [tavily].api_key（共享兜底）
        皆缺 → { error_code: "api_key_missing",
                 guidance: "绑定个人 Tavily key（身份凭证页）
                            或在 ai_orz.toml [tavily].api_key 配置共享 key" }
    → reqwest POST https://api.tavily.com/search（Bearer 解析所得 key）
    → 响应 results[] 映射 { title, url, snippet }
    → 超时保护 + 条数上限（max_results 默认 5）
```

**关键边界**：不做 provider trait 抽象；只读操作；Auto 模式；授权缺失不隐藏工具而是双路径引导；pkg 层经 Resolver trait 注入、不 import DAL。

- [x] clippy -D warnings 双端零告警；双轨解析/皆缺引导/响应映射单测覆盖
