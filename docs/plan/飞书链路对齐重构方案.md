## 一、目标、范围与决策

### 1.1 两条断点、两个目标

飞书现在有**两条互相独立的断点**，任一条不修都「用不上飞书」：

| 断点 | 现状 | 目标 |
|------|------|------|
| **A. 协议层**（连接建立不了） | 端点 404（实测）、鉴权错、帧格式错 → WS 从未建连过 | 真机建立长连接、收到事件、3s 内回 ACK、不触发重推 |
| **B. 凭据层**（凭据进不了库） | 扫码建应用的 `appId` 白拿却被丢掉（硬编码 `None`）、分支 A 从未实现 | 扫码 → 拿 `appId` → 用户粘一次 secret → 自动落库 → 长连接可用（闭环） |

**只修 A** ⇒ 用户拿不到可用凭据，依旧跑不起来。**只修 B** ⇒ 凭据有了但连接建不起来。**必须同批。**

## 二、零改动面（不得削弱）

> 违反以下任一条即为回归，验收时逐条核对。

1. **`pkg::ws` 对联邦零影响**：`organization_link` 的联邦 WS（`dao/organization_link/ws/session.rs`）与本组件共用 `pkg::ws`。所有新能力必须是**带默认实现的 trait 方法 / 新增类型**，**联邦一行不改**；联邦既有测试作为回归闸门。
2. **AOP 不变量**：读循环只 `publish` 不做业务；三入站消费者适配失败必须 `Err`（P6）；`order_key` 同域同消费者；`on_consumed` 保持幂等。

4. **提示词/身份分层**：入站 `from_role=User`、系统链路 `enrich_org_from_project_user` 补 org 等既有约定不变。
5. **门禁**：`cargo fmt` 只对本次 crate；`clippy --workspace --exclude frontend`；前端 `--target wasm32-unknown-unknown --all-targets -D warnings`（`-D warnings` 放 `--` 之后）；提交走 `.githooks`（`core.hooksPath`）。
6. **测试**：禁 `sqlite::memory:`；新集成测试须在 `Cargo.toml` `[[test]]` 注册。
7. **文档 SSOT**：`docs/design|plan` 随代码一笔，`docs/wiki`（含 RAG 快照）单独一笔。

## 四、关键设计决策

### 4.1 `pkg::ws` 如何做加法（S1 的核心）

现状 trait 只有文本帧通路（`on_frame(String)`），且心跳间隔是常量、退避是硬编码指数、无终局停机。**全部用「新增 + 默认实现」扩展**：

```rust
// 新增类型（pkg 只区分文本/二进制，对内容零假设——保持组件无业务语义）
pub enum WsFrame    { Text(String), Binary(Vec<u8>) }
pub enum WsOutFrame { Text(String), Binary(Vec<u8>) }

/// 单帧处置结果：动作 + 需要立刻回写的帧（ACK / pong 走这里）
pub struct FrameOutcome { pub action: FrameAction, pub replies: Vec<WsOutFrame> }

// trait 新增（全部带默认实现 ⇒ 联邦零改动）
async fn on_message(&self, f: WsFrame) -> FrameOutcome {
    // 默认：文本转投既有 on_frame；二进制仅 debug 留痕（不静默）
}
fn heartbeat(&self) -> Option<Heartbeat> { /* 默认 30s + 协议级 Ping，等价现状 */ }
fn reconnect_policy(&self) -> ReconnectPolicy { ReconnectPolicy::Exponential } // 默认等价现状
fn terminal_reason(&self) -> Option<String> { None }  // Some → supervisor 停机
```

配套状态扩展：

| 项 | 变化 | 用途 |
|---|---|---|
| `WsConnPhase` | + `Failed`（`"failed"`） | 终局态可被健康页读到 |
| `WsConnState` | + `last_frame_at` / `frames_received` / `last_close_code` / `last_close_reason` / `terminal_reason` | F1/F2/F6 的判活字段 |
| 读循环 | `Message::Binary` 走 `on_message`；`Close/Ping/Pong` 分支补全并记录 | F0-3 + F1 |
| 心跳任务 | 每 tick **重新查询** `adapter.heartbeat()`（间隔与帧可被 pong 更新） | F0-4 |
| supervisor | 每次退出边界查 `terminal_reason()`；`Some` → `Failed` + 停重连 | F0-8 / D3 |

**为什么不给 `FrameAction` 加第三个变体？** 加变体会让所有 `match` 变成非穷尽（联邦侧、`server.rs` 都要跟改）。用 `terminal_reason()` 单一机制表达「停机」更小：它同样覆盖**取端点阶段的致命码**（`exceed_conn_limit` 发生在建连之前，帧动作根本表达不了）。

**ACL 替代方案**：若不愿引入任何新依赖，`on_message` 的二进制分支可先留 `todo`（先修端点/鉴权/文本，再补 protobuf）——但这正是 D0 要避免的「分两次改」。

### 4.2 protobuf 落地：prost derive 手写结构，不要 `build.rs`

- 官方 `.proto` 只有 `Frame`（9 字段）+ `Header`（2 字段），**手写 `#[derive(prost::Message)]` 结构体即可**，无需 `.proto` 文件、`prost-build`、`protoc`。
- 依赖：根 `Cargo.toml` 加 `prost = "0.13"`（**运行时唯一新增**，feature 默认含 derive）。
- 落点：`src/service/dao/lark/pbbp2.rs`（飞书私有协议，**不进 `pkg::ws`**——保持传输层无协议）。
- 文件头写入「协议依据」注释块：官方 SDK `lib/index.js` 的锚点行号 + 字段 tag 表，供后续对账。

> 备选：手写 varint/length-delimited 编解码（约 120 行、零依赖）。**仅当 prost 因体积/审计被拒时启用**；否则不发明轮子。

### 4.3 ACK 时机（3s 窗口）

官方会**在 3s 内未收到 ACK 时重推**，所以 ACK 必须由**读循环**发出、不能交给 AOP consumer：

```
收到 data 帧 → 解码 → 解析 payload → publish（入队即返回，快速）
           → 立即回 ACK：同 headers + biz_rt + payload {"code":200}
           → 入队失败则回 {"code":500}（把重试交回官方机制）
```

好处：读循环仍是「只入队不做业务」（零改动面 2 保持），同时天然满足 3s。

### 4.4 致命码与终局（D3）

| 码 | 官方语义 | 我方处置 |
|---|---|---|
| `internal_error = 1000040343` | 可重试 | 正常退避重连 |
| `exceed_conn_limit = 1000040350` | **不可重试** | 置 `terminal_reason` → `Failed` + 停重连 + 健康页标 `conflict` |
| `auth_failed = 514` | 鉴权失败（AppID/Secret 错） | 置 `terminal_reason`（重试无意义）→ 前端提示补/换凭据 |
| `forbidden = 403` / `system_busy = 1` | 服务端侧 | 可重试 |

### 4.5 心跳、重连与 `service_id`

- 取连接地址响应的 `data.ClientConfig` 下发 `PingInterval / ReconnectInterval / ReconnectNonce`（**官方兜底默认 120s / 120s / 30s 抖动**，与二手来源「30s / 5s」完全不同）；pong 会再覆盖一次 ⇒ `heartbeat()` **每次 tick 重查**，`reconnect_policy()` **每轮重查**。
- 我方现状 30s + 指数退避 → 改为照服务端参数；首次重连叠加 nonce 抖动，之后固定间隔。
- `service_id` / `device_id` 在连接 URL 的 query 里，**ping 帧需要 `service_id`** ⇒ 取端点时解析并存入 adapter（每次重连刷新）。
- **不做无帧判死**（D2）：`last_frame_at` 只用于展示与 stale 告警，不触发断连。

### 4.6 凭据方向（D6）

```
凭据 SSOT = 我方加密库（现状）
  我方 → CLI：lark-cli config init --app-id <id> --app-secret-stdin   （ensure_cli_config 已是此形态）
  CLI → 我方：只有 appId 明文（--json 输出），secret 永不回读
```

扫码链路只负责**建成应用 + 交出 `appId`**；secret 由用户在开发者后台复制，前端粘一次。**不实现 keychain 反读**（官方 `keychain-downgrade` 面向沙箱/CI，且仍不输出明文 secret）。

### 4.7 多实例语义（D8 + 新增 F20）

官方：**集群模式不支持广播，同应用多客户端只有随机一个收到事件**；且 3s 未 ACK 会重推。两个后果必须显式处理：

1. **F20（本轮新增发现）**：入站**没有任何幂等查重**——`adapt_lark` 只把 `external_key = "lark:{message_id}"` 写进落库命令，`messages.external_key` 是**普通索引非唯一**，落库前不反查；AOP 层也无事件去重。⇒ 一次重推或多实例分发**会重复落库**（对 Agent 表现为「同一条消息被回了两次」）。
   **修法（最小）**：入站落库前用既有 `MessageDao::find_id_by_external_key(ctx, "lark:{message_id}")` 反查，命中 → `info` 留痕（含 `event_id`/`message_id`）+ 跳过。这是 D8 成立的前提，**不可延后**。
2. **F0-12**：启动自检——同 `app_id` 已在本进程外有活跃订阅时打 `warn`（无法可靠探测 ⇒ 退化为「配置/文档 + 健康页 `conflict` 可见」），文档写明「仅一个实例订阅」。
