## 1. 使用的系统/工具

仓库采用**多包管理器混合策略**：
- **Rust 侧**：使用 Cargo workspace（根 `Cargo.toml` 声明 `members = [".", "frontend", "common", "ai-orz-macros"]`，resolver = "2"），通过单一 `Cargo.lock` 锁定所有 crate 版本；SQLx 迁移与 schema 校验由 `.sqlx/` 目录配合 `SQLX_OFFLINE=1` 在 CI 中完成。
- **前端构建依赖**：`frontend/package.json` + `frontend/package-lock.json` 锁定 Tailwind CSS v4、DaisyUI v5 等 CSS 工具链。
- **E2E 测试依赖**：`tests/e2e/package.json` + `tests/e2e/package-lock.json` 锁定 Playwright。
- **无 vendoring**：未使用 `cargo vendor`、`npm ci --frozen` 外的私有 registry 或 `~/.cargo/config.toml` 中的 `[source]` 重定向，全部依赖 crates.io / npmjs.org。

## 2. 关键文件

| 文件 | 作用 |

## 3. 架构与约定

### Rust 依赖分层
- **workspace 成员**：根 crate (`ai_orz`)、`common`（跨前后端 DTO/枚举/错误类型）、`ai-orz-macros`（IDL 宏生成器）、`frontend`（Dioxus WASM）。各成员通过 `path = "../xxx"` 引用内部 crate，不发布到 crates.io。
- **feature flag 裁剪**：`common` crate 将重型可选依赖（`sqlx`、`axum`、`reqwest`、`tokio`、`jsonwebtoken`、`base64`、`toml`、`bincode`）标记为 `optional`，并通过 `features = [...]` 暴露给消费者按需启用。例如根 crate 以 `common = { path = "./common", features = ["sqlx", "axum-integration", "bincode-integration", "toml-integration", "reqwest-integration", "tokio-integration", "jwt-integration", "base64-integration"] }` 引入，避免前端 WASM 编译时链接不必要的运行时；前端 build-dependencies 只引入基础类型不带这些 feature。
- **target-specific 依赖**：根 crate 使用 `[target.'cfg(unix)'.dependencies]` 仅在 Unix 平台引入 `libc`，体现按平台裁剪依赖的约定。
- **版本策略**：大多数依赖使用语义化版本范围（如 `tokio = "1"`、`axum = "0.8"`、`serde = "1"`），允许小版本升级；部分关键库采用精确版本号（如 `sqlx = "0.8.6"`、`uuid = "1.23.0"`、`arrow-array = "57.3.0"`、`duckdb = "1.4.0"`）以控制 ABI 稳定性。
- **向量搜索栈**：显式禁用 `fastembed` 的 `default-features`（注释说明为避免 image → exr → pulp 0.22.3 的 x86 const eval bug），改用 `ort-download-binaries-native-tls` + `hf-hub-native-tls` 纯 Rust candle 后端，并搭配 `lancedb`、`instant-distance`、`arrow-array/schema` 组成零系统依赖的本地向量化方案；`rmcp` 仅启用 `client` 与 `transport-child-process`。
- **Dioxus WASM 前端**：`frontend/Cargo.toml` 启用 `dioxus` 的 `web, router` features，并通过 `web-sys` 白名单方式引入浏览器 API（Window、Storage、EventSource、MessageEvent、Request、Blob、Canvas 等），符合 WASM 最小化原则。
- **补丁机制**：根目录存在 `patches/rig-fastembed/src/` 空目录，预留对第三方 crate 的 `cargo:patch` 机制，当前为空。

### NPM 依赖范围极小
- 前端仅用 Tailwind CLI 做 CSS 构建（`@tailwindcss/cli`、`tailwindcss`、`daisyui` 全部为 devDependencies），无 JS 运行时依赖。
- E2E 独立隔离在 `tests/e2e/` 子目录（Cargo autotests 只扫 `tests/` 顶层 `.rs`，不递归子目录，TS 工程不受 Rust 编译影响），避免污染主构建。
- 通过 `scripts.build:css` / `scripts.watch:css` 调用 Tailwind CLI 生成 `public/output.css`。

### SQLx 离线模式
CI 中设置 `SQLX_OFFLINE: true`，要求 `.sqlx/` 目录中存在预先生成的查询元数据（由 `sqlx prepare` 生成），使 CI 无需连接数据库即可编译和运行迁移校验。这是该仓库对数据库依赖版本的强约束机制。

### 前端依赖
- Dioxus 0.7.9 + wasm-bindgen 0.2 + web-sys 指定精确 feature 集（Window、EventSource、MessageEvent 等），确保 WASM 产物最小化。
- CSS 工具链（Tailwind CLI v4、DaisyUI v5）作为 devDependencies，通过 `package-lock.json` 锁定。

### E2E 依赖
Playwright 独立于主工程，位于 `tests/e2e/` 子目录，通过 `cd tests/e2e && npx playwright test`（或 `make e2e`）运行，当前未接入 CI（workflow 末尾注释说明“待前后端协议化改造落地后再评估重新接入 CI”）。

## 4. 约定与约束

- **版本锁定**：所有 Rust 依赖通过根 `Cargo.lock` 统一锁定；前端/E2E 通过各自的 `package-lock.json` 锁定。CI 的 sccache cache key 直接基于 `**/Cargo.lock` 哈希，保证缓存命中与可重现构建。
- **工具链固定**：`rust-toolchain.toml` 锁定 stable channel 并强制启用 rustfmt 与 clippy 组件，CI 的 `cargo fmt --all -- --check` 与 `cargo clippy -- -D warnings` 构成格式/ lint 门禁。
- **可选依赖必须显式启用**：`common` crate 的所有外部集成（sqlx、axum、reqwest、tokio、jwt、base64、toml）均为 optional feature，调用方必须显式声明所需 feature，禁止隐式引入。
- **平台相关依赖隔离**：Unix-only 依赖放入 `[target.'cfg(unix)'.dependencies]`，避免跨平台编译失败。
- **CI 环境依赖前置**：`lancedb` 依赖 `protobuf-compiler` 与 `libprotobuf-dev`，CI 在每个 job 中显式 `apt-get install`，否则 lance-encoding 的 build script 会因找不到 `empty.proto` 失败。
- **workspace 内 crate 一律通过 `path = "..."` 引用**：确保工作区内版本一致；新增 crate 应加入根 `Cargo.toml` 的 `members` 列表。
- **可选能力通过 feature flags 暴露**：`common` crate 用 optional dependencies + `[features]` 组合出不同集成面，调用方按需启用。
- **Cargo.lock 与 package-lock.json 必须提交**：锁文件随仓库提交，CI 与本地构建必须基于同一份锁定结果；新增或升级依赖需同步更新 lockfile。
- **SQLx 查询快照随源码提交**：`.sqlx/` 下的 JSON 快照文件与迁移脚本配合，确保 SQL 变更在编译期被校验。
- **版本锁定**：Rust 侧通过根 `Cargo.lock` 统一锁定；前端/E2E 通过各自的 `package-lock.json` 锁定。CI 的 sccache cache key 直接基于 `**/Cargo.lock` 哈希，保证缓存命中与可重现构建。
- **工具链固定**：`rust-toolchain.toml` 锁定 stable channel 并强制启用 rustfmt 与 clippy 组件，CI 的 `cargo fmt --all -- --check` 与 `cargo clippy -- -D warnings` 构成格式/lint 门禁。
- **可选依赖必须显式启用**：`common` crate 的所有外部集成均为 optional feature，调用方必须显式声明所需 feature，禁止隐式引入。
- **平台相关依赖隔离**：Unix-only 依赖放入 `[target.'cfg(unix)'.dependencies]`，避免跨平台编译失败。
- **CI 环境依赖前置**：`lancedb` 依赖 `protobuf-compiler` 与 `libprotobuf-dev`，CI 在每个 job 中显式 `apt-get install`；CI 显式设置 `CARGO_INCREMENTAL=0`，让 sccache 完全接管缓存。
- **无私有 registry / vendoring**：未发现 `.cargo/config.toml`、`CARGO_REGISTRIES`、`CRATE_REGISTRY` 或 npm `.npmrc` 等私有源配置；未使用 `cargo vendor` 或 Git submodule 源码级依赖复制策略，依赖树完全由 lockfile 驱动。
- **共享类型走 common crate**：前后端共享的 DTO/枚举/错误类型集中在 `common`，通过 path 依赖引用，禁止在多个 crate 中重复定义。
- **覆盖率门禁**：CI coverage job 使用 `cargo-llvm-cov`，push main 要求 fail-under-lines ≥ 45%，PR 要求 ≥ 38%，低于阈值即失败；报告通过 `--ignore-filename-regex` 排除 tests/common、registry、rustc、build.rs、target。
- **依赖更新流程**：新增或升级外部 crate 需同步提交 `Cargo.lock` 与 `package-lock.json`；CI 格式与 lint 一致性检查强制通过。
