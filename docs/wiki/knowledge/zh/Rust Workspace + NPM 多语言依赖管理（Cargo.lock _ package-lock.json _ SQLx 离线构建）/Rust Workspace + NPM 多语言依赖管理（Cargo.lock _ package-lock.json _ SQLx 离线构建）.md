## 1. 使用的系统/工具

仓库采用**多包管理器混合策略**：
- **Rust 侧**：使用 Cargo workspace（根 `Cargo.toml` 声明 `members = [".", "frontend", "common", "ai-orz-macros"]`，resolver = "2"），通过单一 `Cargo.lock` 锁定所有 crate 版本；SQLx 迁移与 schema 校验由 `.sqlx/` 目录配合 `SQLX_OFFLINE=1` 在 CI 中完成。
- **前端构建依赖**：`frontend/package.json` + `frontend/package-lock.json` 锁定 Tailwind CSS v4、DaisyUI v5 等 CSS 工具链。
- **E2E 测试依赖**：`e2e/package.json` + `e2e/package-lock.json` 锁定 Playwright。
- **无 vendoring**：未使用 `cargo vendor`、`npm ci --frozen` 外的私有 registry 或 `~/.cargo/config.toml` 中的 `[source]` 重定向，全部依赖 crates.io / npmjs.org。

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `Cargo.toml`（根） | workspace 定义、后端主 crate 依赖、`[[test]]` 集成测试入口 |
| `Cargo.lock` | 全工作区唯一依赖快照（CI cache key 基于 `**/Cargo.lock`） |
| `rust-toolchain.toml` | 固定 toolchain channel = stable，启用 rustfmt/clippy，目标包含 `wasm32-unknown-unknown` |
| `common/Cargo.toml` | 共享 crate，通过 optional features（`sqlx`、`axum-integration`、`reqwest-integration`、`tokio-integration` 等）按需裁剪编译产物 |
| `ai-orz-macros/Cargo.toml` | proc-macro crate，仅依赖 `proc-macro2`/`quote`/`syn`/`schemars` |
| `frontend/Cargo.toml` | Dioxus WASM 前端 crate，依赖 `common`（path 方式引用） |
| `frontend/package.json` | Tailwind/DaisyUI 构建脚本 |
| `e2e/package.json` | Playwright E2E 测试脚本 |
| `.github/workflows/rust.yml` | CI 中设置 `SQLX_OFFLINE=true`、安装 `protoc`（lancedb 需要）、配置 sccache 缓存 |

## 3. 架构与约定

### Rust 依赖分层
- **workspace 成员**：根 crate (`ai_orz`)、`common`（跨前后端 DTO/枚举/错误类型）、`ai-orz-macros`（IDL 宏生成器）、`frontend`（Dioxus WASM）。各成员通过 `path = "../xxx"` 引用内部 crate，不发布到 crates.io。
- **feature flag 裁剪**：`common` crate 将重型可选依赖（`sqlx`、`axum`、`reqwest`、`tokio`、`jsonwebtoken`、`base64`、`toml`）标记为 `optional`，由使用者以 feature 形式开启。例如根 crate 以 `common = { path = "./common", features = ["sqlx", "axum-integration", "bincode-integration", "toml-integration", "reqwest-integration", "tokio-integration"] }` 引入，避免前端 WASM 编译时链接不必要的运行时。
- **target-specific 依赖**：根 crate 使用 `[target.'cfg(unix)'.dependencies]` 仅在 Unix 平台引入 `libc`，体现按平台裁剪依赖的约定。
- **向量搜索栈**：显式禁用 `fastembed` 的 `default-features`（注释说明为避免 image → exr → pulp 0.22.3 的 x86 const eval bug），改用 `ort-download-binaries-native-tls` + `hf-hub-native-tls` 纯 Rust candle 后端，并搭配 `lancedb`、`instant-distance`、`arrow-array/schema` 组成零系统依赖的本地向量化方案。

### SQLx 离线模式
CI 中设置 `SQLX_OFFLINE: true`，要求 `.sqlx/` 目录中存在预先生成的查询元数据（由 `sqlx prepare` 生成），使 CI 无需连接数据库即可编译和运行迁移校验。这是该仓库对数据库依赖版本的强约束机制。

### 前端依赖
- Dioxus 0.7.9 + wasm-bindgen 0.2 + web-sys 指定精确 feature 集（Window、EventSource、MessageEvent 等），确保 WASM 产物最小化。
- CSS 工具链（Tailwind CLI v4、DaisyUI v5）作为 devDependencies，通过 `package-lock.json` 锁定。

### E2E 依赖
Playwright 独立于主工程，位于 `e2e/` 子目录，通过 `cd e2e && npx playwright test` 运行，当前未接入 CI（workflow 末尾注释说明“待前后端协议化改造落地后再评估重新接入 CI”）。

## 4. 约定与约束

- **版本锁定**：所有 Rust 依赖通过根 `Cargo.lock` 统一锁定；前端/E2E 通过各自的 `package-lock.json` 锁定。CI 的 sccache cache key 直接基于 `**/Cargo.lock` 哈希，保证缓存命中与可重现构建。
- **工具链固定**：`rust-toolchain.toml` 锁定 stable channel 并强制启用 rustfmt 与 clippy 组件，CI 的 `cargo fmt --all -- --check` 与 `cargo clippy -- -D warnings` 构成格式/ lint 门禁。
- **可选依赖必须显式启用**：`common` crate 的所有外部集成（sqlx、axum、reqwest、tokio、jwt、base64、toml）均为 optional feature，调用方必须显式声明所需 feature，禁止隐式引入。
- **平台相关依赖隔离**：Unix-only 依赖放入 `[target.'cfg(unix)'.dependencies]`，避免跨平台编译失败。
- **CI 环境依赖前置**：`lancedb` 依赖 `protobuf-compiler` 与 `libprotobuf-dev`，CI 在每个 job 中显式 `apt-get install`，否则 lance-encoding 的 build script 会因找不到 `empty.proto` 失败。
- **无私有 registry**：未发现 `.cargo/config.toml`、`CARGO_REGISTRIES`、`CRATE_REGISTRY` 或 npm `.npmrc` 等私有源配置，所有第三方依赖来自公开注册表。
- **无 vendoring**：未使用 `cargo vendor` 或 `npm ci --frozen` 之外的源码级依赖复制策略，依赖树完全由 lockfile 驱动。
