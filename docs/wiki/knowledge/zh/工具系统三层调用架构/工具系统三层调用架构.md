## §1 概述

本卡片定义 AI Orz 工具系统的三层调用架构——**CoreTool trait 抽象层 + Builtin/HTTP/MCP 三协议路由层 + register_handler_tool 宏注册层**。核心决策为：工具实例由 `ToolRegistry` 按协议类型分发创建，`CoreTool::call()` 统一异步执行入口，`handler_adapter` 宏将处理器层工具无缝注册到注册表。三级就绪提示体系（`tool_readiness.rs`）为 CLI 型和 key 型工具提供统一的就绪状态探测与引导。

## §3 架构约定

### 3.1 CoreTool trait 统一抽象

所有工具实现 `CoreTool` trait：

```rust
#[async_trait]
pub trait CoreTool: Send + Sync {
    async fn call(&self, ctx: RequestContext, args: Value) -> Result<Value>;
    fn po(&self) -> &ToolPo;
}
```

### 3.2 三协议路由分发

`ToolRegistry::create_tool()` 按 `ToolPo.protocol` 分发到对应工厂：

| 协议 | 工厂 | 存储方式 |
|---|---|---|
| `Builtin` | `builtin_factories` | `HashMap<String, Box<dyn BuiltinToolFactory>>` |
| `Http` | `http_factory` | 单例 `Arc<dyn HttpToolFactory>` |
| `Mcp` | `mcp_factories` | `HashMap<String, ()>` (stub) |

### 3.3 Handler 适配宏

`register_handler_tool!` 宏将处理器层的异步函数转换为 `CoreTool` 实现：

```rust
register_handler_tool! {
    id = "tool_id",
    name = "Tool Name",
    handler = my_handler_fn,
    // ...
}
```

### 3.4 三层就绪提示

`tool_readiness.rs` 提供统一的就绪状态探测：

- **CLI 型探测器**（browser/gh_cli/lark_cli）：二进制可寻址检查，带 TTL 缓存
- **Key 型探测器**（tavily_search）：共享 config key 或用户凭证库查询，按用户区分缓存
- **统一引导**：`cli_not_installed` / `api_key_missing` 结构化 JSON 返回

### 3.5 与「工具输出与安全治理」卡的关系

本卡定义工具系统的**架构骨架**（协议路由、工厂分发、调用入口）；「工具输出与安全治理」卡（Level 3 互补视角）聚焦该骨架上的**安全边界与输出治理**——包括 HTTP/SSRF 防护、路径逃逸检查、工具输出脱敏、环境变量过滤等具体实现。两卡互为补充：本卡回答"工具系统如何组织"，安全治理卡回答"工具运行时如何保护"。

## §4 硬约束

1. **禁止绕过注册表创建工具实例**：所有工具实例必须通过 `ToolRegistry::create_tool()` 创建，禁止直接 `CoreTool::from()` 构造。
2. **Builtin 工具不可由用户修改或删除**：用户只能通过代码同步获取最新 Builtin 工具定义。
3. **协议路由必须在 create_tool 中匹配**：新增协议类型必须扩展 `ToolPo::protocol` 枚举并在 `create_tool` 中添加 match 分支。
4. **Handler 工具必须通过 register_handler_tool! 宏注册**：禁止手写 `impl CoreTool` 的 handler 适配器。
5. **就绪探测器必须注册到全局 PROBES**：新增 CLI/key 型工具的探测器必须在 `register_default_probes()` 中注册。
6. **就绪缓存 key 必须区分 user_scoped**：key 型探测器按 `(tool_id, user_id)` 缓存，CLI 型按 `tool_id` 缓存。
7. **工具调用日志必须走 ToolCallLogger**：所有工具执行的 stdout/stderr/exit_code 必须通过 `ToolCallLogger::log_call()` 持久化。
8. **参数校验必须走 parameters_schema**：`ToolPo.parameters_schema` 是参数校验的唯一事实源，禁止在 `call()` 中手写格式校验。
