## §1 概述

本卡片聚焦 AI Orz 工具系统的**安全边界与输出治理**——覆盖 HTTP/Builtin/MCP 三协议路由上的安全防护、工具输出过滤与脱敏、路径逃逸检查、SSRF 防护、环境变量白名单等关键机制。核心决策为：

1. **工具三分边界设计**：将工具安全划分为「协议层防护」（HTTP URL 模板校验 + SSRF DNS 钉扎）、「执行层隔离」（Shell 工作目录白名单 + 环境变量过滤 + HOME 用户隔离）、「输出层脱敏」（token/secret 行级过滤 + 大小截断 + 敏感头脱敏）三层防线。
2. **统一安全库**：`tool_security.rs` 作为工具安全的共用基础设施，提供 HTTP 防护、文件系统安全、脱敏工具等跨协议复用能力。
3. **就绪探测 + 安全引导一体化**：`tool_readiness.rs` 的就绪探测结果同时承担安全引导职责（CLI 未安装 / API key 缺失时返回结构化安装指引而非裸错误）。

## §3 架构约定

### 3.1 HTTP/Builtin/MCP 三协议路由 + 安全边界

工具安全沿协议路由在三个层级实施边界检查：

```
请求 → JWT 认证 → 角色鉴权 → RequestContext 注入
  → 协议路由分发：
    ├─ Builtin 协议 → 内部安全检查（白名单/路径/环境变量）
    ├─ HTTP 协议   → URL 模板校验 → SSRF DNS 钉扎 → 响应大小限制
    └─ MCP 协议   → 配置驱动（Stage 2 待完善）
  → 输出脱敏 → 大小截断 → 日志持久化
```

### 3.2 HTTP 协议安全边界

`tool_security.rs` 提供 HTTP 工具的核心安全函数：

- **`validate_target_url()`**：URL scheme 白名单（http/https）→ 域名白/黑名单匹配 → 本地网络拒绝（需显式 `allow_local_network=true`）→ DNS 解析后 IP 二次校验 → DNS 钉扎到客户端
- **`validate_url_template_boundary()`**：URL scheme 与 authority 必须固定，不允许模板占位符；禁止 userinfo credentials（`@`）
- **`validate_supported_placeholders()`**：仅支持 `{{args.key}}` 格式占位符
- **`read_limited_response_body()`**：响应体大小限制（默认 1MB，硬上限 10MB）
- **`sanitize_response_headers()`**：敏感头（Authorization/Cookie/token/secret/password）脱敏为 `[REDACTED]`

### 3.3 Builtin 协议安全边界

#### Shell Exec 安全

- **工作目录白名单**：仅允许 `base_data_path` 或配置的 `additional_allowed_paths`
- **用户身份边界检查**：`crosses_user_boundary()` 检测跨用户树访问，`crosses_agent_workspace()` 检测跨 Agent 工作区访问
- **环境变量白名单**：仅透传允许列表变量，过滤敏感变量名（home/user/password/token/secret/api_key/aws_access_key_id 等）
- **HOME 用户隔离**：注入 `HOME={base}/users/{user_id}`，git/gh 等 CLI 复用用户配置

#### Browser 安全

- **子命令白名单**：仅开放原子操作（open/read/snapshot/click/fill/screenshot 等），拒绝 eval/batch/keyboard/cookies/storage 类命令
- **会话隔离**：固定 `--session ai-orz-agent-{agent_id}`，Agent 间互不干扰
- **截图产物存储**：截图落统一产物存储（经 `ScreenshotStorer` 注入），返回 artifact 引用而非 base64 内嵌
- **spawn 不经 shell**：argv 直拼，无注入面

#### 搜索工具安全（Tavily + 豆包）

- **统一凭据机制**：GenericToken + platform 二元匹配，通过 `platform` 区分 tavily / doubao_search
- **snippet 截断**：Tavily snippet 上限 1000 字符；豆包 summary 上限 1000 字符
- **授权来源标记**：返回 `key_source` 字段区分授权来源
- **豆包搜索安全**：支持 web / web_summary / image 三种类型校验 + time_range 参数校验

#### GH CLI 安全

- **HOME 用户隔离**：`HOME={base}/users/{user_id}`，gh 配置落在 `{home}/.config/gh/`
- **Token 脱敏**：`sanitize_gh_output()` 按行过滤 token 前缀（gho_/ghu_/ghs_/ghr_/ghp_）与敏感关键字行
- **首次幂等登录**：token 走 stdin（避免进程参数泄露），marker 记录 token 指纹

#### Lark CLI 安全

- **HOME 用户隔离**：`HOME={base}/users/{user_id}`，lark-cli 配置落在 `{home}/.lark-cli/`
- **凭证脱敏**：`sanitize_lark_output()` 按行过滤 access_token/app_secret/secret_key/tenant_token/authorization 行
- **幂等 config 写入**：首次 `config init --app-secret-stdin`，secret 走 stdin 避免进程参数泄露

### 3.4 文件系统安全边界

`tool_security::fs` 子模块提供文件系统安全：

- **`resolve_and_validate_path()`**：路径规范化 → 符号链接拒绝 → 白名单范围检查 → 越界路径返回 `NeedConfirmation`
- **`is_sensitive_filename()`**：拦截 `.env/.pem/.key/.p12/.pfx/id_rsa/id_dsa/id_ecdsa/password/secret/token/credential/auth` 及隐藏文件
- **`crosses_user_boundary()`**：检测 `{base}/users/{other}` 跨用户树访问
- **`crosses_agent_workspace()`**：检测跨 Agent 工作区访问

### 3.5 就绪探测与安全引导

`tool_readiness.rs` 提供统一的结构化引导：

- **`cli_not_installed_json()`**：CLI 未安装时返回 `{error_code: "cli_not_installed", install, hint}` 结构化引导
- **`api_key_missing_json()`**：API key 缺失时返回 `{error_code: "api_key_missing", guidance}` 双路径引导（绑个人凭证 / 配共享 key）
- **TTL 缓存策略**：CLI 型按 `tool_id` 缓存，key 型按 `(tool_id, user_id)` 缓存，30 秒 TTL

### 3.6 输出脱敏汇总

| 工具 | 脱敏机制 | 截断策略 |
|---|---|---|
| browser | 子命令白名单硬拦截 | 输出按 `max_output_bytes` 截断，追加 `[truncated]` |
| shell_exec | 环境变量过滤 + 身份边界检查 | 默认 10MB 上限，超长截断摘要 + 完整日志落盘 |
| gh_cli | `sanitize_gh_output()` token/secret 行过滤 | 默认 1MB 上限，超长截断 |
| lark_cli | `sanitize_lark_output()` 凭证行过滤 | 默认 1MB 上限，超长截断 |
| tavily_search | GenericToken + platform 认证 | snippet 按 1000 字符截断 |
| doubao_search | GenericToken + platform 认证 | summary 按 1000 字符截断 |
| HTTP 工具 | 敏感头 `[REDACTED]` 脱敏 | 默认 1MB，硬上限 10MB |

## §4 硬约束

1. **路径逃逸检查必须在 IO 前执行**：`resolve_and_validate_path()` 返回的 `ValidationResult::NeedConfirmation` 必须阻断自动执行，转人工确认。
2. **工具输出过滤**：
   - **HTTP 响应大小**：默认 1MB，硬上限 10MB，超限必须拒绝而非截断。
   - **Shell 输出大小**：默认 10MB，超限截断摘要返回 + 完整日志落盘。
   - **CLI 工具输出**（gh_cli/lark_cli）：默认 1MB，超限截断。
   - **Browser 输出**：按 `config.max_output_bytes` 截断。
3. **环境变量白名单必须显式配置**：`ShellExecConfig.allowed_env` 为空时默认仅透传 PATH，禁止隐式透传全量环境变量。
4. **HOME 隔离必须按用户维度**：gh_cli/lark_cli/shell_exec 的 `HOME` 必须指向 `{base}/users/{user_id}`，禁止复用系统 HOME。
5. **Token 不得出现在进程参数中**：gh_cli/lark_cli 的 app_secret/token 必须通过 stdin 传递，禁止 `--token xxx` 方式。
6. **HTTP URL scheme 与 authority 必须固定**：禁止在 scheme/host 中使用 `{{}}` 模板占位符，仅路径/查询串部分允许。
7. **SSRF 防护必须覆盖 DNS 解析后 IP**：仅检查域名不够，必须在 DNS 解析后对 IP 再次校验是否为本地/私有网络。
8. **子命令白名单不得包含脚本执行类**：browser 工具白名单不得添加 eval/batch/keyboard 等脚本执行子命令。
9. **敏感文件名一律硬拦截**：`.env`、`.pem`、`.key`、`id_rsa`、隐藏文件等必须直接拒绝，不得降级为 NeedConfirmation。
10. **就绪探测异常不得阻塞调用**：探测器内部异常返回 `RuntimeReady::Unknown`，而非 Err，避免探测故障影响工具可用性。
11. **越界路径必须阻断自动执行**：`crosses_user_boundary()` 或 `crosses_agent_workspace()` 返回 true 时，必须设置 `require_confirmation: true`，禁止静默绕过。
12. **Browser close --all 必须拒绝**：`close --all` 会终止所有 Agent 会话，必须硬拒绝。
13. **截图产物不得内嵌 base64**：screenshot 结果必须通过 `ScreenshotStorer` 落统一产物存储，返回 artifact 引用。
14. **工具输出脱敏不得遗漏 token 前缀**：`sanitize_gh_output()` 必须覆盖 gho_/ghu_/ghs_/ghr_/ghp_ 所有 GitHub token 前缀。
15. **就绪缓存必须支持失效**：配置变更或安装完成后，必须通过 `invalidate_cache()` 清除对应工具的就绪缓存。
16. **搜索工具凭据统一走 GenericToken + platform**：Tavily 和豆包搜索不得使用独立凭据类型，必须通过 `(kind=GenericToken, platform)` 二元组匹配。
