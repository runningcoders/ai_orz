# 思考循环异常退出兜底总结与错误上报结构化

## §1 概述

AI Orz 的 think 循环（`run_think_loop`）有两条退出总结路径：(a) **正常退出**（Final 输出 / 轮次耗尽 / 上下文溢出）→ 由 `compact_context` 再发起一次 LLM 调用让模型自己归纳，写入短期记忆；(b) **异常中断**（429 限流 / 5xx / 超时 / 用户主动取消）→ 本次新增的 `abort_summary.rs` 兜底模块提供**完全不依赖 LLM 的规则化拼接**，保证已完成的进度不会蒸发。核心设计哲学：循环之所以异常退出往往正是因为 LLM 调不通，此时再发起 `compact_context` 大概率同样失败，因此框架必须提供一条保底路径让 Agent 下次唤醒时能从记忆里看到「上次做到哪一步、为什么断了」。

## §2 关键文件表

| 文件 | 职责 |
|------|------|
| `src/service/domain/runtime/abort_summary.rs` | **本次新增**：纯函数 `build_abort_summary` 规则化拼装兜底摘要；`finalize_abort` 写 trace + 落库短期记忆；`attach_abort_notice` 把进度概览挂到 Error.field.extra |
| `src/service/domain/runtime/think_loop.rs` | 共享 think loop 引擎；进度快照（`record_round`）在**每轮工具执行完后**立即落袋，为中断兜底提供数据源；与 abort_summary 的分工在 L340-L356 的注释里对比说明 |
| `src/service/domain/runtime/awakening.rs` | awaken 调用点：think_loop 失败时从 `?` 错误传播转为 `finalize_abort` 调用 |
| `src/consumer/message.rs` | `notify_agent_failure` 消费者：从 Error.field.extra 里取 `abort_notice`，把进度概览附在失败通知里告诉用户「工作没白做」 |

## §3 架构约定

- **AbortKind 二分**：`Error`（模型错误 / 超时）vs `Cancelled`（用户主动取消）。摘要措辞分开表述，避免下次 Agent 读到"被取消"误判成故障。
- **进度快照位置**：`think_loop.rs` L394-L412 —— 放在「工具执行完、策略评估前」，保证每一轮已完成的工具调用都不漏记。下一轮 `brain_dal().think()` 失败时本轮已落袋。
- **字符预算**：`SUMMARY_BUDGET_CHARS = 12_000`（L52），`pick_rounds_within_budget` 从最近一轮往前挑直到用尽预算（L136-L151），优先保留**最近**的轮次而非最早的——对接续更有价值的是"最后一刻做到哪了"。
- **全链路尽力而为**：trace 写失败、记忆落库失败只记 warn 返回 `memory_id: None`，兜底本身绝不能成为新的失败源（L353-L356 的注释强调）。
- **不改运行时状态**：`finalize_abort` 只做存档，`BusyGuard` 负责收尾（L25-L27）。

## §4 硬约束

1. **进度快照必须在工具执行后立即落袋**：think_loop.rs L394-L412 位置刻意选在工具执行完、策略评估前，是保证中断兜底数据源的前提。如果放到策略评估后再记录，429 等错误传播 `?` 时本轮快照就丢了。
2. **兜底摘要必须独立于 compact_context**：abort_summary 的拼接逻辑**不能**调 LLM（模块 doc comment L5-L13 明确），否则在 LLM 不通的场景下同样失败。
3. **错误语义不变**：`attach_abort_notice` 只往 `Error.field.extra` 里追加一个 `abort_notice` key，不覆盖现有 extra 内容，不改变 code / msg / error_type（L314-L315 的注释）。
4. **记忆 tag 区分**：压缩记忆是 `["compaction"]`，中断存档是 `["loop_abort", "error"|"cancelled"]`，两者写入同一张表但 tag 可区分（L349-L350）。
