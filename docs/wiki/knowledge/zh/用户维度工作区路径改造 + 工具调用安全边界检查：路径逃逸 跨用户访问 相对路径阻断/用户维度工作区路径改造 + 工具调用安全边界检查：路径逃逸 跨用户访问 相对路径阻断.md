# 用户维度工作区路径改造 + 工具调用安全边界检查

## §1 整体方案

6b883e37 变更落地两个核心安全改造：

1. **用户维度工作区路径改造**：项目根目录统一规范为 `{AI_ORZ_HOME}/workspace/{user_uid}/{org_id}/`（取代之前的全局 `{AI_ORZ_HOME}/workspace/{org_id}/` 共享目录——之前同一 org 下所有用户的 working files 混在一起，Agent A 能随便读 Agent B 上载的 attachment）；同时拆分子目录：`uploads/`（用户前端上传的原始文件）、`agent_outputs/`（Agent 运行产生的临时产物）、`shared/`（org 级共享、显式标记共享）、`attachments/`（task/project 绑定的附件，元数据进 DB，物理文件在 user 目录下）。
2. **工具调用安全边界检查**：在 3 个涉及文件系统的 Builtin 工具（`shell_exec` / `file_read` / `file_write`）的 invoke 入口处，加入**路径规范化 + 前缀白名单校验**，防止 `../` 路径逃逸 / 绝对路径裸访问 / 跨 user 目录访问。`canonicalize(path)` 后的真实路径必须是 `{user_workspace_dir}` 或 `{shared_dir}` 的子树前缀命中——否则返回工具错误「SecurityBoundary: path escape detected」，工具拒绝执行。

双重隔离 = 存储层（目录结构拆分）+ 工具层（BoundaryChecker 前缀校验），即使目录结构未来改了、BoundaryChecker 也能作为第二道防线；反之即使 BoundaryChecker 有 bug、目录结构 user 分离也降低跨用户损害半径。

## §3 架构约定

1. **路径构造统一出口 = src/pkg/paths.rs（§3.2.1 基础设施工具位置约定）**：整个代码库任何业务代码，**禁止**手写 `format!("workspace/{}/{}/uploads", uid, org_id)` 字符串拼路径——工作区路径的唯一构造源是 paths.rs 暴露的函数；未来如果路径再调整（比如改 `workspace/v2/{uid}/{org}`）只改 paths.rs 一处，全库 60+ 处调用零修改。
2. **SecurityBoundaryChecker 类型屏障（新类型防止绕过）**：下游文件 IO 函数（storage/local_file.rs 内部 write_file / read_file 签名）只接受 `CleanPath`（sandbox.rs 定义的 newtype 包装，私有 inner 字段）——**没有公开的 From<String> / From<PathBuf> impl**，只能通过 `SecurityBoundaryChecker.enforce() -> Result<CleanPath>` 得到——从类型系统层面保证路径未经过 enforce 无法做 IO（不是靠「代码审查相信大家都调用 enforce」，而是**编译期不允许**）。
3. **shell_exec 的 cwd 与子进程执行目录严格绑定**：cwd enforce 通过后 → 子进程 `Command::new(script).current_dir(clean_path.inner())`；**绝对禁止** shell 脚本里执行 `cd / && rm -rf *` 后再 `cd 回` 这种裸 cd；如果 Agent 想切到工作区内子目录，用 `subdir: "project-a"` 相对路径参数，BoundaryChecker 内部 `user_workspace.join(subdir)` → enforce → 设置 current_dir。
4. **AI_ORZ_HOME 环境变量的根路径只读保护**：paths.rs 中 `fn ai_orz_root() -> PathBuf` 取 AI_ORZ_HOME 环境变量（或 default `~/.ai_orz/`）后，测试 `workspace_write_gate_test` 保证 SecurityBoundaryChecker.enforce 对 `ai_orz_root` 本身（非 workspace 子目录）——也返回拒绝。**即使用户把 AI_ORZ_HOME=/etc，BoundaryChecker 也阻止 Agent 写 /etc/passwd（虽然 cwd 不影响子进程的其他路径，但 shell_exec 的 cwd 不落在 workspace 内就已拦截）**。
5. **跨用户文件访问只有显式 shared_dir 白名单**：shared_dir(org_id) 是「同一个 org 内所有用户都可读」的唯一例外目录——A 用户上传的文件想让 B 用户的 Agent 看到，必须走「上传 → shared_copy API → 复制到 shared_dir 并在 attachment DB 标记 shared=true」；shared_dir 的写权限是 Admin 以上（Member 用户 Agent 只能读 shared_dir，写被 BoundaryChecker 标记的 write_only_user_dirs gate 拦截）。

## §4 路径 SSOT 重构（4859bcf6）

### config.rs 路径方法精简

AppConfig 从 20+ 路径方法缩减为 3 个：
- `base_data_path()` — 唯一保留的根路径 getter
- `config_path()` — 配置文件路径
- `log_dir()` — 日志目录路径

其余 20+ 路径方法（attachments_dir / artifacts_dir / agent_data_dir / skills_dir / tools_dir / memory_dir 等）**全部删除**，调用方改为使用 `pkg::paths` 纯函数族。

### paths.rs 扩展为 33 个纯函数

paths.rs 从原有的用户维度路径函数集扩展为覆盖全量路径布局的 SSOT：

**用户维度路径（users/{uid}/ 下）**：
- `user_home(base, uid)` → `users/{uid}`
- `user_shared_workspace(base, uid)` → `users/{uid}/shared`
- `user_project_root(base, uid, pid)` → `users/{uid}/shared/projects/{pid}`
- `user_project_workspace(base, uid, pid)` → `users/{uid}/shared/projects/{pid}/workspace`
- `user_agent_workspace(base, uid, aid)` → `users/{uid}/agents/{aid}/work`

**系统/Agent 共享路径**：
- `users_root_dir(base)` → `users`
- `agent_data_dir(base, aid)` → `agents/{aid}`
- `agent_workspace(base, aid)` → `agents/{aid}/work`
- `agent_memory_dir(base, aid)` → `agents/{aid}/memory`
- `attachments_dir(base)` → `attachments`
- `artifacts_dir(base)` → `artifacts`
- `artifact_project_dir(base, pid)` → `artifacts/projects/{pid}`
- `artifact_path(base, pid, aid)` → `artifacts/projects/{pid}/{aid}`
- `vectors_dir(base)` → `vectors`
- `sqlite_db_path(base, name)` / `vector_sqlite_db_path(base, name)` → 数据库文件
- `lance_vector_dir(base)` / `hnsw_index_dir(base, name)` → 向量索引目录
- `stats_db_path(base, name)` → 统计数据库
- `tools_root_dir(base)` / `tool_call_trace_dir(base, tid)` / `tool_logs_dir(base, tid)` → 工具日志
- `skills_root_dir(base)` / `shared_skill_dir(base, sid)` / `agent_skill_dir(base, aid, sid)` → 技能目录
- `seeds_dir(base)` → 种子目录
- `default_workspace(base, uid, aid)` → 按上下文选默认工作区

**关键设计约定**：
- 所有函数第一个参数统一为 `base_data_path: &Path`，不隐式依赖 `config::get()`，保持可独立测试性
- 分为「用户维度路径」（`user_` 前缀，参数带 `user_id`）和「系统/Agent 共享路径」（无前缀，参数只有 `agent_id` 或无子参数）两大类
- 33 个函数全部是纯函数，无副作用，输入相同 base 总是产出相同路径

### PromptBuilder workspace_context 路径注入

与路径 SSOT 同步，PromptBuilder trait 新增 `workspace_context` 方法：
- trait 声明在 `src/models/prompt_builder.rs#L61-L90`
- DefaultPromptBuilder 实现在 `src/service/dal/agent/mod.rsL1465`
- 渲染为 Prompt 中的【工作空间与路径约定】区块（line 1032-1048）
- 覆盖场景：awaken 主流程 / sleep_and_settle / intent_analyze / awaken_for_summary

## §5 约束清单（最高权重，硬红线）

1. ❌ **禁止业务代码手工拼工作区路径字符串**：`grep "workspace/" src/`（paths.rs 自身除外）应 0 命中；任何业务模块里的 `format!("workspace/...")` 必须改成 `paths::xxx_dir(ctx, org_id).join(...)`；CI 有 docs_lint 外的独立工作区路径 grep 检查——违反直接 fail。
2. ❌ **禁止 CleanPath 暴露 From<PathBuf> 或 inner() 后随意修改**：CleanPath 的 inner 字段是 `pub(crate)` 级别，**外部 crate 无法构造**；下游拿到 CleanPath 后不能做 `.join("../")` 等修改再转成新的 CleanPath——任何路径变更后必须重新 enforce（从类型系统保证）。
3. ✅ **强制路径逃逸攻击测试矩阵 12 条全覆盖**：6b883e37 集成测试 `workspace_escape_test_matrix` 包含：① `../../etc/passwd` ② 绝对路径 `/root/.ssh/id_rsa` ③ 符号链接 ln -s /tmp workspace/symlink_tmp ④ Unicode 归一化 `..%2F..%2F` ⑤ Windows 风格 `..\\..\\` ⑥ 嵌套多重 `a/b/../../c/d/../../etc` ⑦ 尾部加斜杠 + 空格 ⑧ 多字节字符路径 ⑨ 先执行 `cd /tmp` 再用相对路径写（cwd enforce 后才设置 current_dir）⑩ symlink 链（A→B→C→/etc）⑪ file_write 试图写 `../../../etc/motd` ⑫ shell_exec 试图 `cwd = "/proc"` —— 12 条全返回 SecurityError 才算 pass（漏 1 条 = fail）。
4. ✅ **强制 60+ 引用全量修正验证**：grep 整个 src/ 目录「paths:: 目录函数」用法，paths.rs 暴露的 user_uploads_dir / agent_outputs_dir / shared_dir / user_attachments_dir 4 个函数——每个函数至少有 1 处调用（证明 6b883e37 真的替换了旧手工拼接，而不是新函数写了无人用）；同时旧的 `format!("workspace/{}", org_id)` 模式 0 命中。
5. ❌ **禁止 file_read/file_write 工具在 BoundaryChecker 外部直接调用 std::fs**：工具内部 IO 必须通过 `storage::read_file(clean_path: CleanPath)` 或 `storage::write_file(clean_path: CleanPath, content)`——这两个函数签名只接受 CleanPath，从类型系统阻断。
