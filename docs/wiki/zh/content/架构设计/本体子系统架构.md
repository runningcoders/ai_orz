## 简介
本体（ontology）是 AI Orz 知识图谱的**模式层（TBox）**：受控词表（实体类 + 关系词 + 同义映射）、属性定义、骨架三元组三部分组成「允许说什么」的声明面；漂移看板与属性有效性构成「说得怎么样」的治理面。业务代码写图谱（ABox）时受它约束，读侧工具把词表裁成视图注入 prompt。规模约 111 个源文件 / 1.17 万行，横跨 Adapter → Domain → DAL → DAO 四层，外加 common 契约与前端面板。

## 为什么本体不是业务模块
本体不承载具体业务动作（不记账、不发消息、不派任务），它只提供两类能力：**约束**（写之前判断合法性）与**解释**（读的时候说明这个节点/关系是什么词、属于哪个类）。因此它的落点贯穿所有写图谱和读图谱的代码，而不是集中在某个业务域里。

## 四条能力线
| 能力线 | 解决什么 | 主落点 |
|--------|----------|--------|
| 受控词表 | 实体类 / 关系词 / 同义映射的唯一声明源；prompt 注入时按 token 预算裁剪 | `src/service/dal/ontology.rs`、`src/service/dao/ontology/` |
| 属性定义 + 写入期门闩 | 属性挂载时逐条体检，越界记账不阻断 | `src/service/dal/memory/properties.rs`、`common/src/ontology_property.rs` |
| 骨架三元组 | 「类 -关系→ 类」形状声明，写边前校验；不匹配只记漂移 | `src/service/dao/ontology/` |
| 治理看板 | 关系词覆盖率、属性域覆盖率、属性有效性（众数占比） | `src/service/dal/ontology.rs`、`src/handlers/hr/ontology/` |

## 写入期五道门闩
| 门闩 | 判据 | 触发结果 |
|------|------|----------|
| 0 | 属性未在本体定义 | 软：记 `UndefinedProperty`，按值自身类型兜底写入 |
| 1 | 载体不匹配（`applies_to`：node / relation） | 软：记 `TargetNotAllowed`，照写 |
| 1.5 | 实体类不在 `domain_classes`（空清单 = 不限） | 软：记 `DomainClassNotAllowed`，照写 |
| 2 + 3 | 值类型 / 值域（枚举白名单、数值区间） | 类型错硬拒；值域越界软 |
| 4 | 基数（单值冲突 / 超上限） | 硬：记 `CardinalityExceeded` 并跳过该条 |

软门禁的产出是 `PropertySaveReport.issues`：写入者当场就能看到「哪条属性因为什么被判越界」，可以立刻自纠；硬拒只留给「数据不可解释」的情形。

| DAL | `src/service/dal/ontology.rs`（1,335 行） | 组合 DAO、内存聚合与纯函数判定（覆盖率、有效性、漂移解析） |

| 契约 | `common/src/api/ontology.rs`（935 行）、`common/src/ontology_property.rs`（503 行） | 前后端唯一 DTO 来源，前端不重复定义 |

分层红线与全项目一致：Handler 不做业务规则、Domain 不直连 DAO、DAL 不写 SQL。

## 治理看板口径
| 指标 | 口径 | 阈值 |
|------|------|------|
| 关系词覆盖率 | 命中规范词 + 同义归并的关系数 ÷ 全部关系数 | — |
| 属性域覆盖率 | 域内属性值 ÷ 全部属性值（strict：属性与节点均未删除） | 低于 0.95 告警 |
| 属性有效性 | 按「属性 × 实体类」分组，取众数占比 `mode_ratio` | 高于 0.90 标黄（提示该属性已退化成近似常量） |

当前实测：属性域覆盖率 1,103 / 1,227 = 0.8989（告警为真）；属性有效性 91 组中 51 组标黄。

## 设计取向与常见误读
- **软门禁优先**：记录而不阻断，让不合规成为可见、可计数、可归因的证据；硬拦仅在类型错与基数冲突时使用。
- **漂移不是错误**：它是「词表映射缺口」的记账，补同义映射即自动愈合；因此写侧只记原文、不阻断写入。
- **默认值取众数而非枚举首值**：有效性指标的口径是「实际退化程度」，按枚举首值会算反方向。
- 常见误读：把 `domain_classes` 当成硬约束（实际是软记账）；把属性有效性当成「使用率」（实际是「单一值占比」）。

## 结论
本体子系统的价值不在「拦住多少写入」，而在**把图谱的词、属性、关系形状变成可声明、可校验、可度量的一层**。它与记忆子系统的分工是：记忆决定「写什么进来」，本体决定「写进来的东西叫什么、能不能这样连」。
