## 架构总览
AOP 事件中心提供统一的发布-订阅与异步调度能力。业务消费者通过实现 Consumer trait 声明感兴趣的事件类型与消费模式（Sync/Async）。Registry 负责：
- 注册消费者与生产者
- 事件序列化与元数据注入（event_id、kind、order_key、priority、created_at）
- 同步直接调用 on_event，或异步入队由 worker 拉取
- 维护 ack/nack 语义，驱动重试与去重
- 启动多 worker 并发消费，支持空队列休眠与错误退避

## 详细组件分析

### 消息消费者（MessageConsumer）
- 事件订阅：message.created
- 路由策略：根据 Message.to_role 分派到 Agent/User/System 三种处理路径
- 幂等与确认：
  - ack：将消息状态更新为已处理
  - nack：将消息状态回滚为待处理，触发重试
- 并发与退避：concurrency=4，空队列休眠 100ms，错误重试休眠 1000ms
- 关键处理逻辑：
  - Agent 消息：原子占用 Agent（避免 TOCTOU），经**唤醒前置门闩**裁决是否唤醒，必要时唤醒 Agent Brain 并调用 awaken
  - User 消息：投递给用户，所有渠道失败时返回错误以触发重试
  - System 消息：解析 ToolCallRequest，构造 RequestContext，调用 RuntimeDomain 执行工具并将结果回写

### 唤醒前置门闩（wake_gate_policy）

「这条消息要不要唤醒 Agent」的前置校验被抽成策略引擎的一个领域落地（`src/consumer/wake_gate_policy.rs`），与 Final 回发路由的 `message_route_policy` 同目录同范式：**keys 常量 → 领域 matcher → 声明式规则表 → `OnceLock` 静态规则集 → `judge_wake_gate()` 出口**。

规则表按 Or 组组合，**声明顺序即优先级，首个命中即决策**：

| 规则 id | 判据 | 命中后果 |
|---|---|---|
| `task_terminal` | 任务已 `Completed` / `Cancelled` / `Archived` | 跳过（日志 info） |
| `dependency_unmet` | `TaskAssignment` 的前置任务未全部 `Completed` | 跳过（日志 info，附未完成 id） |
| `dependency_stale` | 前置任务已 `Cancelled` / `Archived`，永远不会完成 | 跳过 + **`log_warn`（死锁信号，需人工介入）** |
| `wakeup_budget_exhausted` | 该 Agent 在该任务上累计唤醒次数达 `max_thinking_depth` | 跳过 + **通知来源方**（合法停止，来源方需知道为什么停） |

三条设计约束：

- **查库只在适配器**：`build_wake_gate_input` / `classify_dependencies` 负责把 task、前置任务状态查出来填进 `Metrics`，策略表零查询、零副作用。
- **保守优先**：查不到的前置（`Ok(None)` 脏数据 / `Err` 查询失败）一律按「未完成」处理并打 warn，宁可多等一轮也不误判 DAG 就绪。
- **只拦派发不拦对话**：依赖判据仅对 `MessageType::TaskAssignment` 生效；用户对任务的追问、Agent 协作汇报即便 `task_id` 非空也照常唤醒。
- **动态阈值不用 `ThresholdPolicy`**：其构造函数含 `Box::leak`，消息路径每请求 new 一次即漏一次内存；因此 `wakeup_budget_exhausted` 实现为领域专用策略，从 `Metrics` 双键读当前值与 Agent 级上限。

⚠️ **跳过不等于丢弃**：AOP 只有 `Retry / Discard` 两档重投决策，**没有延迟重投**——`return Ok(())` 即 ack 终结。后继任务的推进责任由 `TaskEventConsumer::dispatch_ready_successors` 在前置完成时补发，详见「任务事件消费者」长文。三个动作必须成对存在，缺一即任务永久 Pending 且不报错。

## 性能与背压
- 并发与吞吐
  - MessageConsumer 设置 concurrency=4，适合中等吞吐的消息处理
  - 其他统计类消费者采用 Sync 模式，轻量且不阻塞主流程
- 背压与退避
  - 空队列休眠：empty_queue_sleep_ms=100ms，降低空转 CPU
  - 错误重试休眠：error_retry_sleep_ms=1000ms，避免紧密自旋
  - Registry 在 on_event 失败后主动 sleep，防止 nack 后立即被重新取出导致抖动
- 批处理
  - 当前消费者未实现显式批处理；如需提升吞吐，可在消费者内部聚合多条事件后批量调用 Domain/DAO
- 资源保护
  - Agent 占用采用 try_set_busy 原子操作，避免并发冲突
  - 对已完成/取消/归档的任务直接跳过唤醒，减少无效计算

## 故障排查指南
- 常见问题定位
  - 消息未处理：检查消费者是否已注册（consumer::init）、事件类型是否正确、should_consume 是否过滤
  - 重复处理：检查 ack/nack 是否成对调用；Registry 会在成功时调用 queue.ack，失败时调用 queue.nack
  - 卡死或堆积：查看队列长度与事件详情（Registry::queue_len / query_events / get_event）
  - Agent 忙碌：检查 try_set_busy 失败原因与 busy/idle 状态清理路径
- 诊断手段
  - 使用 Registry 提供的队列统计与事件查询接口定位具体事件
  - 结合日志（tracing/sys_info/sys_debug）追踪事件流转与错误堆栈
  - 对超时或慢处理场景，调整 empty_queue_sleep_ms 与 error_retry_sleep_ms
- 恢复策略
  - 对于临时错误（如网络/DB 异常），保持 nack 以触发重试
  - 对于永久错误（如实体不存在），返回非重试错误并清理资源（如释放 busy）
- **Agent 收到消息但没有任何反应（门闩跳过）**
  - 在日志里找 `handle_agent_message` + `wake skipped`，括号内是命中的 policy id：`task_terminal` / `dependency_unmet` / `dependency_stale` / `wakeup_budget_exhausted`。
  - `dependency_stale` 是 `warn` 级——说明前置任务被撤销或归档，这次等待永远不会结束，**需人工解除**（改依赖或重派），不会自动恢复。
  - `dependency_unmet` 是 `info` 级且**属正常排队**：后继任务会在前置 `Completed` 时由 `TaskEventConsumer::dispatch_ready_successors` 自动补发。若最终没被执行，去查那个消费者而不是这里（详见「任务事件消费者」长文故障排查节）。
  - `wakeup_budget_exhausted` 会同时给来源方发一条通知消息；没收到这条通知说明通知本身失败了（不阻塞停止流程，只记 warn）。
  - 若日志里**完全没有** `wake skipped`，说明门闩未命中——此时问题不在门闩，继续按既有的唤醒链路排查（Busy 占用、模型调用、Brain 就绪）。
  - 只想临时放行而不改代码：把该任务的前置依赖清空（`dependencies` 置空）会让判据直接落空，但会破坏 DAG 语义，仅作应急手段。

## 结论
消息消费者基于 AOP 事件中心实现了高内聚、低耦合的事件处理体系。通过明确的路由与分发逻辑、完善的 ack/nack 语义、合理的并发与退避策略，以及去重与补偿机制，保障了消息处理的可靠性与可观测性。后续可根据业务规模引入批处理与更细粒度的背压控制，进一步提升吞吐与稳定性。

- 消费者配置要点
  - 消费模式：Sync/Async（影响是否入队与 worker 调度）

  - 与 RequestContext：统一传递组织、项目、任务、用户等上下文
