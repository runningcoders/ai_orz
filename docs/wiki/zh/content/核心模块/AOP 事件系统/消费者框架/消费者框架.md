## 简介
本框架基于 AOP 事件中心提供统一的生产者-消费者模型，用于解耦业务模块、实现可靠的事件驱动处理。消费者通过实现 Consumer trait 声明感兴趣的事件类型、消费模式（同步/异步）以及并发与重试策略；注册中心负责分发事件、维护队列、调度 worker 并采集指标。内置消费者覆盖消息投递、定时任务、Agent 循环日志、工具执行统计等关键场景。

## 项目结构
消费者相关代码主要分布在两个层次：
- 框架层（pkg/aop）：定义 Event、Consumer、Registry、EventQueue 抽象及内存队列实现，提供发布、订阅、调度、ack/nack、指标钩子能力。
- 业务层（consumer）：实现具体消费者，将事件编排到 Domain/DAL/DAO，完成 Agent 唤醒、消息投递、统计落库等。

## 核心组件
- ConsumeMode：同步（Sync）与异步（Async）两种消费模式。同步在发布线程直接调用 on_event；异步入队后由 Registry 启动的 worker 拉取处理。
- Consumer trait：声明 name、interested_events、consume_mode、on_event，以及可选的 should_consume、ack、nack、concurrency、empty_queue_sleep_ms、error_retry_sleep_ms。
- Registry：全局注册中心，维护消费者索引、每个异步消费者的独立队列、生命周期管理与指标 Hook 注入。
- InMemoryEventQueue：内存队列，支持按 order_key 顺序、优先级与创建时间排序，维护 pending/in_progress 状态，提供 ack/nack/stats/query。

## 架构总览
事件从生产者发出后，Registry 根据事件类型路由到对应消费者；同步消费者立即处理，异步消费者入队并由 worker 循环拉取，成功则 ack，失败则 nack 并退避重试。队列保证同 order_key 的顺序性与单活消息，避免重复处理导致的竞争。

```mermaid
R->>Q : enqueue(event)
loop 轮询
W->>Q : dequeue_next()
Q-->>W : event?
W->>C : on_event(event)
alt 成功
C-->>W : Ok
W->>R : ack(consumer, event_id)
else 失败
C-->>W : Err
W->>R : nack(consumer, event_id)
W->>W : sleep(error_retry_sleep_ms)
end
end
end
```

## 详细组件分析

### 消费者抽象与选择策略
- 同步 vs 异步选择：
  - 轻量、非阻塞、可容忍失败的侧写（如日志、统计）使用 Sync。
  - 重任务、需要可靠性与重试（如消息投递、Agent 唤醒）使用 Async。
- 过滤与元数据：should_consume 可在进入 on_event 前进行快速过滤；事件 JSON 会注入 event_id/kind/order_key/priority/created_at 供监控与队列使用。
- 并发与退避：concurrency 控制 worker 数量；empty_queue_sleep_ms 控制空轮休眠；error_retry_sleep_ms 控制失败重试间隔。

### 消息消费者（Agent 唤醒/用户投递/工具回调）
- 事件：message.created
- 模式：Async，并发 4
- 职责：
  - 解析 MessageCreatedEvent，加载完整 Message。
  - 按 to_role 分发：Agent → RuntimeDomain.awaken；User → MessageDomain.deliver_message；System → 工具调用请求处理。
  - ack/nack 更新消息状态为 Processed/Pending。
- 关键保障：
  - 原子占用 Agent（try_set_busy），避免多 worker 同时唤醒同一 Agent。
  - 任务完成/取消/归档时跳过唤醒，防止向已结束任务发送误导信息。
  - 达到最大思考深度时通知用户并释放 Busy。
  - 所有渠道投递失败返回错误以触发重试。


## 性能与资源管理
- 并发控制：通过 Consumer.concurrency 调整 worker 数，避免过度并行导致资源争用。
- 退避策略：empty_queue_sleep_ms 降低空轮 CPU 消耗；error_retry_sleep_ms 避免失败紧密自旋。
- 顺序与去重：order_key 保证同 key 顺序消费；队列维护 has_active_message 与 in_progress，避免重复处理与死锁。
- 指标采集：通过 AopMetricsHook 在 publish 与 consume 阶段埋点，结合前端 Gauge 可视化队列健康度。
- 资源清理：ack 成功后从队列移除事件；nack 失败重新入队等待重试；Registry 启动幂等，避免重复启动。

## 故障排查指南
- 消息未消费：
  - 检查消费者是否正确注册（consumer::init）。
  - 确认 interested_events 包含目标事件类型。
  - 查看队列 stats 与前端 Gauge 的 pending/in_progress。
- 消息卡住（同 order_key 后续消息不推进）：
  - 确保 on_event 成功后调用 ack，并在 Registry 中调用 queue.ack；否则 in_progress 不会释放，has_active_message 永远 true。
- 频繁重试：
  - 检查 on_event 是否抛出临时错误；适当增大 error_retry_sleep_ms。
  - 若为永久错误（如实体不存在），应返回非重试错误以避免无限重试。
- 指标缺失：
  - 确认已设置 metrics hook（set_metrics_hook），并在 publish/consume 路径有埋点。

## 结论
该消费者框架通过统一的 Consumer 抽象与 Registry 调度，实现了高内聚、低耦合的事件驱动架构。内置消费者覆盖了消息、定时、Agent 循环、工具执行与统计等关键场景；内存队列提供了顺序、优先级与重试能力；指标钩子与前端仪表盘形成闭环监控。遵循同步/异步模式的选择策略与并发/退避配置，可在保证可靠性的同时获得良好性能。

## 附录：自定义消费者开发指南
- 接口实现要点：
  - 实现 Consumer trait：name、interested_events、consume_mode、on_event。
  - 如需过滤事件，重写 should_consume。
  - 异步消费者需实现 ack/nack，合理设置 concurrency、empty_queue_sleep_ms、error_retry_sleep_ms。
- 测试方法：
  - 使用 Registry 的 publish/dequeue_for/ack/nack 编写单元测试，验证同步与异步路径。
  - 针对顺序键场景，构造相同 order_key 的事件，验证顺序与单活。
- 部署配置：
  - 在应用启动时调用 consumer::init 注册消费者。
  - 如需指标，注入 AopMetricsHook（例如 AopStatsHook）。
  - 通过前端 aop_gauge 观察队列健康度与延迟。
