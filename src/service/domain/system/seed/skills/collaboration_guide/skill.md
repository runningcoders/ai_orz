# Agent 协作指南

本指南帮助你与其他 Agent 和用户高效协作，合理委派任务、通信交流、管理产物。

## 任务委派

当任务超出你的能力范围或需要并行处理时，用 `send_task_assignment_message` 向其他 Agent 分配任务。

### 委派原则
- **明确边界**：委派时清晰描述任务目标、输入和预期输出
- **能力匹配**：根据目标 Agent 的角色和技能选择合适的委派对象
- **避免重复**：委派前确认任务尚未被其他人处理
- **追踪状态**：委派后关注任务进展，及时跟进

### 委派流程
1. 用 `query_users` 或查看项目成员了解可用的协作 Agent
2. 用 `send_task_assignment_message` 发送任务，包含清晰的需求描述
3. 目标 Agent 接收后处理，结果通过消息返回
4. 收到结果后确认并整合到当前工作

## 消息通信

### 发送消息
用 `send_message` 向用户或其他成员发送消息：
- 汇报工作进展
- 请求 clarification 或确认
- 通知重要事件或状态变更

### 查看历史
用 `list_messages` 查看历史消息：
- 了解上下文和之前的讨论
- 追踪任务流转
- 避免重复沟通

## 产物管理

协作中产生的工作成果应保存为产物，便于团队共享和追溯。

### 创建产物
- `create_text_artifact` — 文本内容直接保存（≤1MB），适合报告、方案、代码片段
- `register_artifact_from_path` — 从工作目录文件注册，适合已生成的文件

### 更新产物
用 `update_artifact` 更新产物的内容或元数据：
- 内容迭代时更新内容
- 补充描述、调整标签时更新元数据
- 支持乐观锁 `expected_updated_at` 防止并发冲突

### 查询产物
用 `query_artifacts` 查询项目产物：
- 按 project_id / task_id / file_type / source_type 过滤
- 了解团队成员已完成的工作
- 避免重复创建已有产物

### 文件安全
- 你只能操作自己工作目录 `agents/{你的ID}/` 下的文件
- `register_artifact_from_path` 会复制文件到产物存储，源文件保留
- 不要尝试访问其他 Agent 的目录

## 协作场景

### 场景一：分工合作
多个 Agent 共同完成一个项目时：
1. 明确各自负责的模块
2. 用 `send_task_assignment_message` 委派子任务
3. 各自完成后用 `create_text_artifact` 保存成果
4. 用 `send_message` 同步进展和依赖

### 场景二：能力互补
遇到不擅长的领域时：
1. 用 `query_users` 查找有相关能力的 Agent
2. 委派任务并说明需求
3. 收到结果后整合，必要时用 `update_artifact` 补充

### 场景三：知识传递
完成任务后沉淀知识供团队复用：
1. 用 `save_short_term_memory` 记录经验
2. 定期 `settle_memory` 沉淀为长期知识
3. 重要方案用 `create_text_artifact` 保存为产物
4. 用 `send_message` 通知团队成员

## 行为准则

1. **主动沟通**：遇到模糊需求时主动询问，不要自行假设
2. **及时反馈**：任务进展、阻塞、完成都应及时通知相关方
3. **成果留痕**：重要工作保存为产物，不要只存在对话中
4. **尊重边界**：不越权操作其他 Agent 的资源，通过委派和消息协作
5. **闭环负责**：委派出去的任务要跟进结果，接受的任务要按时完成并回复
