# 记忆管理指南

本指南帮助你有效使用平台的四层记忆系统，积累经验知识，提升长期工作能力。

## 记忆四层模型

平台记忆对齐人类认知机制，由四层组成：

| 层 | 类型 | 写入方式 | 用途 |
|---|------|---------|------|
| 核心记忆 | soul / capabilities | 配置定义 | 人格、能力声明，每次请求携带 |
| 工作记忆 | Trace（每日文件） | 系统自动记录 | 当前会话原始对话与思考，客观不可变 |
| 短期记忆 | ShortTerm | 主动调用工具保存 | 思考过程中总结的摘要 |
| 长期知识 | KnowledgeNode + Relation | 休息时自动沉淀 | 结构化知识图谱，支持关系遍历 |

## 短期记忆（主动保存）

思考过程中遇到重要信息时，用 `save_short_term_memory` 主动保存摘要。

### 使用时机
- 用户提供了重要需求或约束
- 完成了一个关键决策或判断
- 发现了值得记录的经验或模式
- 会话即将结束，需要总结

### 保存建议
- 写**摘要**而非原文（原文由 Trace 自动记录）
- 附带 `tags` 便于后续检索（如 `["需求", "用户偏好"]`）
- 关联 `trace_ids` 以便溯源到原始对话

## 长期知识图谱（自动沉淀）

当短期记忆积累到一定量时，调用 `settle_memory` 触发沉淀：

1. 系统获取近期短期记忆
2. 用 LLM 归纳总结为知识节点（KnowledgeNode）
3. 通过向量相似度检测冲突（>0.85 视为同一知识，合并更新；<0.85 新建节点）
4. 自动建立节点间关系（RelatedTo / Contains / DependsOn 等）

### 沉淀时机
- 连续工作多轮后
- 完成一个复杂任务后
- 感觉短期记忆过多需要整理时

### 主动创建知识节点
除了自动沉淀，你也可以用 `save_long_term_memory` 主动创建知识节点并建立关系：
- 明确学到新知识时直接创建
- 可同时创建节点间关系（如"A 依赖于 B"）

## 记忆搜索

用 `search_memory` 检索记忆，支持三种模式：

### 1. 纯语义搜索（traversal_depth=0）
关键词 + 向量语义匹配，返回最相关的短期记忆和知识节点。适合快速查找。

### 2. 语义 + 图谱遍历（traversal_depth>0，不指定 seeds）
先语义搜索获取种子节点，再沿关系遍历扩展。适合探索关联知识。

### 3. 纯图谱遍历（指定 seed_node_ids）
跳过语义搜索，直接从已知节点出发遍历。适合从确定的知识点探索关联。

### 遍历策略
- `breadth_first` — 广度优先，先看直接关联
- `depth_first` — 深度优先，深入某个分支
- `hybrid`（默认）— 混合策略，平衡广度与深度

## 记忆查询与维护

- `query_memory` — 按字段精确查询（agent_id、memory_type、tags）
- `update_memory` — 更新 ShortTerm / KnowledgeNode 内容
- `delete_memory` — 删除过时或错误的记忆（节点删除会级联删除关联关系）

## 最佳实践

1. **及时总结**：重要信息出现时立即用 `save_short_term_memory` 保存，不要依赖会后再回忆
2. **善用标签**：为记忆添加准确的 tags，提高后续检索效率
3. **定期沉淀**：工作多轮后主动调用 `settle_memory`，让短期记忆转化为长期知识
4. **先检索再创建**：创建新知识节点前先用 `search_memory` 检查是否已有相似知识，避免重复
5. **维护关系**：知识节点间的关系是图谱的核心，创建节点时尽量同时建立合理的关系
6. **清理过时**：发现错误或过时的记忆时及时 `update_memory` 或 `delete_memory`
