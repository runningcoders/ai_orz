# 工具基础

本指南帮助你理解平台的工具体系，掌握工具查询、调用、结果处理的完整流程。工具是你执行任务的核心能力延伸。

## 工具分类

平台工具按加载方式分为两类：

| 类型 | 加载方式 | 调用方式 | 特点 |
|------|---------|---------|------|
| **Auto 工具** | 自动注入模型上下文 | 模型直接 function calling | 无需手动请求，适合简单工具 |
| **Manual 工具** | 通过 Prompt 展示 | 手动调用 `request_tool_call` 或 `send_tool_call_message` | 需要明确请求，适合关键工具 |

工具按标签（tags）分组管理，常见工具包标签：
- `tool_management` — 工具管理类（查询、调用、绑定）
- `skill_management` — 技能管理类（搜索、安装、卸载）
- `messaging` — 消息类（发送、查询）
- `collaboration` — 协作类（Agent 间通信、查询）
- `project_management` — 项目管理类（项目、任务、产物）
- `file_management` — 文件管理类（附件上传下载）

## 工具查询与发现

遇到新任务时，先了解有哪些工具可用。

### `list_tools` — 列出所有工具
返回所有已注册的工具的完整列表，包含名称、描述、参数定义。适合初次了解工具全集。

### `query_tools` — 按条件查询工具
支持按 tags、名称、状态等条件过滤。适合按工具包标签查找特定类别的工具。

### `list_tool_tags` — 列出工具标签
返回所有已启用工具的标签聚合。用于发现可安装的工具包，了解工具分类全貌。

### `list_installed_tool_packs` — 查看已安装工具包
返回当前 Agent 已安装的工具包标签列表。用于确认自己当前可用的工具集。

## 工具调用模式

Manual 工具有两种调用模式，根据任务特征选择：

### 同步调用 — `request_tool_call`

**特点**：阻塞当前轮次，结果在当前回合返回。

**适用场景**：
- 需要立即获取结果继续推理
- 短时间运行的工具（查询类、计算类）
- 结果是后续决策的依赖项

**参数**：
- `tool_id` — 工具 ID
- `tool_name` — 工具名称
- `params` — 工具调用参数（JSON）
- `project_id` — 关联项目 ID（可选）

### 异步调用 — `send_tool_call_message`

**特点**：不阻塞当前轮次，结果在下一轮通过 ToolCallResult 返回。

**适用场景**：
- 长时间运行的工具（外部调用、文件处理）
- 不需要立即结果的任务
- 并行发起多个工具调用

**参数**：与 `request_tool_call` 相同。

## 结果处理

### ToolCallResult 结构

工具调用结果统一封装为 ToolCallResult，包含以下关键字段：
- **状态**：成功 / 失败 / 执行中
- **结果数据**：工具返回的具体内容
- **错误信息**：失败时的错误描述
- **`trace_ref`**：调用追踪引用（包含 `tool_id` 和 `call_id`），用于后续查询调用详情

### 结果追踪

用 `trace_ref` 中的 `call_id` 可以：
- 通过 `get_tool_call_entry` 查询单次调用的完整记录
- 通过 `query_tool_call_entries` 批量查询历史调用
- 在产物或消息中引用调用记录，便于溯源

### 失败处理

工具调用失败时：
1. 检查错误信息，判断是参数错误还是工具内部错误
2. 参数错误 → 修正参数后重试
3. 工具内部错误 → 记录问题，考虑换用替代工具或人工介入
4. 不要无脑重试相同参数，先分析失败原因

## 最佳实践

1. **先查后用**：不熟悉的工具先 `query_tools` 查看参数定义，避免盲目调用
2. **看场景选模式**：短任务同步，长任务异步
3. **追踪留痕**：重要调用记录 `trace_ref`，便于后续溯源
4. **善用标签**：通过 tags 发现同类工具，扩展能力认知
5. **失败分析**：失败时先分析原因再决定重试策略，避免无意义重复
